# Много проектов: реальные границы

Повторяемая регистрация не означает неограниченную ёмкость одной установки.
Проверить три вещи до массовой партии, не после ошибки на очередном проекте.

1. Реестр: текущий `modules/apps/server/index.mjs` допускает менее 100 уже
   существующих `local_apps` на владельца перед созданием следующего. В счёт
   входят отозванные записи. Обновление прежнего app ID не расходует новый слот.
   Для сотен/тысяч проектов нужен отдельный проверенный capacity release с
   настройкой лимита, пагинацией/интерфейсом списка и нагрузочным сценарием.
   Не обходить лимит подделкой ownership, чисткой истории или новым аккаунтом.
2. TLS: leaf on-demand не требует route на каждый проект, но требует новый
   сертификат. По [Let's Encrypt](https://letsencrypt.org/docs/rate-limits/),
   проверено 05.10.2026, обычный лимит — 50 новых сертификатов на registered
   domain за 7 дней. Он общий для всех аккаунтов CA. У другого issuer проверить
   его собственные условия. Не считать новый ACME account обходом этого лимита,
   не удалять certificate storage при выпуске.
3. Runtime: измерить доступные порты, память/CPU, число соединений и размер
   хранилищ на выбранном host. Общий коннектор переиспользуется только внутри
   той же доверенной границы; контейнеры, владельцы и storage права не смешивать.

Для большого потока новых имён нужен автоматический wildcard certificate
через DNS-01. Одна wildcard A-запись и wildcard сертификат — разные вещи.
Сначала определить issuer, установленный DNS provider module/ACME client,
проверенный DNS transport, отдельную минимальную credential и renewal.
DNS API доступ не выводить и не класть в skill/план. Если его нет, подготовить
точный ограниченный вариант и запросить только недостающий доступ; не менять
nameservers и не ослаблять HTTPS ради скорости.

Wildcard certificate покрывает один DNS label. Реестр и source/session checks
остаются обязательны, даже когда сертификат общий. Проверить unknown/nested
hosts и точные native hosts, renewal, TLS storage backup и откат. Не выдавать
список ранее скрытых приложений через публичный catalog ради certificate setup.

Для CA экспериментов использовать staging; production не служит тестовым
стендом на сотни случайных имён. Убедиться, что число проектов и скорость
создания входят в подтверждённый профиль, затем применять обычный короткий путь.
