# Обложки и аватары Сот

Результат — выбранная человеком картинка в настоящей соте, с рабочим названием и управлением поверх неё, сохранённая в правильной области доступа. Сначала выясни цель: обложка приложения, личный аватар или общий визуальный набор. Сохрани выбранную картинку, стиль и режим доступа; отсутствие картинки нормально и не мешает пользоваться приложением.

Найди рабочий checkout Сот и его инструкции. Текущие контракты и точные пути приведены в [references/integration.md](references/integration.md). При иной версии проверь исходники, а не угадывай API.

## Выбор пути

- **Готовый общий арт приложения.** Используй существующий `scripts/app-art/cli.mjs`: prepare → выбранный исходник → проверка реальной соты → import/bind → validate. Это операторский статический pipeline; принятые WebP публичны. Он не является пользовательским upload API.
- **Загрузить свою картинку.** Предпочитай существующее владельческое управление профилем либо зарегистрированный runtime cover API. Фото остаётся локальным до сохранения. Личный аватар сохраняется через signed `world.profile.avatar.set`, доступ читающего проверяет World. Для общего статического арта проверь поддержку `prepare --origin upload` и `import --public-approved`; если её нет, старый importer безусловно пишет generated provenance и не подходит для upload. Статическое размещение требует конкретного выбора публичной обложки, не выводится из загрузки личного фото.
- **Сгенерировать.** Для разовой работы Codex применяй доступный skill `imagegen` и встроенный `image_gen`. Сохраняй готовый результат в проекте. Встроенный инструмент Codex не означает, что production агент умеет вызывать генератор: runtime использует только действительно зарегистрированный provider/capability. Если такого подключения нет, подготовь brief и preview-путь и назови точный блокер; не показывай фиктивное «сгенерировано».
- **Ничего не выбирать.** Оставь устойчивые инициалы, цвет или существующий локальный значок. Не создавай генерацию по факту появления приложения.

## Композиция и предпросмотр

Для поля сохраняй квадратный мастер, а шестиугольник применяй настоящей UI-маской. Важная часть предмета должна помещаться в центральных 70% квадрата; нижнюю треть оставь спокойной для HTML-подписи. Не рисуй внутрь изображения кнопки, текст названия или статус.

Покажи текущую и предлагаемую версии в одной реальной маске: маленькая сота телефона, обычная сота, карточка при наличии, светлая и тёмная тема. При загруженном фото не заменяй смысл картинки стилизацией. Для аватара без исходной фотографии не выдумывай внешность настоящего человека: предложи абстрактный образ по его brief либо запрошенную фантазийную иллюстрацию.

Текущий профиль уже поддерживает путь «Фото → локальное центральное превью → Сохранить»; пользовательского focal point/масштаба и промежуточной кнопки «Готово» в нём пока нет. Используй фактические контролы, не ищи выдуманные. Операторский crop настраивается существующими focal point metadata без генерации.

Для нового runtime editor при его реализации: обрезку меняй через focal point/масштаб без повторной генерации; drag дополни клавиатурой и видимыми сбросом/масштабом. «Готово» выбирает draft, «Сохранить» принимает его в аккаунт. Отмена не меняет текущую версию. Нельзя считать размер/хеш художественной проверкой.

## Генерация без лишних вызовов

Формируй короткий brief из назначения и явно выбранного стиля, без закрытых экранов, документов и секретов. Для редактирования укажи точную цель и сохраняемые признаки, осмотри локальный исходник через `view_image` перед `image_gen`.

Перед реальным вызовом проверь доступность выбранного provider, действующий аккаунт/target scope, разрешённый для задачи ввод, policy и оставшийся лимит вызовов/расходов. Используй фактический статус интеграции; не выдумывай сведения об аккаунте или цене, которых инструмент не показывает. Выполняй уже разрешённую разовую генерацию без повторного запроса разрешения; новые расходы и отправку личного референса нельзя выводить из разрешения создать этот skill.

Один запрос пользователя на одну картинку означает одну задачу генерации. Укажи предполагаемое число вариантов; не запускай серию или периодическое обновление из общего пожелания об автоматизации. Не пересоздавай картинку из-за переименования, повторного открытия или изменения crop. Перед передачей личных медиа внешнему генератору должен быть конкретный выбор пользователя для этой задачи. Не переключайся на платный API/CLI без его выбора.

Для повторяемой генерации требуются сохранённые цель, частота, предел вызовов/расходов, срок действия и режим применения. По умолчанию режим ручной; новое изображение остаётся предложением до принятия, если человек явно не выбрал автоприменение. Пустые лимиты не означают бесконечный бюджет. Если расписания/бюджеты не поддерживаются установленным API, не создавай скрытый cron или внешнюю автоматизацию.

При неопределённом исходе provider-запроса сначала проверяй исходный job/receipt; новый платный запрос не является способом проверки. Остановка запрещает новые вызовы, но не обещает отмену уже принятого provider-вызова.

## Принятие и проверка

Обновлять может владелец текущего приложения/профиля. Проверяй актуальный аккаунт, target ID, revision и права при принятии результата; подготовленная картинка сама по себе прав не даёт. Agent/MCP использует ту же операцию и тот же draft/receipt, а не прямую запись в хранилище.

В runtime pipeline сохраняй новую неизменяемую версию, затем атомарно переключай указатель с CAS. Операторский pipeline уже использует собственный lock и version history. Не перезаписывай файлы прежней версии. Откат — новая явная смена указателя с текущей revision, без повторной генерации. После неизвестного сетевого результата проверь тот же request ID/receipt и подписанный readback. Нынешний legacy `avatar.set` не принимает request ID: при timeout сначала прочти актуальный аватар и revision, не придумывай ему receipt API и не повторяй запись вслепую.

Проверь права → реальную запись → чтение → reload. Личная картинка не должна оказываться в публичном static manifest, URL или логе; публичность профиля/приложения не меняется из-за оформления. Закрытие окна, смена аккаунта и более поздняя версия делают старый async результат недействующим.

В результате сообщи выбранный target, источник картинки (upload/generated), локальный файл/asset ID, версию, реально выполненные проверки и доступность отката. Отдельно укажи, если результат только подготовлен, локально принят или ещё не опубликован. Не объявляй runtime API, provider, периодичность или физический touch проверенными только на основании наличия skill.
