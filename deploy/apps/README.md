# Изолированные приложения

Рабочий host controller принимает `appOriginTemplate: "https://{appId}.soty.pochinit.online"`. У каждого приложения отдельный origin: ключи профиля и другие приложения ему недоступны. DNS для `*.soty.pochinit.online` должен вести на обслуживающий TLS edge.

`edge-config.mjs` только готовит проверенный Caddyfile и шифрованную копию прежней конфигурации. Он не меняет работающий файл и не перезагружает Caddy. Перед применением оператор сравнивает `beforeSha256`, проверяет отсутствие параллельного изменения файла, затем применяет только этот кандидат. Чужие блоки сохраняются побайтно. Приватный ключ резервирования хранится в Windows DPAPI, на сервере нужен только публичный.

Сертификат разрешается лишь для точного имени зарегистрированного и включённого приложения через `/api/apps/tls-allow`. Произвольные домены, незарегистрированные ID и отозванные приложения получают 403. Маршрут включается после выпуска сервера, когда отказ для неизвестного домена проверен. Сама сессия приложения дополнительно требует одноразовый ticket и действующие права; TLS не даёт доступ к данным.

Первая установка сертификата может занять несколько секунд. Для массового размещения следует перейти на wildcard-сертификат с DNS challenge и распределённое хранилище; текущая схема не заявляет неограниченную скорость выпуска сертификатов или готовность одного сервера к миллиардам пользователей.

Основание: [Caddy Automatic HTTPS](https://caddyserver.com/docs/automatic-https), [TLS directive](https://caddyserver.com/docs/caddyfile/directives/tls), [permission endpoint](https://caddyserver.com/docs/caddyfile/options#on-demand-tls).
