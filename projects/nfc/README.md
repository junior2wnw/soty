# Метки · NFC

Отдельное приложение Сот: https://nfc.соты.online. Источник работает на SSH dev, локальный порт 5318; наружу приложение открывает коннектор и Soty gateway.

Версия 1.1. Подготовка ссылки, текста, vCard-контакта, Wi-Fi WSC, телефона, письма, SMS, координат, JSON, MIME/HEX, Android AAR, Smart Poster и внешнего типа NDEF. До 16 записей и 16 КиБ NDEF на метку; реальная метка может вмещать существенно меньше. Файлы до 16 000 байт импортируются локально через «Свои данные». Координаты новых геометок записываются обычной HTTPS-ссылкой на карту; ранее прочитанные `geo:` сохраняются при копировании. Локальные шаблоны, импорт/экспорт JSON, передача подготовленного содержимого по QR-фрагменту. Сервер не получает содержимое меток.

На вкладке «Считать» доступны однократное и непрерывное чтение, NDEF-диагностика, скачивание данных каждой записи и копирование содержимого в черновик. Непрерывное чтение останавливается кнопкой, сворачиванием приложения или через пять минут; ближайшие повторные события подавляются. Последние десять чтений остаются только в памяти вкладки. MIME-данные, внешние записи с двоичными данными и вложенные записи читаются раздельно: вызов `toRecords()` не используется для обычного MIME и не должен мешать чтению байтов внешней записи.

«Записать несколько меток» фиксирует подготовленное содержимое для ручной серии. Каждая метка требует отдельного нажатия и проверяется обратным чтением. Пустые метки защищают прежние данные по умолчанию; замена требует подтверждения. Отдельно считаются проверенные различные номера, повторы, записи без проверки и без доступного номера. Номер из Web NFC не гарантирует уникальную физическую идентичность метки. Максимум — 1000 завершённых записей в серии; итоговый файл содержит только счётчики.

Диагностика показывает фактический тип Web NFC, выводимый из него TNF, размеры данных API и оценку размера NDEF. Модель чипа, технологию, полную ёмкость и аппаратную защиту Web NFC не раскрывает: эти поля остаются неизвестными. Байты из API — данные записи после обработки браузером, а не дамп памяти или полный NDEF-пакет. Чтение ограничено 128 верхними / 256 суммарными записями, восемью уровнями вложенности и 64 КиБ данных.

Проверка iPhone относится к формату первой верхней URI-записи. Обычный HTTPS URL подходит для фонового открытия; текст со ссылкой, `absolute-url`, вложенная ссылка Smart Poster и `geo:` могут быть подготовлены как отдельная HTTPS-запись через подтверждённую замену черновика. Формат ссылки не доказывает совместимость самого чипа. На iPhone сайт не получает Web NFC. Основания: [Web NFC](https://w3c-cg.github.io/web-nfc/), [фоновые метки Apple](https://developer.apple.com/documentation/corenfc/adding-support-for-background-tag-reading).

Отчёт `soty.nfc-report.v1` экспортируется локально: по умолчанию без содержимого, номера метки и ID всех записей, включая вложенные. Их можно включить отдельными флажками. Импорт принимает файлы до 400 КБ, проверяет лимиты, соответствие текста байтам и представление `web-nfc-decoded-record-data`; аппаратные заявления отбрасываются. Экран «Отчёт из файла» отличает такой результат от нового чтения телефоном. Отчёт без содержимого нельзя использовать для записи.

Неполный черновик сохраняется без требования заполнить все поля. Открытие приложения не перезаписывает хранилище. Перед изменением повреждённые исходные данные сохраняются локально; в меню появляется их скачивание. Если резервную копию создать нельзя, оригинал остаётся на месте и приложение сообщает о несохранённом черновике. Лимит — 40 шаблонов: новый сверх лимита можно скачать, старые не вытесняются. Список перечитывается перед сохранением и удалением, чтобы сохранить изменения другой вкладки.

Чтение и запись используют настоящий Web NFC в Chrome на Android. На iPhone и компьютере доступна подготовка. Нужны HTTPS, верхнее окно, включённый NFC и разблокированный экран. «Записать» защищает прежнее содержимое; видимая кнопка «Перезаписать метку» предлагает новые данные и предупреждает об их замене. Только нажатие «Заменить и записать» передаёт `overwrite: true` непосредственно из пользовательского действия, только для этой операции. Запись проверяется повторным чтением; непроверенная запись получает отдельный результат. Закрытие записи навсегда требует ввода подтверждения и зависит от поддержки телефона и метки. Сырое чтение памяти чипа, пароли секторов, эмуляция карт и запись платёжных карт не поддерживаются.

Web NFC возвращает `NotAllowedError` и при отказе в доступе, и когда `overwrite: false` встречает занятую метку ([алгоритм Web NFC](https://w3c-cg.github.io/web-nfc/)). Поэтому интерфейс учитывает текущее состояние разрешения: занятая метка с уже разрешённым NFC предлагает подтверждённую перезапись; запрещённый доступ предлагает исправить разрешение. Если Permissions API недоступен, причина остаётся явно неопределённой. Повторная запись не запускается автоматически; отказ после подтверждённой перезаписи не предлагает бесконечно менять тот же флаг.

Локальная разработка: npm ci, npm test, npm run dev. Сборка: npm run build; npm start обслуживает dist на 127.0.0.1:5318. Dockerfile собирает и тестирует приложение на закреплённом Node 24. Контейнер публикует порт только на loopback хоста.

Инструкции общей публикации: [поддомены приложений](../../docs/deployment/app-subdomains.md). Физический NFC нужно проверять на настоящем Android с метками; программные проверки жизненного цикла этого не заменяют.

Главный сценарий: выбрать тип → заполнить → записать. Для занятой метки — «Перезаписать метку» → «Заменить и записать». «Считать» и «Мои» в нижней навигации. Меню «…» содержит сохранение, перенос на телефон, дополнительные записи, оценку памяти, диагностику, отчёты и серию меток. При отсутствии Web NFC главное действие предлагает QR-перенос на Android; внутри iframe — отдельное окно. Запись доступна только по явному нажатию владельца телефона.

Внутри Сот вход начинается с одной кнопки «Открыть NFC». Выбор типа и ввод происходят уже в отдельном приложении: черновик не приходится переносить между встроенной страницей и новым окном. Прежние данные встроенной страницы не удаляются; корректный черновик можно выгрузить через её меню. Защита sandbox сохраняется, отдельное окно открывает сама оболочка Сот после проверенного действия пользователя.

Приложение имеет свой PWA-манифест. NFC не требует отправки содержимого на сервер: уже открытый интерфейс может работать без сети. Для нового открытия нужна сеть. Шлюз Сот сейчас запрещает service workers у приложений; отдельный офлайн-кеш потребует собственного проверенного профиля размещения.

Для агентов доступен `/agent.json` с типами и форматом обмена. Агент создаёт JSON-файл со schema `soty.nfc-template.v1`, name и records; все значения полей — строки. Пользователь открывает файл через меню и подтверждает замену черновика. Пример:

```json
{"schema":"soty.nfc-template.v1","name":"Соты","records":[{"kind":"url","values":{"url":"https://соты.online"}}]}
```

Операции с физической меткой выполняет телефон с разрешением Web NFC. Удалённого API записи чипов нет. Не помещайте настоящие пароли и личные данные в публичные примеры или QR-ссылки.
