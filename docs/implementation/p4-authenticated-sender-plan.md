# P4-D2-R1c — authenticated sender library plan

01.10.2026. **PLAN ONLY / NOT IMPLEMENTED / NOT RUN.** Изменён только этот документ; код R0/R1a/R1b, runtime, архивы, ключи, SSH и модели не затронуты. Реализация после отдельного review/GO и принятия R1b.
Основание: [принятый extractor plan §2–3/6–7](p4-restore-extractor-plan.md), [Docker stream preflight](p4-docker-stream-preflight.md); прочитаны `backup-format.mjs:401–470`, `restore-backup.mjs`, `backup.mjs`, `docker-api.mjs`.
Конкретный разрыв: нынешний `readEncryptedBackup` сам открывает/закрывает файл; два его вызова не обеспечивают same-FD. Его plaintext buffers стираются сразу после awaited parser feed — передача требует дождаться потребления этих bytes до wipe.
Минимальные будущие файлы: `deploy/connect/backup-format.mjs` — выделить один внутренний проход по owned handle; `restore-backup.mjs` — фиксированный sender port/lifecycle; NEW `restore-sender.test.mjs` и `p4-authenticated-sender-receipt.md`. Никакого второго crypto/tar parser, ledger, generic callback API или изменений producer/sink.
R0 API/CLI/receipt/failure и dry R1a/receiver R1b signatures не меняются; прежние tests остаются. Общий core использует прежние envelope/RSA/AES/metadata/tar/SQLite/RestoreInventory primitives; внутренние новые digests не добавляются в legacy receipt.

1. Private API: `sendAuthenticatedBackup({file,privateKeyPem,expectedSha256,expectedManifestSha256,sourceWitness,output,limits,signal?})`; все поля захватываются внутри нормализующей границы до I/O, только закрытая форма, без plaintext result/callback/path output.
2. Success ровно `{authenticated:true,archiveSha256,plaintextSha256,manifestSha256,plaintextBytes}`; это private control receipt отправителя, не `extracted`, `restored` или принятие target. Public projection не содержит plaintext/manifest/per-file hashes, paths или key identity.
3. Archive/manifest pins берутся из protected approved backup-stage evidence, `sourceWitness={generationId,checkpointSha256,inventorySha256}` — из независимого cold inventory. GCM не доказывает origin без trusted archive pin; ни metadata, ни R0 receipt не заменяют witness.
4. `file` — bounded absolute path≤4096 UTF-8 bytes, PEM≤64KiB; digests64lowerhex и generation32lowerhex. `limits` — ровно нынешние12 sender/dry keys: archiveBytes, plaintextBytes, fileBytes, extractedBytes, entries, headers, pathBytes, pathDepth, externalFiles, externalBytes, wallMs, idleMs; positive safe integers, без defaults/авторасширения. Format caps прежние.
5. `output` — exclusively owned свежий binary Node Writable: objectMode=false, HWM1..65536, empty/uncorked, без pending writes/finish/destroy/error; effective emitClose=true и autoDestroy=true проверяются по pinned Node24.21 native state, без изменения флагов. Конкретный transport wrapper обязан поддерживать этот profile; arbitrary Duplex не принимается как доказательство закрытого канала.
6. После полной validation sender принимает ownership output и ставит bounded lifecycle listeners; первая фаза не вызывает write/end. Invalid options/output остаются caller-owned. Ошибка после adoption разрушает owned output даже при0bytes; stdout/console/общий multiplexed writer не являются допустимым каналом.

7. Обязательная предпосылка caller: новая transaction-owned ciphertext copy, созданная эксклюзивно в private namespace, bounded copy+fsync, creation writer закрыт, ожидаемый archive pin сохранён, другие writers отсутствуют. Входной download/original архив нельзя расшифровывать inplace; plaintext temp file не создаётся.
8. Windows operator до создания copy задаёт и проверяет owner SID и protected DACL private directory/file с allow ACE только для operator SID, без broad/inherited доступа; исключает reparse/alternate-stream paths. `mode0600`, ReadOnly attribute и ACL родителя сами по себе не доказывают private file ACL.
9. Для Windows handoff operator удерживает read-only `FileStream(FileMode.Open,FileAccess.Read,FileShare.Read)` этой copy до actual sender child completion: не разрешены write/delete sharing, несовместимый прежний writer означает refusal. Guard handle не заменяет Node read FD и не передаёт ключ; actual совместимость/ACL проверяется отдельным synthetic operator gate до SSH.
10. Библиотека сама не доказывает Windows DACL/отсутствие mapping/writers; это явная trusted setup обязанность существующего controller. Linux caller обеспечивает аналогичный private sole-writer namespace. Один FD/stat/inode не означает immutable storage; hostile privileged host/owner вне этой гарантии.

11. Sender открывает copy один раз read-only и сохраняет FileHandle до конца двух проходов; только regular/nlink1, bounded size. Для sender проверяются отсутствие final symlink, captured identity/size, stat после проходов и EOF за ожидаемым концом; всё чтение positional, pathname не переоткрывается.
12. Один private `readEncryptedPass(handle,...)` содержит существующий decrypt+strict parser loop. R0 вызывает его один раз под прежним open/close wrapper; sender дважды создаёт состояние того же parser/cipher. Передача bytes доступна лишь внутреннему фиксированному sender mode, не R0/dry options.
13. Первый проход полностью проверяет actual GCM final, parser.finish, exact logical inventory/config hashes, manifest pin, independent witness и whole archive SHA. Считает plaintext SHA/count, закрывает только состояние прохода; любой отказ даёт0output bytes и0end. FD остаётся тем же.
14. Второй проход повторно читает header/tag/ciphertext, выполняет тот же strict parser, повторный GCM final и SHA ciphertext/plaintext/count. Все pins и результаты должны совпасть с первым проходом; данные framing `uint32BE metadataLength + metadata + tar` передаются без перекодирования.
15. Source mutation/append/truncation, иная valid-GCM generation или поздний bad tag запрещают success/end. Ранее отправленные bytes невозможно отозвать: downstream остаётся quarantine, принимать target по EOF или одному receiver receipt нельзя.
16. Кусок≤64KiB: decrypt→await parser.feed→write с заранее установленными lifecycle/drain наблюдениями→await callback и нужный drain→wipe; одновременно только один outstanding chunk. Node24.21 может испустить drain ДО callback: запрещено await callback→once('drain'), уже наблюдённый drain учитывается. Буфер не стирается до callback; нет массива chunks/unbounded queue/второго полного plaintext buffer.
17. Нормальный конец: второй GCM/digest/parser/EOF checks→await owned file close→final abort/deadline check→output.end→actual finish И close→final check→receipt. End callback, write return true или finish без close не дают success.
18. До вызова end любой error/abort/timeout означает0end. После проверенного второго прохода и уже вызванного output.end ошибку _final/close или late abort нельзя превратить в «EOF не отправлен»: no success, destroy без raw error/reason и actual cleanup. Unconditional awaited file/output cleanup не проходит через deadline guard; failed/unconfirmed close не даёт успех, target/copy автоматически не удаляются.
19. Один monotonic wall deadline на оба прохода и output; idle считает реальный read/write progress. Один re-armed timer с delay clamp2147483647, safe-point checks до/после await; удержанный write/final инициирует refusal/destroy. Timer не доказывает отмену syscall или custom _destroy; hard kill/cleanup deadline принадлежит будущему parent watchdog.
20. Fixed message/code/stack без cause/raw errors: restore_archive_invalid, restore_incomplete, restore_authentication_failed, restore_limit_exceeded, restore_timeout, restore_io_failed, restore_cleanup_pending. AbortSignal проверяется native getter без reason; thrown options/stream/crypto errors нормализуются, неизвестное→io_failed.
21. RSA/AES/PEM только в операторском процессе; transient buffers wipe best-effort после потребления. JS strings/KeyObject memory не получают обещания secure erase. Открытие канала, логирование и пользовательская копия receipt не раскрывают metadata/payload/ключи.

22. Это library slice. Нынешний DockerApi буферизует JSON/ответы и не реализует upgrade/stdin; его request/helperOutput нельзя использовать как готовый бинарный handoff. Synthetic code-archive PUT для R1b также не является транспортом encrypted recovery data.
23. Следующий отдельный root slice соединяет sender-owned Writable с authenticated pinned-host binary SSH/no-PTY каналом и exact owned Linux receiver, используя прежний journal и согласованный Docker streaming lifecycle. Передача RSA/AES remote, PowerShell text pipeline и новый deploy orchestrator исключены.
24. Private key из existing DPAPI CurrentUser передаётся Node через bounded private stdin, не argv/env/disk/log; payload идёт отдельным binary channel. Этот план не реализует key loader, ACL guard, SSH/Docker adapter или producer completeness.
25. Controller принимает результат только по sender+receiver receipts с одинаковыми plaintext/manifest hashes и byte counts, trusted archive pin/target identity и actual process completion; lost receipt/разрыв оставляет unresolved quarantine, без blind retry в тот же target и без скрытого START.

26. Local causal fixtures: настоящий encryptBackup + independently produced tar/metadata framing; exact plaintext equality проверяется boolean/hash без raw diff. Bounded memory Writable здесь fixture, не production transport; RSA/данные только synthetic.
27. First-pass negatives: bad key/tag/truncation, wrong archive/manifest pin/witness и omission дают0write/0end; valid control использует те же достаточные limits. Общие прежние R0/R1a/R1b causal assertions не ослабляются.
28. Обёртки реального FileHandle.read отслеживают один handle/оба прохода/actual fd=-1 после close. Изменение source pathname не переключает второй проход на иной FD; same-length ciphertext/header/tag mutation и append/truncation между проходами либо во втором дают no success/end.
29. Поздний auth oracle меняет фактический второй-pass tag через controlled real file read boundary: первый проход проходит, output уже имеет bytes, затем GCM final отказывает. Не подменять parser/cipher и не заявлять0bytes при позднем отказе.
30. Actual Writable с HWM1 и удержанным _write callback: нет следующего чтения/переиспользования buffer до release; штатный false→drain→callback завершается без зависания. _final и _destroy удерживаются отдельно: receipt pending до completion. Pre-end отказ проверяет0end; post-end _final/close error/late abort —1end, no success и actual destroy/close. Premature close и emitClose:false/autoDestroy:false дают fixed refusal.
31. Finite bounds+1, virtual monotonic wall/idle и real-I/O wrappers, abort до/во время двух проходов/held write; каждый observed FD/owned output действительно закрыт либо честный cleanup_pending. Все mocks serial и восстановлены; никаких production clock/IO hooks.
32. Canary в input getters, source paths, stream errors и signal.reason не выходит в code/message/stack/cause/stdout; listeners/таймеры сняты после terminal close. Отдельный будущий Windows gate доказывает DACL/read-sharing refusal/actual guard lifetime, а не только успешный synthetic Node read.
33. Порядок после GO: shared-pass refactor с unchanged parity → sender lifecycle/local causal gate → source freeze/independent audit → отдельный operator/transport gate. Root единственный исполнитель tests/runtime; библиотечный PASS не закрывает R1c handoff, Linux restore, full-image или production release.
