# Linux bridge: отдельный reviewable synthetic packet

База Source3 `0cecf09` и narrow cancel fix `607d6a8` сохраняются. Новая delta добавляет только фиксированный synthetic engine/enforcer, one-use packet builder и приватный `beforeStart`/SQL-monitor. Ни модели, ни пользовательские материалы, ни публикация/расходы не включены. Windows START остаётся not-ready.

## Контроль и данные

`createSyntheticLinuxFeedbackProcessor` — LAB-only constructor. Единственный разрешённый host directory `/home/ai2/codex-soty-universal-20261007-9f8dcd71/source-feedback-jobs`, UID1000/mode700/no-symlink; Docker binary `/usr/bin/docker`, image `sha256:c03a61d12e03870747e9013860fc36e23e53920da9b07ea1e795b3fef9628ae6`. `prepare` сверяет установленный image ID. Это не публичный API или произвольный command/path/URL.

Native grant binds exact engine ref. Engine digest включает image, фиксированные worker bytes, purpose OCR, synthetic scenario и закрытый максимум бюджета. Scenario задаёт trusted constructor для лаборатории, не тело Native job. Все результаты явно synthetic, без модели/качества OCR. Source передаёт в packet только точные сохранённые body/media, inputDigest, purpose, budget и engine pin. Source secrets, Root context/proof, issuer/sub, cookie, keys и Docker socket в processor отсутствуют.

Host supervisor владеет Docker CLI. Он создаёт конкретный container ID, читает только выбранные безопасные inspect fields и до START сверяет image/spec/entrypoint/argv/mount. Processor получает read-only packet и три bounded tmpfs, включая `/data` вместо image VOLUME. `--network none`, UID1000, read-only, cap-drop ALL, no-new-privileges, memory/swap128MiB, pids32. Node worker не имеет subprocess permission. RLIMIT_CPU применяется prlimit к одному фиксированному Node processor; CPU должен быть целыми 1–10s, дробные/<1s бюджеты not-ready. NanoCpus ограничивает только скорость.

Wall guard — отдельный OS `/usr/bin/timeout` + kill-after cleanup, а не таймер Source JS. Поэтому блокировка Source event loop не превращает wall в неограниченное выполнение. Abort отдельно SIGTERM→SIGKILL останавливает ровно собственный container ID. Все stdout/response bytes ограничены; scratch соответствует допущенному бюджету. Parent должен перед RUN проверить наличие `/usr/bin/timeout` и `/usr/bin/prlimit`; никакие apt/pip/model downloads не выполняются.

Source после async Docker подготовки вызывает private `beforeStart`: заново actual Root/channel/RP current proof, then Native current/final SQL check exact grant/job/claim/resources/consent/session/key/deadlines. Network вне SQL, START следует после этой проверки. Distributed мгновенную атомарность после передачи START этот port не обещает; непроверенный результат остаётся unknown.

Native SQL monitor опрашивает текущие authority rows с target interval250ms. Он ловит revoke из другого OS процесса и посылает Abort текущему executor. Это интервал в исправной среде, не гарантированная мгновенная отмена при DB/host outage. Финальный SQL fence и readonly receipt остаются обязательными. Begun/unknown не захватывается и не перезапускается автоматически.

## Как проверяет Parent

`node scripts/prepare-linux-feedback-jobs.mjs` создаёт immutable fresh-nonce public packet: `fixture.mjs`, manifest с SHA файла/source inputs и четырьмя exact image imports. Последние — `/app/server/http-app.js`, `/app/modules/connect/browser/client.mjs`, `/app/modules/apps/server/schema.mjs` и maintained `/app/node_modules/openid-client/build/index.js`. Root/runtime код из локального worktree не подменяется: используются bytes того image, который Parent повторно inspected. Установленный connector — `/app/dist/agent/soty-connector.mjs`, не старый локальный сгенерированный binary.

Guarded запуск требует **trusted fixture supervisor** с доступом к Docker daemon для fixed child create/inspect/kill/rm. Это сильное host полномочие; его нельзя отдавать обычному publisher/Source UI. Parent может исполнять Node24 на owned host либо отдельный approved supervisor container. Если используется container, socket+CLI есть только у доверенного supervisor, never processor. Public packet и host lab directory должны монтироваться по тому же абсолютному host path, чтобы фиксированный child bind не указывал на другой каталог. Supervisor использует mode700/UID1000 owned lab, bounded `/tmp`, реальные Source SQL только временные; удаляются только созданные exact child IDs/packet dirs. Ни production socket consumers, ни сервера не переключать.

Контейнер processor создаётся с фиксированными аргументами, фактические spec проверяются до START. Source fixture использует настоящий signed Connect/Apps/Human, private installed connector HTTP/WS/MAC, maintained Source OIDC/currentuserinfo и существующий Native-owner dual proof. JSON/Root owner label не является Native owner. Шесть case: success/CPU/wall/cancel/scratch/output. Success должен дать encrypted Source receipt, restart/readback ровно один результат; остальные — unknown/zero result/no rerun и фактический stopped child. UI ticket остаётся received. Cancel начинается только после наблюдаемого running child, а не во время подготовки.

До Parent RUN это подготовленный пакет, не PASS. Standalone предыдущий probe8/8 не объявляется job-ready. Joint Linux результат должен отдельно подтвердить exact image/profile2/installed connector совместимость и фактический Source job→processor→receipt путь. Reader3/compatible cold image gate остаётся отдельным; общий Standard finite long-session consumer и явный new-empty user re-login после Basic300 ещё не реализованы. Прежние Standard1/2 pins не меняются; Basic не возрождается автоматически и Root metadata не создаёт права к существующему Native owner/tenant.
