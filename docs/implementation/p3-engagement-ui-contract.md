# P3D3 — экран приложения, сохранённые и обсуждение

Статус: локальная приёмка кода D3 описана в [интеграционной квитанции](p3-engagement-integration.md). D2 завершён коммитом `4ff4359`; D4 и production не приняты этим контрактом.

## Пользовательский результат

Приложение открывается один раз. Человек сохраняет именно выбранный адрес, открывает обсуждение рядом, возвращается из архива и продолжает работу в той же мини-апке. На узком экране разговор занимает область приложения, но не уничтожает его. Сохранённые доступны отдельной линзой на главной. Локальное закрепление остаётся отдельным действием «Закрепить здесь».

## Порядок и границы работ

1. Root: минимальная подтверждённая точка входа, запуск, маршруты и жизненный цикл экрана.
2. Publishing architecture: отдельные состояния сохранённых, черновиков, подтверждений и ограниченного окна истории; свои тесты.
3. Agent ecosystem: компоненты сохранения, библиотеки и обсуждения, включая клавиатуру, фокус и состояния ошибок; без второй реализации хранения.
4. Whole product critic: независимые HTTP, гонки состояний и компонентный стенд; production-код не изменяет.
5. Root: интеграция, последовательные проверки, реальный браузер, разбор независимого аудита. После исправлений — отдельная квитанция, коммит и push.

Одновременно работают три субагента. Код сервера D2 заморожен, кроме добавочного `apps.entry.get` и безопасного `entry` в ответе `apps.launch`.

## Инварианты

- `apps.launch` возвращает `{appId, domainId, origin, path}` из того же решения о допуске, что и билет. Успешный ответ без этих данных отклоняется. Поздний отдельный запрос не должен подменить уже открытый путь новым значением по умолчанию.
- Только отказ первого запуска может вызвать `apps.entry.get`. Этот запрос проверяет точный вход без билета, профиля и обсуждения; допускает выключенный источник, но не закрытый адрес или потерянный доступ.
- Первое разрешение входа сериализуется. Одновременное открытие отдельной вкладки получает собственный билет к той же точке. Последующие запуски сохраняют точные адрес и путь, включая Unicode, query и SPA fragment.
- Адрес панели, выбранный архив и браузерный Back меняют представление, а не экземпляр iframe. Другая мини-апка, другой явный путь или аккаунт создают новый экран. Поколение аккаунта защищает также A→B→A.
- `panel=discussion`, `conversation=conv_…`, `admin=1` — строго проверенные параметры оболочки. Они не попадают в путь мини-апки и не выдают доступ. Административное чтение передаёт `entry:null`, не запускает приложение и не разрешает отправку.
- «Сохранено» выводится из актуального `current.entry`, а не исторической квитанции. Замена сохранённого входа требует явного действия. Доступность потерянного адреса не заменяется доступностью другого адреса того же приложения.
- Черновик привязан к аккаунту, приложению, аудитории и точному входу. При смене аудитории старый текст не переносится в новый разговор. Позднее подтверждение очищает только свою редакцию.
- Один ограниченный локальный реестр на аккаунт: не более 32 слотов и 1 MiB UTF-8. Непустые черновики и неподтверждённые сообщения не вытесняются. Ошибка хранения оставляет редактируемый текст в памяти и предупреждение перед уходом; новый неподтверждённый запрос не отправляется.
- Старый локальный черновик можно найти по app/domain/path после потери доступа. Это чтение собственного локального текста, а не разрешение на историю, отправку или запуск. Исходный origin остаётся частью сохранённого контекста.
- Сетевая история ограничена 500 сообщениями/2 MiB. Более старая история доступна перемещением окна и возвратом «К последним». Перезапуск сервера сбрасывает сетевые курсоры, но не собственные черновики.
- Закрытая панель не опрашивает историю. Смена аккаунта очищает все проекции и запрещает поздним ответам восстановить старый экран.

## Визуальная и доступная оболочка

Нейтральные существующие theme tokens; единая геометрия, без импорта classic UI. Основные действия: назад, сохранить, обсуждение, дополнительные действия. Вторичные команды раскрываются одной кнопкой; цели не меньше 44 px. На телефоне заголовок сокращается, но действие остаётся доступно по понятному имени. Начальная история не озвучивается как новые сообщения; новые события используют отдельный ограниченный live region. Меняющийся статус не перехватывает фокус.

Исследовательские основания: [Web Locks Editor’s Draft](https://w3c.github.io/web-locks/) применён для коротких операций одного origin, без ожидания сети и без обещания синхронизации устройств; [WAI-ARIA Button Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/) — для постоянного имени переключателя; [WCAG ARIA23](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA23) — для последовательных обновлений разговора.

## Приёмка

Проверяются: два окна; потерянное подтверждение; позднее подтверждение после нового текста; изменение аудитории; недоступный источник; закрытый alias; потеря доступа; точные Unicode/query/fragment; смена аккаунта A→B→A; отсутствие догадок по устаревшим метаданным; отсутствие лишнего запуска при панели/архиве/Back; клавиатура, 320 px, 667×375, desktop. Модельные, HTTP и компонентные тесты не заменяют реальную проверку iframe и браузера. Полные тяжёлые наборы запускаются последовательно с ограниченной конкуренцией после ранее наблюдавшегося исчерпания Windows commit memory.
