# R1d: зависимости backup — независимый preflight

**SOURCE-ONLY / NOT SERVER INVENTORY / NOT RUN.** Подготовка R1d по исходникам; не выполненная проверка completeness, restore или production readiness. Реальные config/env, ключи и история не читались; тесты, hosts, CLI и SSH не запускались.

Минимальная граница — весь фактически используемый `/data` плюс настроенные внешние durable зависимости и provenance. Запись ниже означает возможность в коде, а не наличие файла или настройки на сервере. Фактическое отсутствие устанавливается отдельным fresh inventory; выключенный сервис сам по себе не разрешает исключить существующий ключ или данные из канонической generation B.

- `container-config`: существующий backup шифрует полный `original` Docker inspect, поэтому inline `Config.Env` уже может присутствовать в metadata; содержимое произвольных внешних файлов и независимую полноту это не доказывает. Pointer: `deploy/connect/backup.mjs:71`.
- `application-token-file`: отдельно копируется только RO bind с точным destination `/run/secrets/soty-application-tokens.json`; приложение допускает иной `SOTY_GONKA_APPLICATION_TOKENS_FILE`, который этим special case не покрыт. Pointers: `deploy/connect/backup.mjs:57`, `server/gonka-proxy.js:139`.
- `oauth-key-bundle`: внешний `SOTY_OAUTH_KEYS_FILE` содержит JWKS, cookie keys, artifact key и key ID; текущий producer не перечисляет его содержимое отдельно. Artifact key и его identity необходимы для расшифровки сохранённых AS artifacts. Pointers: `server/capabilities-configuration.js:16`, `modules/capabilities/server/oauth-crypto.mjs:22`, `modules/capabilities/server/oauth-crypto.mjs:38`.
- **AS-off всё ещё читает непустой keys-file:** `enabled:false` не отменяет `secretFile(filename)`. В approved isolated keyless profile требуется явно отсутствующая файловая зависимость, а не оставленный путь к отсутствующему файлу; это не разрешение удалить существующие ключи из B. Pointer: `server/capabilities-configuration.js:61`.
- `authority-profile`: сохраняются issuer/resource/audience, static client profiles, Connect origins и trusted-proxy provenance. AS-off keyless bearer использует durable digest/link и текущую authority без расшифровки artifacts; выключенный AS не означает потерю уже выданного доступа или owner history. Pointers: `server/capabilities-oauth-profile.js:61`, `server/connect-module.js:23`, `server/http-app.js:37`, `modules/capabilities/server/oauth-connections.mjs:354`.
- `model-provider-profile`: primary/fallback credentials и routing нужны для восстановления model service, но не для открытия исторических данных. AS/native flags их отдельно не отключают; допустимый no-egress recovery profile задаётся явно. Pointer: `server/gonka-proxy.js:14`.
- `identity-trust-profile`: публичные issuer registries условны по собственным флагам identity adapters, не по AS/native flags. При отключённых adapters их runtime config может отсутствовать; существующее durable состояние остаётся в `/data`. Pointers: `server/identity-wire-v1.js:137`, `server/soty-identity-adapter.js:71`, `server/identity-wire-v1-api.js:25`, `server/soty-identity-adapter-api.js:26`.
- `release-source` / `traffic-exit-pool`: настроенные внешние пути требуют inventory; стандартные dataDir paths покрывает полный data archive. Traffic имеет собственное включение и не отключается AS/native flags. Pointers: `server/http-app.js:85`, `server/traffic-control.js:15`, `server/traffic-control.js:22`.
- `image-config-control-provenance`: entrypoint допускает DATA_DIR/dist override; source/image/release/trust pins, host/module journals и выбранный controller/timer config нужны по D2. Архивируется согласованный checkpoint до backup, без автоматического исполнения старого journal при restore. Pointers: `server/index.js:14`, `docs/implementation/p4-release-recovery-plan.md:94`, `docs/implementation/p4-release-recovery-plan.md:96`.

Обязательная сохранность и границы готовности:

- `committed-generation`: Notes и immutable create proofs, Caps intents/receipts/budgets/original credentials, Connect authority и остальные durable stores сохраняются одной холодной generation, даже при AS/native-off. Native reconcile читает положительный proof до последующих решений об авторизации/отмене. Pointers: `server/http-app.js:97`, `server/connect-module.js:9`, `modules/capabilities/server/native-notes.mjs:238`, `docs/implementation/p4-release-recovery-plan.md:92`.
- Model/service readiness отдельно от data/open recovery: `/ready` дополнительно требует готовности обоих model proxies; его отказ без provider credentials не доказывает повреждение восстановленных stores. Pointer: `server/http-app.js:194`.
- Личные operator/device signing keys исключены из серверного backup: Connect хранит/проверяет публичную authority и запрещает private-key поля. Pointers: `modules/connect/server/index.mjs:119`, `docs/implementation/p4-release-recovery-plan.md:94`.

Известные blind spots quiescence:

- Два `assertNoWriters` проверяют только running Docker containers с совпадающим именем одного `/data` volume; host processes, aliases/bind mounts к тем же данным и writers, появившиеся и исчезнувшие между проверками, этим не исключены. Pointer: `deploy/connect/backup.mjs:51`.
- AS/native-off не равно read-only: startup запускает native reconciliation при подходящих formats и OAuth cleanup при configured profile; другие routes/stores также могут писать. Pointer: `server/http-app.js:168`.
- STOP одного container и два snapshots не дают общей границы для всех DB и внешних файлов. R1d требует all-writer quiescence, независимый source witness и связанный manifest; unknown extra RW dependency или missing required file должны отказать полноте. Pointers: `docs/implementation/p4-release-recovery-plan.md:90`, `docs/implementation/p4-release-recovery-plan.md:94`, `docs/implementation/p4-release-recovery-plan.md:96`.

Этот preflight не добавляет новый registry, journal или key store и не заменяет будущие producer/restore/runtime gates.
