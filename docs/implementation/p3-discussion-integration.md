# P3-D2 — локальная приёмка обсуждений приложений

Дата: 30 сентября 2026. Основание: [контракт D2](p3-discussion-contract.md), предыдущий D1 `3794f01`. Серверный этап локально принят. Интерфейс D3, пользовательский цикл D4 и production остаются отдельными задачами.

## Результат

Обсуждение принадлежит приложению, работает при выключенном источнике и не копирует чат сообщества. У приложения одно текущее обсуждение; доступные прежние разговоры открываются только для чтения. Публикация приложения не раскрывает прежнюю закрытую переписку. Смена аудитории происходит в той же Apps transaction, что изменение прав. Пустые поколения не создают строки архива.

Точный повтор отправки возвращает прежнюю квитанцию. Он не создаёт дубль, не переносит сообщение к другой аудитории и не восстанавливает удалённый текст. Изменения включают удаления сообщений вне последнего видимого хвоста. Автор может убрать собственное сообщение после потери доступа; владелец отдельно открывает административный архив закрытого приложения без возможности запуска или отправки.

Apps6 добавляет шесть таблиц и проверяемую миграцию. Общая синхронная transaction сохраняет порядок Connect → World → Apps. World возвращает только пересечение нужных активных memberships и права издателя управлять соответствующей группой, без создания профиля или выдачи его содержимого.

## Исправление, найденное независимым аудитом

Первая версия зашифрованного указателя архива имела переменную длину. При неизменных видимых разговорах 105 пустых смен аудитории увеличивали указатель с 223 до 225 символов. Это раскрывало разрядность скрытого поколения, хотя содержание оставалось закрытым. Фиксированный 512-byte блок перед шифрованием устранил наблюдаемую разницу; независимый тест сначала воспроизвёл отказ, затем прошёл. Это не доказательство отсутствия любых временных каналов.

Архив полностью фильтруется по правам до формирования страницы. Скрытые строки не создают пустого продолжения или счётчика. В пределах согласованного пилота используются до 1000 материализованных разговоров на приложение и один bounded запрос World по соответствующим группам.

Наборы частично пересекаются: числа не складываются в количество независимых доказательств. Полные исходные команды и SHA модели находятся в связанных отчётах. Root запускал общий набор с `--test-concurrency=2`, reader — с `--test-concurrency=1`.

Первоначальный одновременный запуск общих наборов исчерпал доступную память Windows: SQLite сообщил `out of memory`, Node завершил typecheck по OOM, отдельный deploy fixture получил `spawn ENOMEM`. Исходные журналы сохранены отдельно и не считаются успешными. Последовательный полный повтор с ограниченным числом процессов прошёл без изменения требований тестов, assertions или таймаутов.

Миграция проверена на literal Apps5 и точном старом коде из D1, включая настоящий main5 + committed WAL6. Старый migrator отказывает до записи; байты main/WAL не изменяются. Имена, grants, сохранения, квитанции и версии источников сохраняются. Неизвестная Apps7 и неполные/ослабленные известные схемы отвергаются. Rooms2 и envelope2 не изменены.

## Границы приёмки и следующий шаг

Лимиты обсуждений — логические ограничения допуска пилота, а не физическая гарантия размера SQLite/WAL или масштабируемости на миллионы пользователей. Локальные измерения одного World JOIN и прохода по архивам не заменяют промышленную нагрузку. Курсоры живут в одном service instance; после перезапуска требуется новый снимок. Сохранность введённого текста при таком сбросе должна быть доказана в D3/D4.

Видимые компоненты приложения этим этапом не менялись. Реальные браузерные сценарии save → return → discussion, новые панели и контроль отсутствия старого UI относятся к следующему подплану. Production не перезапускался; внешний домен, точные Linux candidate/fallback, свежая защищённая копия и isolated restore остаются обязательными условиями выпуска.
