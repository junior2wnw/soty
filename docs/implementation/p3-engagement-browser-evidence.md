# P3-D4 — интегральная проверка сохранений и обсуждения

Изолированный стенд: UI 5420, подписанный Connect API 5421, QA connector, настоящий sample source 56323. Production не менялся. Локальная приёмка после `e00f3a0` завершена; внешние gates ниже остаются открытыми.

## Реальные клиенты и границы доказательства

Владелец работает в настоящем браузере с существующим QA-аккаунтом. Независимый участник создан штатным `createClientWithStorage.bootstrap`, его второе устройство присоединено через `startEnrollment → approveEnrollment → previewEnrollment → finishEnrollment`. HTTP-запросы действительно подписываются клиентом и проверяются сервером. Ключи существуют только в памяти QA-процесса, служебный loopback endpoint возвращает лишь выбранные результаты. Это два аккаунта и два устройства второго аккаунта, а не физический телефон или пользовательское исследование.

Участник использует точный вход `entry-demo.named.localhost:5421/?list=d4%2Bone#items`. Основной legacy-адрес приложения остаётся отдельным закрытым входом. Контрольный helper хранит один неизменяемый save intent и один send intent; повтор с другого устройства использует прежний request ID, conversation и body.

## Подтверждённый цикл

1. До публикации canonical context для обоих устройств участника отвергнут с `app_unavailable`.
2. Владелец через настоящую форму включил «Все по ссылке» для выбранных локальных адресов. После ACK alias context и entry разрешены, canonical context по-прежнему закрыт. Параметры query/hash не изменились.
3. Участник сохранил alias; второе устройство прочитало то же сохранение с revision1, теми же domainId/origin/path. Название и состояние выдаются только в разрешённой текущей проекции.
4. Участник отправил одно сообщение в публичный разговор. Второе устройство увидело его. Точный повтор с второго устройства вернул `replayed:true` и тот же message ID, без второго сообщения.
5. Браузер владельца увидел сообщение участника. После перехода из личной аудитории текущий composer пуст; прежний «Черновик D3 — ещё не отправлять» показывается отдельно и не отправляется в публичный разговор. Личный архив содержит прежнее сообщение и доступен только для чтения.
6. Владелец вернулся в «Аппки → Сохранённые → Обсудить». Открыт сохранённый canonical domainId с исходным path, а не автоматически выбранный public alias.
7. После UI-отзыва публичности оба устройства участника больше не получают alias entry/context. Точный повтор уже принятого сообщения возвращает **только собственную квитанцию** (`replayed:true`, `message:null`), а не новое сообщение или закрытое содержимое. Собственная библиотечная запись остаётся с прежними адресом/названием, `current:null`.
8. После повторного включения публичности создано новое поколение разговора. Затем владелец закрыл только QA alias `entry-demo`; другой QA alias `settings-check` оставлен действующим. Участник получает unavailable именно для закрытого входа; сохранение не переключается на другой адрес.

Выбранные результаты: `output/implementation-20260930/p3-d4-reader-{initial-public,save-message,replay-second-device,revoked,retired-entry}.json`. Ранее принятые signed/domain acceptance tests отдельно покрывают новый send после отзыва, пересечение исходного/текущего grant, группы, удаление сохранения и administrative mode. Эти проверки не выдаются за повтор всех путей в браузере независимого участника.

## Реальный экран и найденные дефекты

- На actual320×760 восстановленный двухстрочный composer теперь имеет height68/clientHeight66/scrollHeight66 вместо прежних48/46/66. Обе строки и Send видны: `p3-d4-composer-320.png`.
- Runtime input, введённый в sample, пережил открытие/закрытие discussion без повторной загрузки iframe. Полная перезагрузка страницы и HMR не объявляются сохраняющими память стороннего приложения.
- Независимый mounted DOM fixture: autosize1/1 и полный16/16 на1280×720. `p3-d4-composer-fixture.json` хранит реальные метрики переносов, cap/internal scroll, фокуса, выделения и истории. Транспорт этой отдельной fixture синтетический; настоящая сеть проверена выше.
- Обнаружен и передан автору **сброс клавиатурного фокуса на body при выборе архива**. Исправление и независимый held-response сценарий проходят отдельный повтор.
- Обнаружена **неверная подпись «Только вам» в карточке владельца при активных public aliases**. Основной вход действительно закрыт для постороннего, но подпись карточки не должна скрывать существование публичной публикации. Узкий owner-only summary и общий formatter проходят отдельную проверку; admission не меняется.

## Внешние условия и границы

Физический телефон, установленная PWA, внешний домен/DNS/TLS, Linux fallback и фактический backup restore остаются самостоятельными gates общего плана. Не заявляется полный браузерный E2E обоих участников: owner использует browser, другой account и его второе устройство — настоящие signed HTTP clients. Исследование нового человека не заменяется QA-аккаунтом. Нативный drag textarea/все OS клавиатуры не доказаны программным inline-size fixture.

В последующем P2-I навигационном аудите нужно отдельно проверить возврат фокуса из цепочки «связи карточки → настройки → закрыть» после полного rerender домашней страницы: наблюдался `body`, тогда как внутрипанельный archive/current здесь исправлен и проверен. Это отдельный переход оболочки, не скрытый PASS текущего archive scenario.
