# P4-C2 — MCP transport и headless child grant

Дата проверки: 2026-10-01. Статус: **C1 принят и pushed8367feb; C2a принят и pushed14f419a; C2b локальная приёмка завершена; далее C2c actual clients**. Прочитаны целиком [master P0–P8](../plans/soty-human-agent-platform-20260930.md), [P4 preflight](p4-external-agent-preflight.md), действующие C1 contracts и исходники catalog, access, native coordinator, HTTP/OAuth adapters. Исследовательский срез ниже отделён от исполнения: final runtime exact SDK server/core2.2.0 и devclient2.2.0 с lock; исследованный node2.1.0 удалён как неиспользуемая dependency. [Root C2a receipt](p4-mcp-integration.md) и [root C2b receipt](p4-service-delegation-http.md) отдельно фиксируют реальные проверки. Настройки CLI, credentials и production этими checkpoints не изменены. Безопасно перепроверенные CLI `--version` и hashes не являются OAuth/MCP/model acceptance.

## 1. Два решения и предел результата

1. **Один stateless `/mcp`, два явных wire profiles:** `2026-07-28` и `2025-11-25`. Maintained SDK отвечает за codecs/lifecycle; существующий Capabilities domain — за authority, idempotency, budget и Notes proof. Нет MCP session store, второй identity/ledger, GET event channel, SSE replay, Tasks, MRTR, sampling, elicitation, `activate_tool` или generic execution. У нового профиля конечный JSON response; у штатного legacy fallback SDK — конечный SSE response на конкретный POST. Это всё ещё Streamable HTTP, а не deprecated отдельный HTTP+SSE endpoint.
2. **Headless parity отдельным узким HTTP derive:** реальный service actor передаёт только часть своего разрешённого grant отдельному leaf service principal. OAuth connections C1 остаются non-delegable. Дочерний Notes effect проходит тот же native coordinator/root budget. Выдача child credential однократная; digest-only store не позволяет восстановить plaintext после потери ответа. Нельзя маскировать новую выдачу автоматическим retry.

Завершённый C2 означает работающие четыре tools, оба protocol profiles, actual HTTP child grant, owner-visible расход/историю/отзыв и два настоящих CLI transport/OAuth smoke. Полные 24 RU/EN задачи обеих моделей — отдельный P4-D1; внешний production HTTPS/restore/release — P4-D2. SDK smoke не заменяет CLI, а CLI login не доказывает model tool use.

## 3. Существенные несовпадения, которые C2 должен закрыть

- В `server/capabilities-oauth.js` `/mcp` сейчас намеренно возвращает `transport_unavailable`, причём находится после `!runtime` AS gate. Новый MCP adapter монтируется **до** этого guard/reservation; keyless действующий bearer/read/replay должен работать при AS off. PRM остаётся существующим C1 endpoint.
- В `access.mjs` `access.grants.derive` — signed owner command, не headless API. Нельзя вызывать его с выдуманным account/device либо parent из request. Нужен узкий branded-service port (§8).
- Исторический preflight предлагает `{invocationId,status,...}`; реальный принятый HTTP envelope уже `{invocation,reused?,result?:{noteId,revision,url}}`. C2 использует **реальный envelope** и общий safe projection, не создаёт конкурирующую форму receipt и не расширяет output capability@1.
- `documentation.mjs` ещё пишет «допуск/проверка результата появятся отдельным этапом» и `externalWriteAdmission='unresolved-before-write-enable'`. Это sidecar, не semantic contract. Нужна отдельная узкая актуализация на действующий fatal Unicode / full-document byte admission; pinned digest/input/output не меняются. Composed OpenAPI также ещё содержит историческое «No OAuth»; root обновляет только реально смонтированные surfaces.
- **Короткая проза плюс structuredContent недостаточны выбранному OpenCode.** [catalog.ts:38–75](https://raw.githubusercontent.com/anomalyco/opencode/v1.18.15/packages/opencode/src/mcp/catalog.ts) синтезирует JSON text только при пустом content; [session/tools.ts:376–468](https://raw.githubusercontent.com/anomalyco/opencode/v1.18.15/packages/opencode/src/session/tools.ts) строит LLM output из content. Поэтому cursor/Invocation ID/schema должны находиться и в TextContent. Это source-backed finding, ещё не actual model run.

## 4. Точный transport и SDK seam

`POST ${H}/mcp`, где `H` — существующий trusted canonical shell origin. Никаких query, path alias, redirect в SPA, encoded slash/case variant или другого origin. C2 adapter сохраняет host/TLS predicate C1, single Authorization и raw-header duplicate checks; `Origin` допустим только отсутствующий или точный `H`. `Forwarded` не становится источником authority. Ответы — `no-store`, `nosniff`, `no-referrer`; SW остаётся network-only для `/mcp`/OAuth/PRM.

Предлагаемый host port: `attachCapabilitiesMcp(app,{service,origin,limits?}) -> {close():Promise<void>}`. Выключенный/unconfigured mount остаётся явным отказом; его установка не включает native execution/AS и не запускает миграцию.

Использовать public SDK `createMcpHandler(factory,{legacy:'stateless',responseMode:'json',maxRequestBodySize:2097152,keepAliveMs:0,maxSubscriptions:0})`; factory создаёт **новый** `Server`/`McpServer` на каждый request. `Server` с `supportedProtocolVersions:['2026-07-28','2025-11-25']` и raw JSON-schema definitions предпочтителен для сохранения точных существующих schemas; все четыре input/output handlers явно валидируются доменным/transport validator. Не импортировать SDK internals и не обходить codec. Public low-level `Server.projectCallToolResult` даёт тот же wire projection. [Serving API](https://ts.sdk.modelcontextprotocol.io/v2/serving/http.html), [legacy serving](https://ts.sdk.modelcontextprotocol.io/v2/serving/legacy-clients.html), [ProtocolOptions source](https://raw.githubusercontent.com/modelcontextprotocol/typescript-sdk/v2.2.0/packages/core-internal/src/shared/protocol.ts), [Server projection](https://raw.githubusercontent.com/modelcontextprotocol/typescript-sdk/v2.2.0/packages/server/src/server/server.ts).

В pinned [createMcpHandler](https://raw.githubusercontent.com/modelcontextprotocol/typescript-sdk/v2.2.0/packages/server/src/server/createMcpHandler.ts) `responseMode` относится только к modern; legacy transport по умолчанию SSE. Переданный `parsedBody` обходит SDK byte limit; Host/Origin/token SDK не проверяет. Поэтому host сначала завершает ограниченный ingress, затем передаёт один проверенный parsed object через public API. Не разрешать default4MiB/100-message batch только потому, что библиотека это умеет. `subscriptions/listen` SDK перехватывает отдельно от tool handlers: `maxSubscriptions:0` и negative wire gate обязательны; отсутствие listChanged само по себе не доказывает отсутствие долгого потока.

| Profile | Допуск и ответ |
|---|---|
| 2026-07-28 | Per-request `_meta` и совпадающие `MCP-Protocol-Version`, `Mcp-Method`, для tools/call —`Mcp-Name`. `server/discover`, tools/list/call без initialize. SDK формирует modern result metadata/resultType. Missing/mismatched header →400/-32020; unsupported revision →400/-32022 |
| 2025-11-25 | initialize/initialized, затем запросы с `MCP-Protocol-Version:2025-11-25`. Legacy response остаётся legacy, без ручного modern envelope. Первый initialize может не иметь version header; после него отсутствующий header не означает поддержку старого2025-03-26. Не заявлять поддержку других revisions |
| Оба | Один JSON-RPC object на POST, batch/posted responses не принимаются. Tools capability без listChanged; нет resources/prompts/Tasks/logging/sampling. Нормативные границы: [2026 Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http), [versioning](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning), [2025 transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports). Modern/legacy classification и header comparison выполняет SDK; host добавляет только согласованную revision/body/method admission policy. Unsupported-method ответы сохраняют JSON-RPC error, чтобы клиент не принял их за отсутствующий endpoint старого SSE.

## 5. Четыре tools и результат

`tools/list` всегда возвращает один стабильный небольшой список в указанном порядке; не весь registry и не персональные descriptors. Cursor для этих четырёх definitions не выдаётся; неожиданный cursor — invalid params. Names, schema и descriptions server-owned. Instructions в первых512 символах объясняют create-only/private, обязательный стабильный key и различие receipt/current Note; не просят доверять чужому тексту.

| Tool | Точные arguments | Успешный structuredContent |
|---|---|---|
| `catalog_search` | `{query?:string,limit?:integer,cursor?:string|null}`; domain defaults/bounds A1 | Точно public search `{scope,revision,items,total,cursor}` |
| `catalog_get` | `{capabilityId:string,version:integer}` | Точно public detail `{scope,capability,documentation,links}`; private/unknown одинаково отсутствует |
| `notes_create_draft` | Ровно `{title:string,body:string,idempotencyKey:string}` | Действующий safe HTTP create envelope `{invocation,reused,result?}` |
| `invocations_get` | Ровно `{invocationId:string}` с существующим pattern UUID36/legacy32 | Safe read envelope `{invocation,result?}`; без input/current Note lookup |

Все argument objects `additionalProperties:false`. Schema title/body копируется из immutable `notes.createDraft@1`, key добавляется только в **tool transport** schema:8–160 UTF-16 units, без whitespace/control. Пределы title160/body100000 UTF-16, canonical input262144B, полный Notes document262144B и fatal lone-surrogate refusal до admission сохраняются. NFC/NFD не нормализуются. Публичная schema остаётся JSON Schema2020-12 плюс явно описанный runtime profile; другой SDK validator не расширяет принимаемое @1 множество. Semantic digest остаётся `95008a3424e375b6bdefec6e41bbdfb411dc98e6b4fd4505f387ce552c162204`.

`outputSchema` описывает transport envelope, а не выдаёт его за output capability@1. Внутри success результата `{noteId,revision}` отдельно проверяется прежним `validateOutput`; URL выводится только из проверенного historical receipt и **H**, не из resource `H/mcp` или request Host. URL обычный `H/#notes/<id>`, не credential/existence proof. Из общего `server/capabilities-actions.js` извлекаются только fixed orchestration/safe projection, чтобы HTTP и MCP не разошлись; generic actorless результат наружу не выходит.

Для успешных результатов всех четырёх tools `content=[{type:'text',text:JSON.stringify(checkedEnvelope)}]` плюс идентичный object `structuredContent`. Это устраняет OpenCode seam §3, поддерживает [MCP structured-result compatibility](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) и сохраняет ID/cursor/schema для модели. Не дублировать prose, не эхо Notes input; catalog examples — только уже публичный sidecar. Schema выводится из одного источника, проверяется фактический final encoded byte size. Вложенные local `$defs`/refs если нужны строятся при startup из фиксированных schemas; remote refs не разрешены. Ошибки имеют отдельную text-only проекцию §6 и не объявляются успешным structured result.

Read tools: readOnly=true, destructive=false, openWorld=false. Create: readOnly=false, destructive=false, idempotent=true **для одного неизменяемого key/input в действующем namespace**, openWorld=false. Аннотации не дают authority и не означают, что автоматический новый key безопасен. Create не advertised как task/async execution; неизвестный durable outcome возвращает свой Invocation для последующего get, а не ложный успешный Note.

## 6. Authority, ошибки и cancellation

Все `/mcp` requests, включая discover/initialize/tools/list, требуют текущий bearer. Public HTTP catalog/HTML остаются общедоступными. MCP auth вызывает прежний strict `authenticateCredential` для `soty_cap_`, иначе закрытый `oauth.authenticateBearer`, **audience ровно `H/mcp`**; HTTP actions/derive требуют `H`. Scope и clientInfo в MCP payload не являются Connect identity. Никакого token passthrough в Notes/другой RS. Existing C1 PRM challenge: `H/.well-known/oauth-protected-resource/mcp`; issuer `H/oauth`. [MCP authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization), [C1 resource contract](p4-oauth-storage-contract.md).

Private actor удерживается только в закрытом request context/factory closure, не в сериализуемом `authInfo` с подделываемыми account/grant полями. После network read домен повторяет current chain check. Shared fixed sequence: admit → proof-first reconcile → beginAttempt/execute только когда разрешено → **fresh authorized get**. Same-connection lost-ACK replay проверяется до readiness; другой OAuth connection с занятым namespace/key получает прежний deny-only conflict, даже после purge/revoke. Refresh actor читает свой старый receipt, но не продлевает original execution credential/expiry.

SDK dispatch/response introduce awaits, которых нет после read в нынешнем HTTP adapter. `await handler.fetch(...)` ещё не завершает legacy обмен: возвращённый Response содержит читаемый SSE stream. Host **сначала полностью читает конечный SDK body под byte/deadline cap §7**, сохраняя сформированные SDK JSON/SSE bytes; только затем выполняет fresh current read/authority fence для того же actor/Invocation и без нового await передаёт bounded buffer в `res.end`. До этой проверки не отправляется ни один private wire byte. Штатный [toNodeHandler](https://raw.githubusercontent.com/modelcontextprotocol/typescript-sdk/v2.2.0/packages/middleware/node/src/toNodeHandler.ts) сразу передаёт читаемый body в Node writer, поэтому прямое подключение без этого узкого final-output gate недостаточно. Второй codec/SSE parser не нужен. Персональный результат, собранный до revoke/account expiry, нельзя поздно отправить лишь потому, что первый bearer check прошёл. Public catalog не требует invoke readiness. AS-off/keyless current auth/get/replay работает; operational disable не скрывает свой прошлый receipt и не разрешает новый effect.

Ошибки до dispatch:401 + правильный PRM challenge для missing/expired/wrong-audience bearer;403 для Origin/current denied;413/415/408/429 для ingress; malformed JSON/JSON-RPC и unsupported method — typed protocol errors, без отражения body/header/token в message. Unknown tool — -32602. Валидный tools/call с неверными arguments/domain refusal возвращает `isError:true` и безопасный `{error:{code}}` как один JSON TextContent, **без structuredContent**; нет SQL/stack/внутреннего store ID. Pinned [SDK1.29 client](https://raw.githubusercontent.com/modelcontextprotocol/typescript-sdk/v1.29.0/src/client/index.ts) валидирует любое присутствующее structuredContent по успешной outputSchema даже при isError:true; text-only error сохраняет domain code для OpenCode, не маскируя его новым InvalidParams. Коды повторяют safe HTTP semantics (`invalid_input`, `payload_too_large`, `invocation_not_found`, `invocation_request_conflict`, `service_unavailable`, allowlisted limits). Отказ fresh read после эффекта не раскрывает actorless receipt. Failure не означает отсутствие Note.

Cancellation: до admission закрытие request прекращает работу; после durable admission/Notes COMMIT transport abort не делает rollback, release budget либо новый key. SDK закрывает request instance/response, доменный reconcile сохраняет правду. Legacy notifications/cancelled не становятся произвольным invocation cancel API; current finite sync Notes transaction нельзя прервать уведомлением посередине COMMIT. Нет нового public cancel tool/P6B. Клиент восстанавливается `invocations_get` или точным повтором прежнего key/input; после новой OAuth connection этот key может дать только generic conflict, owner history остаётся источником решения.

## 7. Проверяемые ограничения transport

| Граница | Предлагаемый C2 предел |
|---|---|
| Ingress |2MiB raw body,15s absolute read; UTF-8 fatal, без BOM/compression, один bounded allocation, strict CL/TE/duplicate raw headers |
| JSON object work |До JSON.parse ограниченный scan: depth≤20, nodes≤10000, duplicate decoded keys запрещены; root —single object. `_meta`≤16KiB; request ID —safe integer либо string≤160 units. Не echo arbitrary clientInfo/metadata |
| Concurrency |8 active exchanges/process,2/socket peer; lease до output/close, не только до body read.60 attempts/60s/peer,≤2048 peer slots; capacity и deadlines только уменьшаются trusted test options |
| Output |Final JSON/SSE wire≤2MiB, absolute response/write deadline15s после ingress; один bounded result, no queue/progress/bus traffic. Public detail≤384KiB плюс serialized text copy/escaping укладывается; измеряется actual encoding |
| Discovery |A1 сохраняет≤128 public versions,query200 units/800B/12normalized tokens,default10/max20 items,page64KiB,cursor512B. Public filter до revision/count/rank/page/cache; private additions не меняют публичные ответы |
| Native |Прежние durable quotas/rate/root budget/original expiry/262144B input+document, без новых MCP bypass |

SDK default reader использует свой TextDecoder/сборку strings; он не заменяет fatal UTF-8/duplicate-key/tiny-chunk guard. `parsedBody` передаётся только после нашей проверки. Писатель уважает backpressure и close/deadline, затем освобождает SDK instance, bounded buffers, listeners и lease. SDK `handler.close()` закрывает только modern in-flight instances; legacy lifecycle остаётся обязанностью host. Каждый admitted request имеет свой AbortController/reader, удерживаемый в том же bounded≤8 set. Deadline, client close и общий adapter.close отменяют request, cancel/release body reader и освобождают listeners/lease, включая legacy до и после получения Response; никакой поздней отправки после abort. Это конкретные bounds, не обещание постоянного RSS или заданной production capacity. Negative slow reader/aborted response/tinychunks проверяются фактически; долгие subscription requests должны сразу закончиться отказом, а не занять default1024 streams.

## 8. Headless parity без fake owner и нового ledger

Предлагаемый закрытый service port: `service.delegation.derive({actor,label,expiresAt})`. Host повторно использует реальный `Connect.withAuthorityFence`, уже доступный composition; missing fence →controlled unavailable, AS runtime/secret не нужен. Private resolver — тот же WeakMap/ancestry, ни owner API с fabricated device, ни OAuth Token Exchange/client_credentials. HTTP: `POST H/api/capabilities/v1/grants/derive`, strict JSON **ровно** `{label,expiresAt}` (label1–100 UTF-16 units, well-formed; expiresAt safe milliseconds). Bearer ordinary `soty_cap_` audienceH; OAuth-linked caller отказан.

В одном Connect→Caps COMMIT: re-resolve parent из actor; проверить текущий ordinary credential, всю ancestry, `allowDelegation` и остаток depth; создать отдельные client/service principal/child grant/credential и существующий audit event с `actor_type='service'`, `actor_id` реального delegating principal. Creator device наследуется от проверенного parent grant как действительная линия владельца, а не новая «человеческая» идентичность. Scope фиксирован `{notes.createDraft@1,resources:['notes:new'],effects:['create'],recipients:['soty:notes']}`, leaf `allowDelegation:false,maxDepth:0`; account/root/parent/client/audience/budget из запроса не принимаются. `expiresAt<=min(current credential expiry,all parent grant expiries)` и прежний max TTL; child audience=H. Новый budget не создаётся — тот же root reservation CAS.

Ответ201: `{principal,grant,credential,token}` из существующих безопасных DTO; token один раз, `no-store`, не попадает в логи/receipt. Existing account principal/grant/credential quotas применяются до INSERT; ingress ограничен, EXPLAIN на populated rows — приёмка, а не предположение по LIMIT. Ошибка/kill после COMMIT может оставить выданный child; plaintext из digest не восстанавливается. **Автоповтора derive нет**: outcome «выдача могла состояться» требует owner list/audit/revoke возможного child и нового осознанного действия. Если нужен durable retry именно выдачи секрета, это отдельный design gate, не скрытая C2 таблица/детерминированный token.

Каскадная зависимость сейчас — от **parent grant/principal/creator**, не от credential, которым однажды делегировали. Parent grant revoke/expiry закрывает descendants; точечный service credential revoke закрывает только его последующие запросы и не притворяется отзывом уже выданного child. Ограничение срока child выше не продлевает issuer credential. Parent service не получает автоматического доступа к чужому child Invocation: child видит свои receipts, владелец — оба в PWA. Один и тот же request key у разных service clients остаётся прежним независимым namespace; OAuth cross-connection deny-only правило сюда не переносится.

Owner UI использует существующий AccessPanel: отдельный явный opt-in delegation для **manual service grant**, defaultoff, pilot maxDepth1; OAuth consent unchanged. Child показывает связь/общий budget/срок и понятный grant revoke. История не смешивает owner и service audit, не выдаёт inherited creator за человека, совершившего Note effect. Точечный credential revoke и отзыв доступа различаются текстом/проверками. Никакого автоматического генератора дерева агентов.

## 9. Последовательность, владение и реальные gates

Файловое разделение принято root для последующих отдельных implementation GO; никаких одновременных владельцев одного исходника:

| Checkpoint | Владелец / файлы | Достаточная приёмка |
|---|---|---|
| **C2a transport** | `agent_ecosystem`: NEW `server/capabilities-mcp.js`, `capabilities-mcp-ingress.js`, `capabilities-mcp-tools.js`, новые MCP tests и собственная квитанция. Root/integrator: exact package+lock, narrow common projection/orchestration extraction из actions, http-app/OAuth namespace order/OpenAPI/sidecar. Critic: отдельный audit/test-only после freeze | Actual SDK modern+legacy wire на реальном HTTP/Connect/Notes/Caps, не fake auth/readiness. SDK options/JSON/SSE/schema/byte gates до CLI |
| **C2b delegation** | Domain author: узкие `access.mjs`, `index.mjs`, при необходимости NEW `delegation.mjs`; собственные новые `delegation*.test.mjs`. Root HTTP derive adapter/contract; UI owner отдельно `access-panel.ts`+focused fixture | Real signed owner даёт delegable ordinary grant; headless HTTP получает child, creates once, budget/revoke/expiry/owner history. Никаких DDL/reader changes |
| **C2c independent + clients** | Critic: новые independent wire/authority cases. Root/operator: isolated genuine CLI homes, реальный consent/PWA. UI author делает только утверждённый bounded source fix по finding | Две выбранные executable versions, фактический negotiated revision/OAuth resource, четыре tools и owner-visible private Note. Полная D1 модельная матрица отдельно |

Обязательные причинные проверки C2a: wrong/missing/mismatched modern headers; strict2025 path не принимает2026 поле как legacy; unsupported version/future/old SSE/GET/session replay/batch; fatal UTF8/escaped duplicates/depth/nodes/tiny chunks/slow body/slow response; no listeners/leases после abort/close **также в legacy после fetch-before-body-completion**; no subscription stream. Handshake/list не требует executionEnabled. OpenCode content содержит настоящий cursor/Invocation ID/schema, success structured/text одинаковы, а text-only isError доходит с прежним domain code при advertised success outputSchema. Final byte cap проверяется максимальным valid public detail с escaping; held legacy read + revoke до flush даёт ноль private bytes.

Authority/effect parity: одинаковые синтетические inputs через HTTP и оба MCP profiles дают одинаковый бизнес-result/digest и policy; HTTP token→MCP и MCP token→HTTP отказаны. Refresh same connection + lost ACK →same Invocation/один Note; original credential expired before effect не продлевается. AS-off/keyless authorised historical read и disabled exact replay работают. Kill после Notes COMMIT/до transport response →reconcile, edit/purge не воскресают, current revoke перед delayed flush не раскрывает receipt. Body никогда не появляется в get/error/log; foreign/sibling/unknown IDs одинаково закрыты. Существующие B2/C1 suites не повторяются без изменения их границы: проверяются новые transport seams сверху настоящих stores.

C2b negatives: fake actor; body parent/account/audience/budget/scope; OAuth/nondelegable parent; expired credential/ancestor; чужой parent; quota до mutation; расширенный effect/recipient; child key не даёт parent/foreign history. Actual два writers/children на последнем root unit →не более одного admission/effect, root spent один; revoke parent grant/creator на втором Connect handle закрывает child. Точечный revoke parent credential после derive сохраняет child ровно по §8. Kill после derive COMMIT/доresponse оставляет metadata для owner/revoke и не приводит к automatic replacement key.

Два CLI: изолированные выбранные binaries/homes, синтетический аккаунт и настоящий signed consent; static IDs `soty-codex-cli`/`soty-opencode-cli`, resourceH/mcp, scope `notes.createDraft`, S256. Codex callback `http://127.0.0.1/callback` с ephemeral port; **не добавлять oauth_resource**, ранее это удваивало resource. OpenCode callback `http://127.0.0.1:19876/mcp/oauth/callback`. Реальный browser authorize/resume/code/token →CLI initialize/list →catalog RU/EN →create/get →открытие в owner PWA →revoke отказ. No DCR/fake approval/client ID authenticity claim. Safe trace сохраняет только versions/revision/method/tool/status/synthetic IDs/digests, не codes/verifiers/tokens/body. Не называть protocol acceptance model acceptance; если model credential/доступ отсутствует, этот точный gate остаётся открыт, SDK его не заменяет.

## 10. Что решено исследованием, что требует исполнения

Primary stable versions и SDK seams подтверждены; установленным CLI не приписана ненаблюдённая revision. Конкретные integration risks —AS-dependent `/mcp`, private response после SDK await, OpenCode text-only model projection, revision defaults, bounded nested ingress, non-replayable child secret— внесены в подплан. C2a/C2b source и локальные executable gates выполнены по последующим отдельным GO; этот исходный исследовательский документ не подменяет их квитанции.

Root отдельно принял one-shot plaintext response, lost-response unknown без автоматического retry, owner visibility/revoke, каскад по parent grant/principal и child expiry не позднее credential/chain. Notes same-child/key exact replay обязателен; идемпотентность выдачи не обещана. Минимальное исправление устаревшего sidecar также принято. Внесены три принятые root уточнения независимого review: полный bounded read legacy SSE до fresh authorization/первого private byte, host-owned legacy abort/reader cleanup и text-only tool error для SDK1.29. C2a GO выдан после push C1; actual executable evidence принят в отдельной [квитанции C2a](p4-mcp-integration.md). C2b implementation GO выдан после C2a commit/push; domain/HTTP/UI и actual signed owner→headless child→Notes/edit/replay/mobile revoke приняты в отдельной [квитанции C2b](p4-service-delegation-http.md). Далее C2c actual CLI, без заявления выполненного OAuth/model gate по SDK tests.

После закрытия C1 checkpoint и отдельного GO сохраняется конечный порядок: **C2a source+wire checkpoint →C2b derive+owner parity →C2c реальные CLI**. Ни library version check, ни будущий план не являются выполненным P4-C2, обещанием совместимости любых ИИ или public Registry publication.
