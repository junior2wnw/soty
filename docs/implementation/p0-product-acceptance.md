## 1. Что означает утверждение preview

Сохраняем apps-first композицию: компактная постоянная навигация, узнаваемые карточки, собственная айдентика приложений, видимые сообщества, рабочая область приложения, контекстный разговор, доступное возвращение. Палитра оболочки — нейтральный графит/светлые поверхности и мягкий тёплый акцент. Синий внутри чужого приложения допустим; синяя или зелёная тонировка всей оболочки не переносится из прежней темы.

На просмотренных снимках: desktop — боковая навигация и четыре колонки карточек при 1440 px; mobile — две колонки при 390 px, горизонтальная строка сообществ, закреплённая нижняя навигация. CSS preview переводит карточки в одну колонку ниже 359 px. Это исходный визуальный образец, не доказательство удобства всех новых экранов.

Preview содержит примерных людей, приложения, сообщения, имена доменов и локальные демонстрационные состояния. Он не содержит готовых Assistant/consent/access surfaces и новой навигации «Приложения · Чаты · Помощник». Эти поверхности проектируются по master plan; третья кнопка «Создать» из preview становится действием добавления, а не четвёртым независимым продуктом. Данные и обработчики concept.js не переносятся в production.

«Практически попиксельно» проверяем на согласованной композиции и контрольных одинаковых данных. Изменение числа карточек, длинных реальных названий, доступности и масштаба текста не исправляется сокрытием данных ради совпадения снимка. Новые экраны получают отдельный review. Оценка «100/100» не заменяет перечисленные ниже проверки и не выдаётся за измеренную реакцию всех людей.

## 4. Маршруты и предотвращение случайного старого UI

Текущий entry выполняет развилку до загрузки UI. По умолчанию монтируется World; classic импортирует src/main.ts, а тот импортирует глобальный src/style.css и строит весь прежний DOM. Это полезная граница, которую нельзя разрушить ради быстрого переноса.

| Вход | Сейчас | Обязательное поведение после P2 |
|---|---|---|
| / без параметров | World и сохранённый view | Новая apps-first оболочка; миграция preferences не возвращает старую библиотеку |
| #mine, #world, #messages, #library | World views | Канонический новый маршрут или совместимое представление с сохранением Back |
| #messages/<communityId> | Community chat | Открыть тот же разрешённый разговор, не частный диалог с ИИ |
| #community/<id>/about\|chat\|apps | Сообщество | Сохранить ID, вкладку, права, выбранный контекст |
| #app/<appId>[/<communityId>] | Разрешённая app с необязательным контекстом | То же приложение; groupId не выдаёт доступ и не меняет аудиторию чата |
| #notes, #notes/new, #notes/<id> | Native Notes | Сохранить в новой app-поверхности и все draft guards |
| ?connect=… | Connect panel | Обработать приглашение/вход, вернуться в исходный контекст; не переписать секретные параметры в аналитические логи |
| ?action=connect-device#mine | Подключение устройства | Явный новый поток, возврат к выбранному устройству |
| ?view=classic[&tool=notes\|files\|chess\|terminal\|internet] | Полный classic document | Только явная совместимость/архивный вход, пока конкретный сценарий не портирован; без вложенного старого shell |
| j, connector, link, agent, agentRelay, agentRelayId | Наличие параметра включает classic | Сохранить соответствующие invite/relay протоколы; новые публичные URL не должны случайно использовать эти legacy triggers |
| reset-local, soty-reset, repair, traffic | Наличие параметра включает classic | Отдельные контролируемые recovery/traffic flows; не новый default home |
| /install/… | Classic bootstrap | Сохранить установку и возврат; не сломать entry общим redirect |

Ссылки: src/entry.ts:12; world-adapter.ts:14; main.ts:687,1690; tools-shell.ts:6. Последний добавляет собственную навигацию поверх classic, а tools-shell.css скрывает части старого интерфейса. Это не готовый reusable app frame.

Правила P2:

- Не импортировать src/main.ts, src/style.css или tools-shell.css из новой оболочки/карточки ради одного инструмента. Не вставлять старый #app, .shell, .side-panel, .dialog-shell и tools-navigation внутрь новой рабочей области.
- Сначала выделить контроллер данных/команд, затем подключить его к новому представлению. Изолированный компонент шахмат/файлов допустим после проверки стилей и lifecycle; весь classic DOM под CSS hide — нет.
- Сохранять старый маршрут отдельным документом только осознанно, с понятной подписью совместимости и возвратом. Это временное сохранение старых данных, а не сданный новый экран. Обычные apps/chat/assistant flows не должны внезапно переносить туда.
- Каждый перенос имеет route ID, владельца данных, список side effects, teardown, статус backend и независимую приёмку. Монтирование скрытого classic ради «работающих функций» запрещено.
- Новые стили scoped; общие theme tokens имеют один источник. Не переносить из preview глобальные .shell/button/:root правила без преобразования в дизайн-систему проекта.
- Не копировать fictitious apps/people/messages/online counters, local demo publish, “cloud success” и example domains в реальные состояния.
- Все пользовательские данные выводятся безопасно; карточка не превращает app description в исполняемый HTML. Названия и доступность не определяют права.

| F11 | Список pending ciphertext/controlQueue может расти независимо от чтения | Ограничить reader И in-flight encrypted chunks/очередь, ACK/backpressure, disconnect/retry. Один slice вместо arrayBuffer не доказывает bounded RAM |

F10 подтверждён чтением sync.ts:606–648 и features/files.ts:68: downloadReceivedFile заново создаёт Blob из пустых bytes отправленной записи вместо её содержимого. Runtime-сценарий и hash-проверку выполняет исполнитель исправления. F11 выявлен интегратором в sendControl/pendingFileControls/controlQueue (sync.ts около 1501); отдельная независимая проверка должна покрыть offline/slow receiver, а не только быстрый happy path.

## 6. Последовательность P2 с независимой сдачей каждого результата

P2 зависит от навигационных/статусных/identity контрактов P1. Можно разрабатывать read-only поверхности раньше, но нельзя выдавать consent/revoke за работающие без серверного исполнения. Публикация P3 и agent Notes P4 сдают свои функции отдельно.

| Подэтап | Конкретная работа | Приёмка, после которой идти дальше |
|---|---|---|
| P2-A. Контракты маршрута и поверхности | Route map выше; account switch/return target; разделить controller/view; описать интерфейсы app/chat/task/consent | Прямые ссылки, Back/Forward, logout и старый invite не теряют контекст/данные; новый default не импортирует classic |
| P2-B. Дизайн-система и каркас | Neutral palette single source, шрифт с лицензией, типографика/spacing, native semantics и выбранная совместимая headless-библиотека, shell/nav/overlays | Desktop/light/mobile сопоставлены с preview; 320 и 200% читаемы; keyboard/focus/contrast до переноса сложных screens |
| P2-C. Реальные app cards и поиск | Источники реальных apps, pinned/recent, контексты и availability; lazy preview; app launch frame/return | Нет demo records, двойного launch или hidden autorun; empty/loading/error/offline различимы; открывается правильная app |
| P2-D. Notes и сохранность работы | Встроить существующий domain state/session/drafts, обновить presentation; quick create/checklist; archive/trash/conflict/export | Ввод → app switch → Back/refresh/offline/update; текст сохранён или честно восстанавливается. Account A не видит draft B |
| P2-E. Люди, сообщества и разговоры | Перенести discovery/group/membership/moderation; общий inbox и audience header; разные conversation keys | Join/request/invite/revoke, два разговора одной app/группы, unread и drafts; app/DM пока не подменены community chat |
| P2-F. Помощник, устройства и доступы | Постоянный private assistant, устройство/project, текущие tasks/artifacts; consent и «Доступы и действия» на контрактах P1 | Новый человек находит устройство, знает кто/где действует, открывает результат и отзывает клиент. Own/external имеют одинаковый допуск |
| P2-G. Сохраняемые инструменты | File transfer/download/memory/backpressure исправление; команды, шахматы, прежние комнаты и recovery по migration map | Sent/received binary hash совпадает; очереди bounded при slow/offline; команды/игры/legacy история работают без вложенного old shell |
| P2-H. Поле и микровзаимодействия | Общая геометрия; stable layout; связи по выбору; понятные app/person/community; motion на состоянии | Соты не растянуты, текст/focus не обрезан; фильтр/добавление не ломают ориентацию; всё можно сделать без drag/hover |
| P2-I. PWA и интеграционная сдача | Один lifecycle controller; update guards; cache/account границы; слабое устройство, сеть, формы, polling cleanup | Multi-tab update ждёт сохранения; возврат после discard; нет дублирующих listeners/jobs; закрытие UI не выдаёт fake cancel |

Независимый reviewer после каждой подзадачи получает: короткую цель, изменённые файлы, ручной сценарий, доказательство результата, известные ограничения и способы возврата. Он проверяет поведение и внешний вид, а не только снимок автора. Найденные defects закрываются до следующей зависимой задачи. Нет «весь интерфейс готов, осталось подключить кнопки».

Перед выбором UI library проверить текущую vanilla TypeScript архитектуру и доступность native dialog/form/details. Не вводить целый второй framework только ради меню. Сохранить единый набор компонентов/семантики; решение библиотеки не оправдывает потерю поведения существующих редакторов.

Без необходимости UI не трогает modules/connect, modules/notes/server, modules/apps/server, trustlink keys/storage, grants, launch-ticket, CSP, service worker protocol. Улучшение внешнего вида не является основанием ослаблять эти границы.

## 8. Независимая визуальная и пользовательская приёмка

Проверки выполняются на реальном тестовом стенде с определёнными разрешёнными QA-данными. Синтетические люди допустимы только в изолированном fixture, никогда как production activity. Для сравнения screenshot закрепить состояние, шрифт, размер, DPI и тему; различия из-за данных не маскировать.

- [ ] V01 Desktop 1440 и 1024: apps-first иерархия, один header/nav, отсутствует legacy second toolbar; поиск/добавление/контекст сразу доступны.
- [ ] V02 Mobile 390 и 320: нет горизонтального overflow оболочки; нижняя навигация не закрывает действие/последнюю строку; community strip прокручивается осознанно.
- [ ] V03 768, landscape и 200% текста: тексты/контролы не перекрываются; карточки перестраиваются, а не уменьшают шрифт ради сетки.
- [ ] V04 Dark/light и светлота 0/25/50/75/100: computed tokens соответствуют новому источнику; проверены все текстовые/interactive пары, focus и disabled state.
- [ ] V05 Hex geometry: единая ориентация; размеры/radius пропорциональны; стыки и скругления не искажают форму; длинный контент не вылезает; доступная hit area/focus не ограничены декоративным clip.
- [ ] V06 Card actions: открыть app, открыть связи, сохранить, чат и меню дают разные ожидаемые действия; вложенная кнопка не запускает карточку второй раз.
- [ ] V07 Space state: selection, scroll, фильтр, search input, camera и контекст возвращаются; новые объекты не сдвигают прежнее поле без причины.
- [ ] V08 Overlay: начальный focus внутри, Esc/закрытие доступны, возврат к trigger, фон не активен; mobile keyboard не закрывает submit/error.
- [ ] V09 Semantics: button для действия, link для перехода; name/role/state доступны; Enter/Space и Tab; drag, hover и цвет не являются единственным способом.
- [ ] V10 Feedback: ошибка остаётся рядом с полем/задачей и даёт исправление; успех основан на ACK/postcondition; уведомления не перехватывают ввод.
- [ ] V11 Chat audience: app/community/DM/assistant различаются без чтения инструкции; composer draft не уходит другому адресату при переключении.
- [ ] V12 Notes: пустая запись, длинный русский/латинский текст, чеклист, конфликт двух окон, offline, quota failure, экспорт, delete/restore; нет ложного «Сохранено».
- [ ] V13 Permissions: account/client/resource/data/recipient/expiry/cost видны; человек объясняет допуск и самостоятельно находит revoke; уже отправленные данные не обещаются возвращёнными.
- [ ] V14 Task: accepted/running/needs input/approval/uncertain/failed/cancel requested/confirmed/results; уже выполненные эффекты не исчезают за красной или серой меткой.
- [ ] V15 App runtime: устройство offline, process stopped, revoked, несовместимый iframe, медленный запуск, separate tab; отсутствие live runtime не маскируется красивым preview.
- [ ] V16 PWA: установленная и обычная вкладка, multi-tab update, unsaved form, bfcache, background/discard, offline/online; никакого автоматического повторного опасного действия.
- [ ] V17 Accounts: A→B→logout/revoked; в DOM, drafts, caches, recent и output не остаётся чужого содержания.
- [ ] V18 Files: оригинал и скачанный sent/received имеют одинаковые размер/hash, включая empty/Unicode/binary; slow receiver/disconnect ограничивают память reader и ciphertext queue.
- [ ] V19 Lifecycle/performance: многократный app/chat/notes switch не множит polling/listeners/iframe и не теряет формы; loaded catalog bounded; измерения на слабом устройстве.
- [ ] V20 Human test: новый человек открывает app, создаёт записку, находит людей/сообщество, устройство, результат агента и отзыв без подсказки автора; фиксируются конкретные ошибки, не общая оценка «нравится».

Для V01–V05 эталон — утверждённый preview и текущие изменяемые data states. Для V06–V20 одного screenshot недостаточно: нужен реально выполненный сценарий и результат. Проверки assistive technology и физической клавиатуры телефона не заменяются расчётом ширин DOM.

Стоп-условия: утрата подтверждённого текста/файла, смешение аудиторий/аккаунтов, скрытая публикация/отправка, ложное «готово/остановлено/сохранено», расход вне допуска, сломанный старый invite/recovery, классический shell внутри нового экрана, недоступное основное действие. Эти дефекты нельзя компенсировать красивой главной.

## 9. Четыре первичных основания

| Источник | Как используем | Чего источник не доказывает |
|---|---|---|
| [W3C APG — Button](https://www.w3.org/WAI/ARIA/apg/patterns/button/) | Действия и переходы имеют соответствующую семантику; кнопка именована, работает с клавиатуры; focus следует результату действия | Не доказывает популярность формы, цвета или конкретной карточки Сот |
| [W3C APG — Disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) | Дополнительные функции раскрываются предсказуемой кнопкой, с aria-expanded и доступной клавиатурой | Не требует скрывать частые действия или последствия допуска за «ещё» |
| [W3C — Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) | Существенные состояния объявляются без перехвата focus; live feedback не превращается в непрерывный поток для screen reader | Не делает корректными ложные бизнес-статусы и не заменяет тестирование |
| [Microsoft Research — Human-AI Interaction](https://www.microsoft.com/en-us/research/articles/guidelines-for-human-ai-interaction-eighteen-best-practices-for-human-centered-ai-design/) | Ясные возможности/ограничения, контекстная информация, возможность исправить/отклонить, глобальный контроль | Исследовательские рекомендации не доказывают предпочтения конкретных пользователей Сот и не обещают «вау у каждого» |

Психология понятности здесь — проверяемые гипотезы о распознавании действия, сохранении внимания и контроле ошибки. Скрытые «подсознательные триггеры», искусственная срочность, бесконечные уведомления и затруднение выхода не используются.

## 10. Сдача P0

Продуктовый inventory и P2 acceptance contract составлены. Подтверждённые source risks переданы интегратору; особенно classic routing/style leakage, динамический источник старой палитры, неполные conversation types, ложное повышение job status до результата и дефекты files.

Интегратор сообщил о поднятом стенде 5300, исходных снимках и пройденном baseline. Это отдельные доказательства интегратора; данный reviewer не заявляет повторный browser/test run. Для начала P1 документ не требует дополнительных пользовательских согласований. Переход к P2 происходит по контрактам master plan и перечисленным gate; кодовый preview не считается готовым продуктом.
