# Ограниченное чтение манифеста агентом

Этот интерфейс позволяет агенту прочитать название и отпечаток **одного заранее выбранного** `.soty/app.json` на устройстве владельца. Он не перечисляет соседние папки, не обращается к порту приложения, не запускает процесс и не добавляет карточку в Соты. Успешное чтение не доказывает, что приложение работает или поддерживает вход Сот.

Нужен подключённый владельцем коннектор с capability `preparedManifest`; первый исходный выпуск с ним — **1.4.14**. До пересборки и установки соответствующего bundle опубликованный 1.4.13 не поддерживает эту операцию и корректно отказывает. Старый Root также не предоставляет её. Это не изменение существующего notes OAuth: ключ для заметок не даёт доступа к проекту.

Ошибка `prepared_connector_unsupported` означает, что подключённый процесс коннектора не подтвердил поддержку этого чтения; нужно обновить именно его, а не повторять действие через старый `browse`.

## Выдача разрешения через подписанный Connect API

Ниже путь для разработчика интеграции. Обычный экран Сот пока **не умеет выдавать** этот конкретный доступ: не представляйте пример как готовую кнопку или автоматически полученное согласие. Вызывающий клиент должен использовать уже действующее подписанное устройство владельца и получить от него отдельное явное согласие на указанные устройство и проект.

1. Выберите принадлежащий владельцу `hostDeviceId`, `connectorId` и точный `location` (`rootId` и относительные `segments`). Операция `apps.prepared.agentScope` проверяет владение, доступный корень, путь и сам файл на устройстве; она не делает HTTP-запрос приложению.

   ```js
   const selection = { hostDeviceId, connectorId, location };
   const scope = await connect.extension('apps.prepared.agentScope', {
     expectedAccountId: accountId, ...selection,
   });
   // Покажите человеку устройство, выбранный путь и scope.project.name.
   // Продолжайте только после явного согласия на чтение этого проекта.
   ```

2. Для отдельного сервисного исполнителя подпишите существующие `access.principals.create`, `access.grants.issue` и `access.credentials.issue`. Разрешение должно содержать ровно capability `{ capabilityId: 'apps.prepared.manifest.read', version: 1 }`, ресурсы `['apps.prepared.manifest', scope.resource]`, пустые `effects`, получателя `['soty:prepared-manifest']`, ограниченные срок и бюджет; по умолчанию `allowDelegation: false`, `maxDepth: 0`. Аудитория ключа — точный адрес Root с суффиксом `/mcp`. Обрабатывайте созданный секрет как одноразовый: не записывайте его в документацию, логи или чат. При неизвестном результате выдачи сначала проверьте и отзовите старый доступ, а не создавайте новый автоматически.
3. Передайте агенту уже разрешённые `selection` и `scope.project.digest`. Найдите точную версию/отпечаток контракта в собственном `apps_catalog_search` и вызовите существующий `apps_query`:

   ```js
   {
     reference: approvedReference,
     idempotencyKey: oneStableKeyForThisRead,
     input: { ...selection, manifestDigest: scope.project.digest }
   }
   ```

Ответ содержит только `schema`, `state: 'present'`, `name` и `digest`. Разрешение связано с владельцем, исходным устройством, связью коннектора, выбранным корнем и относительным путём и исходным отпечатком манифеста. Изменённый файл, другая связь, другой путь или чужой владелец требуют нового явно выданного разрешения. Учётная запись агента остаётся сервисной и не становится устройством человека.

`apps_query` использует существующий ограниченный журнал чтения. Точный повтор того же ключа возвращает историческую квитанцию без текста результата; для нового чтения с сохранённым разрешением нужен новый ключ и единица бюджета. При отзыве или смене владельца до выдачи ответа содержимое не возвращается. Нет гарантии распределённой атомарности между разными хранилищами; доработку нельзя считать регистрацией или запуском приложения.
