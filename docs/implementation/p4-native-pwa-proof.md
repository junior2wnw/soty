# P4-B2 — HTTP результат продолжается в настоящей PWA

30.09.2026. Root прошёл сценарий через IAB, обычную production-сборку UI и нынешний `createHttpApp` на отдельном `http://127.0.0.1:5470`. Это synthetic loopback QA, не боевой аккаунт, установленная PWA или внешний AI-клиент. Общий старый стенд5420 и пользовательские данные не менялись.

## Условия

Новый каталог `var/p4-native-browser/data`, собственный nonce marker, пустые Notes/Capabilities. Только в этом каталоге схемы2 подготовлены явным закрытым migration-вызовом; обычный host по-прежнему не мигрирует их автоматически. Host получил явные `capabilityAudience` и `nativeNotesEnabled:true`. Inference не настроен. QA запускает HTTP-состав приложения; WebSocket-комнаты в этом узком стенде не обслуживаются и не проверяются.

Профиль создан самим интерфейсом с обычными подписанными Connect запросами. В «Доступы и действия» выбран новый учебный клиент: только создание личных записок, без чтения прежних и без передачи доступа, срок1час, лимит2действия. UI показал правильные ограничения и подтверждённое создание ключа. Ключ оставался закрытым password-полем, не копировался и не выводился в отчёт.

Изолированный QA HTTP wrapper наблюдает только собственный успешный ответ `access.credentials.issue`, передаёт выданную credential в памяти настоящему `fetch`-клиенту и не меняет результат Connect/HTTP. Он не подставляет владельца, не делает fake actor и не читает browser storage. Собственный endpoint `__qa/native-result` содержит лишь безопасную квитанцию. Wrapper находится в ignored `var/`, не входит в приложение/сборку.

## Пройденная цепочка

1. Учебный клиент вызвал настоящий `POST /api/capabilities/v1/notes/drafts`:201. Повтор того же ключа/текста:200, `reused:true`, тот же Invocation.
2. Владелец открыл вкладку «Действия»: ровно одно «Создание записки», имя клиента, «Завершено», одно сохранённое изменение и ссылка «Открыть записку».
3. Нажатие настоящей ссылки открыло `#notes/<noteId>` в той же авторизованной PWA. Редактор содержал исходное название и точные3строки:

```text
Одна задача — один результат.
Точный текст: е́ и é, 中文, 👩🏽‍💻.
Продолжить работу можно здесь, в Сотах.
```

4. Через обычный textbox дописана четвёртая строка «Продолжено человеком в PWA.». Наблюдался переход локального статуса к «Сохранено»; после настоящего reload все4строки остались.
5. Desktop1280×720 и viewport390×844 просмотрены в screenshots. На390px название переносится, текст/toolbar и нижняя навигация доступны; measured `documentElement.scrollWidth-innerWidth=0`. После проверки viewport reset.

Отдельный read-only SQL audit собственного QA-каталога подтвердил: одна записка revision2 после человеческой правки, один retained proof, один Invocation и один receipt; reserved0/spent1; входной текст Invocation удалён после terminal commit. Это подсчёт настоящих SQLite rows после браузерного сценария, не только число карточек в интерфейсе.

Визуальные captures просмотрены в tool output; отдельные screenshot-файлы этим receipt не заявляются. Read-only DOM проверка сравнивала `textarea.value`, включая NFD/NFC, CJK и emoji, а не только картинку. UI source для результата не менялся. При чтении доступов обнаружена неточная accessibility-подпись «Одноразовый ключ доступа»: ключ допускает разрешённые повторные вызовы, одноразов только показ. Подпись исправлена на «Ключ доступа»; объяснение однократного показа и скрытое поле сохранены. Это небольшая текстовая поправка, не повторная реализация формы.

Полные сетевые lost-response/revoke/purge сценарии и независимая проверка схем относятся к [HTTP gate](p4-native-http.md). Человеческий новый участник, физический телефон/клавиатура, установка/offline PWA, OAuth/MCP, настоящие внешние AI-клиенты и production остаются отдельными критериями. Этот сценарий подтверждает именно переход от разрешённого HTTP-действия к продолжению человеком в реальном UI.
