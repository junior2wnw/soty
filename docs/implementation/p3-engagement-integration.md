# P3-D3 — интеграция сохранений и обсуждений

Дата: 30 сентября 2026. Локальная приёмка кода D3; D4, публикация и весь P3 остаются незавершёнными. Основание — D2 `4ff4359`. Исходная рабочая папка `D:\соты` не менялась.

## Результат

У приложения появился единый экран с сохранением выбранного входа, обсуждением и вторичными действиями. На главной доступна личная библиотека «Сохранённые». Закрепление на этом устройстве называется «Закрепить здесь». Открытие разговора и доступного архива не перезапускает мини-приложение. На узком экране панель занимает его область, сохраняя iframe и введённое внутри состояние.

Черновик, ожидающая отправка и квитанция связаны с аккаунтом, точным входом и разговором. Смена аудитории не переносит текст. Неподтверждённый эффект повторяется с прежним requestId; ошибка локального сохранения останавливает уход и возвращает адрес панели к реально показанному разговору. Фоновое обновление сохраняет фокус и выделение собственного текста, временно блокируя отправку до нового разрешённого контекста. Недоступный сохранённый адрес не заменяется другим origin.

## Границы кода

- Root: `apps.entry.get`, entry в launch, shell routes/account lifecycle, `mountAppStage`, интеграция библиотеки. Entry происходит из того же разрешения, что билет. После неудачного первого запуска разрешён отдельный lookup для offline source; malformed successful launch отвергается.
- Автор состояний: bounded account-owned saved/draft/pending, устойчивые квитанции, cursor feed и очистка закрытых проекций после auth denial. [Контракт и тесты](p3-engagement-client-model.md).
- Автор компонентов: saved/library/discussion, доступные имена, состояния ошибок, архивы и собственный локальный текст. [UI receipt](p3-engagement-ui.md).
- Независимый критик: реальный signed HTTP, lost ACK/account/generation/quota сценарии, mounted DOM fixture и review авторских изменений. [Независимая приёмка](p3-engagement-independent.md), [bridge review](p3-engagement-bridge-audit.md).

Старая `application.css` удалена; её импортов/классов в действующем экране нет. Новый экран использует общие palette tokens, без копирования classic UI. Незавершённый текст после подтверждённого изменения настроек и ложное сообщение «Ссылка сохранена» для простого route удалены.

Все логи находятся в `output/implementation-20260930/`. Полный world предшествовал последним исправлениям фокуса/возврата URL; они проверены финальным66-test delta gate, typecheck/build и повтором mounted fixture. Это не повтор всего world на окончательном UI.

В fixture используются настоящие компоненты и scoped persistence, но вымышленные API-ответы и iframe srcdoc. Его DOM-события не доказывают мышь, физическую клавиатуру, screen reader, настоящий runtime tunnel или второе устройство. Статус «ошибок0» относится к собственному обработчику стенда; журнал браузера также содержит отдельную ошибку MutationObserver без доказанного источника. Она не скрывается и не объявляется исправленной по15/15.

Для уточнения добавлен пассивный error/rejection collector до module imports. Свежий запуск снова дал15/15, ранний collector0, но dev console повторил MutationObserver error без source/stack. В графе импортов стенда вызов MutationObserver не найден; это не доказательство внешнего источника. `p3-d3-fixture-early-errors.txt` сохраняет результат. Сам MutationObserver, его ошибки и assertions не заменялись/подавлялись. Дальнейшая диагностика инструмента остаётся частью D4.

## Частичный реальный браузерный опыт

На локальном API с Apps6 и настоящим коннектором подтверждены: сохранение выбранного приложения, открытие панели, сообщение «Проверка D3 · сообщение из первого окна» с серверным подтверждением и собственный локальный черновик. Сохранение текста внутри runtime при первом открытии чата наблюдалось отдельно. Эти отдельные действия не считаются полным D4 циклом.

На desktop1280×720 измерены: отсутствие горизонтального выхода, toolbar64px, runtime804×600, panel396×600, основные иконки44×44. Снимки экрана и часть pointer/keyboard действий не были получены: browser tool возвращал timeout или действие не меняло видимый экран. Последний документированный reset/rebind сохранил доступ к DOM стенда15/15, но единственный повтор screenshot снова завершился `Page.captureScreenshot` timeout. Дополнительных повторов без новой причины не выполнялось. Визуальная приёмка, полный Back/recovery и два независимых пользователя остаются открытыми. Никаких D3 pixel/screenshot доказательств не заявляется.

Тихий WS примера закрылся во время длительной проверки. [Отдельный preflight](p3-runtime-idle-preflight.md) установил120s idle и асимметрию учёта направления трафика; конкретный старый close не трассирован. Это выделено в самостоятельное исправление живости произвольных приложений, а не замаскировано heartbeat только демонстрационного проекта.

Позднейшая проверка30.09: в восстановленной IAB-сессии screenshot и pointer заработали. На перезапущенном настоящем API/connector сохранены library entry, серверное сообщение и scoped draft прежнего опыта; `p3-d4-restored-desktop.png` фиксирует1440×828. R4 отдельно проверяет source stop/reconnect и потерю ответа после реальной записи. Исторический отказ инструмента выше не является текущим запретом всей визуальной проверки. Полная D4 матрица пока не закрыта.

Причина отдельной ошибки MutationObserver изолирована [контрольным опытом без кода Сот](p3-browser-environment-audit.md): bare static HTML без JS не даёт ошибку, тот же HTML со статическим srcdoc iframe и нулём script в обоих документах воспроизводит её. Это снимает прежнюю неопределённую атрибуцию к production/fixture-коду; конкретный browser/tool realm не установлен. Ошибка среды не подавлена, успешность продуктовых сценариев доказывается отдельно.

## Следующие обязательные действия

1. Универсальная bounded WS liveness с независимым аудитом и реальным туннелем.
2. D4: полный save→return→discussion, два аккаунта/устройства, exact alias/private path, offline/revocation/retired, повтор/ошибка, работа фокуса, визуальный обзор всех ширин и отсутствие старого UI.
3. Независимая линия P4 внешних агентов после принятых общих контрактов; незаконченный внешний release не превращается в формальную блокировку её локальной реализации.
4. Linux candidate/fallback Apps6+, свежая зашифрованная копия и фактическое изолированное восстановление, выбранная отдельная registrable domain zone/DNS/TLS и real-project pilot до production.
