## 1. Один parser и закрытый порт

`extractOwnedBackup({input,target,expectedManifestSha256,sourceWitness,limits,signal?})` — private API в `restore-backup.mjs`. Нет нового decrypt, tar codec, ledger, CLI, output callback у R0/R1a или production handoff. Существующий shared parser становится async (`feed/beginEntry/finishEntry/finish`); только internal extraction mode получает проверенный `LinuxSink`, await завершает текущую file operation прежде следующего chunk. Encrypted reader await-ит feed до wipe plaintext buffer. Verify/dry используют тот же grammar/inventory core без sink, их API/receipt/errors не меняются.
`input` — принадлежащий вызову bounded binary Node Readable будущего R1c protected channel: `uint32BE metadataLength + metadata JSON + tar`. Не произвольный async iterable, objectMode/text/уже consumed stream; controlled producer не push-ит chunk >64KiB и obeys backpressure. Private key/AES key receiver не получает. Metadata/manifest и body остаются untrusted до проверок.
На не-Linux: fixed `restore_platform_unavailable` **до чтения input или filesystem I/O**; нет portable fallback. На Linux options/limits/pins захватываются один раз внутри safe-error boundary; неизвестные поля/некорректный native signal отвергаются, `signal.reason` не выводится.

## 2. Exact target, trust и identities

```text
target = { targetId, mountNamespace:{dev,ino}, namespace:RootPin, dataRoot:RootPin, configRoot:RootPin }
RootPin = { path, dev, ino, mountId }
targetId: 32 lowercase hex; dev: bigint >=0; ino: bigint >0; mountId: positive safe integer
```

Это in-process shape; будущий trusted control adapter может декодировать strict canonical decimal strings в bigint, никогда через Number. Все path — bounded canonical absolute POSIX strings ≤4096 UTF-8 bytes, не `/`, без controls/backslash/empty/`.`/`..` components; каждый component ≤255B. `dataRoot.path` ровно `namespace.path + '/data'`, `configRoot.path` ровно `namespace.path + '/config'`. Namespace содержит только эти две пустые roots, все три initially0700 и принадлежат helper euid; namespace остаётся private0700 после finish.
Trusted setup снимает pins **в mount namespace самого exact owned helper до payload**, связывает их с owned target/spec в прежнем controller journal; host `/proc` mount IDs не сравниваются с helper IDs. Namespace identity сверяется через `/proc/self/ns/mnt`; каждый открытый FD — bigint fstat dev/ino + bounded `/proc/self/fdinfo/<fd>` mnt_id. Pins не берутся из metadata и не угадываются по именам. Root descriptors удерживаются до finish; identity повторно сверяется перед mutation и receipt.
Private local filesystem и sole writer — prerequisite: helper не имеет serving mounts, Docker socket, egress, другого write principal или процесса, меняющего ancestors/mounts. Начальные ancestors каждого root проверяются по lstat и no-follow directory open; внутри data/config дерева каждый ancestor/FD должен иметь ожидаемые root dev/mountId и сохранённую identity. Bind/nested mount substitution, symlink, wrong inode/type/owner или непустая цель → refusal. Hostile privileged root и concurrent external ancestor replacement не объявляются защищёнными этим Node path-based API.
Root setup задаёт umask0077; runtime fixture helper: root, cap-drop ALL, только CHOWN/FOWNER, no-new-privileges. DAC_READ_SEARCH/DAC_OVERRIDE от backup profile не переносим. Actual full-app UID/profile — отдельный full-image gate, foreign fixture UID этого не доказывает.

## 3. Материализация и durability

До первой записи общий core проверяет metadata bounds, closed manifest, expectedManifest pin и независимый sourceWitness, весь declared inventory/config hashes и required presence. Source paths/Mounts.Source/config values никогда не становятся destination; data names проходят strict R1a path/type policy. External file destination — ровно `configRoot/<approved manifest logical id>`; без пользовательских filename mappings. Encrypted B остаётся canonical recovery copy, configRoot — только private operational material для isolated run.
Только regular0 и directory5. Duplicate effective path/file-directory collision, link/device/FIFO/type7/sparse/ACL/xattr/unknown extensions, special mode bits и malformed UTF-8 запрещены общим parser. Никакого recursive mkdir по входному пути; parent уже создан/проверен sink. Tar root `''` сопоставляется только заранее pinned dataRoot, остальные directory entries обязаны быть новыми.
Directory создаётся0700, lstat/open `O_DIRECTORY|O_NOFOLLOW`/fstat фиксируют dev/ino/mountId; metadata откладывается до общего finish. Это bounded directory identity map, **не FD на каждую directory**. File открывается `O_CREAT|O_EXCL|O_NOFOLLOW|O_RDWR`, mode0600; fstat требует regular, nlink1 и ожидаемые device/mount, запись только через этот FD с обработкой partial writes.
File pipeline: awaited chunk writes/input hash → parser подтверждает declared size/hash → file fsync → positional readback через **тот же FD**, hash/size/EOF → fchown(uid,gid) → fchmod(mode) → fsync → fstat проверяет metadata/identity → awaited close. Config files проходят тот же pipeline. Нельзя нормализовать foreign owner/mode в root или объявить один write checksum readback-доказательством.
После полного tar EOF/strict finish — directories в порядке deepest-first; reopen no-follow со сверкой сохранённых identities, пока их ancestors ещё helper-owned0700, затем chown/chmod/fsync/fstat/close. dataRoot получает архивную root metadata последним; configRoot и enclosing namespace остаются private0700. Parent-directory fsync покрывает созданные entries; все owned descriptors закрыты до receipt. Failures оставляют только quarantine, никакого частичного accept/автоматического retry поверх неё.

## 4. Bounds и граница cleanup

Sink limits — отдельный closed object: `{plaintextBytes,fileBytes,extractedBytes,entries,headers,pathBytes,pathDepth,externalFiles,externalBytes,wallMs,idleMs,freeSpaceReserveBytes}`; все positive safe integers без defaults. `archiveBytes` не принимается: receiver ciphertext не видит. Fixed R1a caps metadata/extension4MiB, path4096B/component255B/chunk64KiB сохраняются; max declarations/paths/headers проверяются до allocation/write, один current file и одна awaited operation, без очереди payload chunks.
После manifest, до writes: bigint `statfs.bavail * statfs.bsize` ≥ declared bytes соответствующих roots + frozen reserve. Если roots на одном filesystem, их demand суммируется один раз; для разных проверяется отдельно. Проверка — не reservation; ENOSPC/quota/readonly/unsupported fsync и любое расхождение дают refusal. Trusted setup выбирает известный local filesystem, не network filesystem с неопределёнными durability semantics.
Monotonic wall deadline общий для input/write/readback/finish; idle reset только при реальном byte progress. На ожидании input — конечный deadline/abort разрушает owned input, listeners снимаются; вокруг filesystem await остаются cooperative checks. Никаких accumulating cancellation promises per chunk или success после cancellation. Закрытие input/descriptors подтверждается до success; hung syscall/close нельзя объявить завершённым по timer.
Helper RAM/CPU/PIDs/free-space provisioning, hard watchdog, cleanup deadline и exact Docker removal — **будущий parent/controller profile**, не гарантии библиотеки. При неподтверждённом cleanup прежний journal сохраняет pending; библиотека не делает recursive delete и не трогает чужие resources. Потеря receipt не разрешает reuse непустой цели/START; parent reconciles pinned target либо подтверждает cleanup перед новым owned attempt.

## 5. Receipt, ошибки и конечный gate

Private receipt ровно `{extracted:true,targetId,manifestSha256,plaintextSha256,plaintextBytes,entries,fileBytes,readbackVerified:true}`; `fileBytes` включает data и present external payload. Нет `authenticated`, `restored` или release-ready: GCM подтверждает будущий sender, а controller сопоставляет оба receipts/pins/actual process completion. Manifest/plaintext hashes только в protected control evidence; human projection — targetId/counts/fixed stage, без paths/config/per-file hashes.
Errors — fixed code/message/stack без cause/raw data: `restore_platform_unavailable`, `restore_target_invalid`, `restore_incomplete`, `restore_archive_invalid`, `restore_limit_exceeded`, `restore_timeout`, `restore_io_failed`, `restore_cleanup_pending`. Последний обозначает неподтверждённое завершение owned cleanup, не удалённую quarantine. Короткие UI пояснения наследуют reviewed R1 §7.
Будущие author files: narrow changes `backup-format.mjs`/`restore-backup.mjs`, новый `restore-sink.mjs`, новый `restore-sink.test.mjs` и отдельный receipt; никаких producer/host/deploy edits. Root отдельно владеет exact-byte загрузкой core/sink в owned Linux tmpfs, synthetic helper lifecycle/harness и runtime gate; serving mounts не используются. R1b fixture может использовать существующий bounded synthetic helper logger; full-image LogConfig:none/stream adapter относится к следующему gate.
Последовательность: review этого контракта → отдельный implementation GO → source freeze → Windows unsupported/refusal + прежние R0/R1a без ослабления → **настоящий Linux** sink acceptance → independent audit. Test fixture framing/keys только synthetic; plaintext assembler fixture не объявляется production sender.
Linux positive: exact main+WAL/config bytes и sourceWitness, независимый readback всех regular files, foreign UID/GID +0600, вложенные restrictive directory modes/postorder, empty files, fsync/close и повторное read-only inspection. Linux negatives: preexisting root/entry, wrong pin/ancestor symlink/nested mount, alias/link/type/UTF-8/payload mismatch, limit+1/free-space refusal, truncated/disconnected input/abort/held operation; внешняя sentinel file неизменна, нет accepted receipt, exact owned cleanup подтверждает parent. Не добавлять второй deploy framework ради fixtures.
Минимальные первичные primitives: [Node24.21 FileHandle/no-follow/statfs](https://nodejs.org/download/release/v24.21.0/docs/api/fs.html), [Linux fdinfo mount ID](https://www.kernel.org/doc/html/latest/filesystems/proc.html#proc-pid-fdinfo-details-about-open-file-descriptors). Это source-backed выбор API, не доказательство Linux запуска, full-image C/R или end-to-end production restore.
