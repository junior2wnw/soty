Подключения из OAuth отделены от выданных вручную ключей точным серверным marker; общего второго списка прав/выдачи ключей для одного OAuth principal нет. Выбор, срок, лимит и отзыв доступны в существующей панели «Доступы и действия».

## Найдено и исправлено

- Два подключения одного клиента могли выглядеть одинаково. Короткий код служит ориентиром, полный selectable код виден в подробностях и подтверждении. Намеренно совпадающие короткие коды покрыты независимым тестом. При недоступных подробностях показан отдельный код principal, без выдуманной связи с connection.
- При667×375 после lost ACK выросший текст оставлял кнопку частично за нижним краем диалога: bottom358.953 при dialog bottom347. Отдельный footer теперь содержит live status и действия; подробности прокручиваются независимо. Grid ограничен connection dialog, прежние dialogs не заменены.
- Подтверждённый отзыв и неизвестный результат различаются. При потерянном ответе предлагается сначала проверить тот же доступ. Повторная mutation не вызывается автоматически, соседние подключения не отзываются. Полный ID остаётся текстом; он не заменяет проверку account/authority на сервере.

Реальное подписанное OAuth→PWA подключение, физический телефон, экранный диктор и browser zoom200% не объявляются пройденными. Built production PWA и серверный signed цикл проверяются отдельно.
