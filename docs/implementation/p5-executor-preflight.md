# P5 — preflight проверяемого исполнителя

Статус: **исследование исходников и проект следующего этапа; P5 не реализован и не принят**. Дата: 2026-10-01. Прочитаны master §§10–12, P5.1–P5.6, существующие connector/job/agent/inference части и первичная документация ОС. В этом срезе создан только этот файл. Исполнители, CLI, Docker/VM, hosts, тесты и модели не запускались; конфигурации с ключами, C2c helpers/run data и production не менялись. Наличие нужных ОС primitives на конкретном устройстве не проверено.

Исходная точка worktree: `2103d755c081f03cdad98959fe593c6151ea2eec`; текущие незакоммиченные C2c изменения не являются доказательством P5. Соседний [D1 real-model plan](p4-real-model-plan.md) проверяет выбор функции настоящими моделями, но не изоляцию локального executor. Детерминированные C2c provider fixtures также её не доказывают.

## 1. Минимальное решение

Сохранить существующие Connect account/device, principal/grant/credential, Invocation/dispatch intent и durable connector jobs. Добавить одну исполняемую политику поверх этой цепочки, не второй реестр агентов, очередь заданий или отдельный финансовый ledger.

Разделить два класса. Нынешний **доверенный оператор владельца** честно работает с правами пользователя/службы устройства. Первый предлагаемый **ограниченный workspace executor** выполняет конечную задачу внутри поддерживаемого Linux runtime: выбранный входной snapshot, отдельная writable рабочая область, артефакт результата, закрытый внешний egress, ресурсы и локальный deadline. Он не получает рабочий стол Windows, произвольные host paths, порт Docker, личный HOME или полномочия установки/публикации. Это сокращение первоначально доступных функций, а не переименование широкого режима в sandbox.

Рекомендуемый первый backend — поддерживаемый rootless Docker Engine на выделенном Linux runtime account с cgroup v2/systemd и проверенной делегацией контроллеров. Он использует готовую ОС/OCI изоляцию; не строим собственные AppContainer, syscall sandbox или универсальный firewall. Нативный Windows delegated shell остаётся недоступен. Linux VM на Windows можно принять отдельно как Linux-класс на Windows-устройстве; совместимость Windows desktop из этого не следует. Недоступный backend даёт явный отказ без перехода к owner/native исполнителю.

Это предложение к review перед реализацией. Ни установка Docker/VM, ни изменение служб/ACL, ни выдача нового внешнего generic-compute grant этим документом не разрешаются.

Объявление connector «умею bounded» не является remote attestation. Смена kernel/runtime/image требует повторного gate для заявленной платформы.

## 4. Узкий контракт первого профиля

Это **предлагаемые внутренние пределы к утверждению**, не уже действующие настройки и не новый экран с десятком ползунков. Начать с одного профиля и одного job на device; если реальные fixture не укладываются, менять числа открыто до freeze.

| Параметр | Первый предлагаемый предел |
| --- | --- |
| Runtime | Pinned Linux image/toolchain digest, non-root payload, read-only image, default maintained seccomp, dropped capabilities/no-new-privileges; без privileged/host PID/host network/device/daemon mounts. |
| Файлы | Selected regular-file input snapshot ≤64 MiB/4096 файлов; отдельный tmpfs scratch ≤512 MiB; экспорт ≤16 MiB/1024 regular файлов. Image/toolchain учитываются отдельно при installation, не скачиваются по инструкции job. |
| Процессы/compute | 2 CPU quota, 2 GiB memory, 128 tasks/PIDs; swap для профиля запрещён проверяемым runtime setting. Tmpfs входит в RAM accounting, а не даёт ещё 512 MiB сверх hard limit. |
| Время | Максимум 15 min; authorization lease ≤30 s, renew целевой период 10 s; bounded stop escalation 5 s + 5 s. Это параметры, подлежащие реальному OS измерению, не hard-real-time обещание. |
| Вывод | RAM queue ≤1 MiB, одна JSON line ≤256 KiB, persisted log tail ≤1 MiB; overflow явно обрывает/усекает вывод и прекращает допустившую переполнение работу, не накапливает Promise/Buffer бесконечно. Docker container получает explicit `LogConfig.Type=none`; единственный bounded collector принимает stdout/stderr, supervisor не дублирует payload stream в journal. |
| Inference | Один job-scoped model request одновременно; первый controlled gate без расходов. Платный режим только при доказанном reservation/provider cap (§6). |

**Файлы.** Самый простой безопасный первый путь — snapshot → работа → artifact. Не монтировать live пользовательскую папку RW. Импорт/экспорт проверяет regular files, нормализованные относительные пути, число/байты, symlink/junction/reparse points, hard-link alias и race подмены пути. Копия получает новые inodes; путь, лексически находящийся под root, сам по себе не разрешение. Импорт нельзя делать через небезопасное следование links/archive traversal. До freeze выбрать поддерживаемую handle-relative/no-follow primitive для реальной ОС копирования и доказать TOCTOU negative; отсутствие этой гарантии блокирует import, а не решается одним `realpath` до копирования. Выбранный snapshot не гарантирует отсутствие добровольно включённого владельцем секрета; UI объясняет, какие файлы может прочитать модель.

**Env и инструменты.** Строить allowlist с нуля: фиксированные PATH/toolchain, locale, temporary HOME/XDG внутри job и необходимая служебная настройка. Не наследовать parent env, connector token, SSH/auth sockets, браузер/CLI profiles, cloud credentials, proxy/loader overrides или личные skills/plugins. Job не может добавить переменную/плагин/модель из своего payload. В широком owner режиме это отдельная явно обозначенная политика, не fallback.

**Host logs.** Ограничение нашего tail не ограничивает отдельные файлы Docker daemon: default `json-file` не включает rotation. Для первого профиля явно отключаем этот второй поток на каждом container, не меняя global daemon setting. `none` не сохраняет `docker logs`; accepted receipt и bounded tail собираются существующим collector, а служебный supervisor journal содержит только ограниченные lifecycle события. Проверка actual LogConfig и роста host log files при шумном payload/смерти collector входит в P5-B. Это контракт нового backend, не доказанный дефект нынешнего executor. [Docker logging configuration](https://docs.docker.com/engine/logging/configure/)

**Сеть и модель.** Для первого bounded профиля `network=none`; скачивание пакетов, webfetch и произвольный URL не поддерживаются. OpenCode нужен доступ к inference, поэтому prerequisite spike — один закрытый IPC endpoint существующего model broker с фиксированным назначением, доступный контейнеру через local socket/loopback adapter. Это узкая транспортная обвязка, не новый HTTP-proxy framework: без CONNECT/произвольного upstream/redirect/host аргумента. Raw connector/provider credential остаётся вне payload; вызов broker связан с immutable job/attempt/lease/model/data destination. Проверять актуальный допуск и резерв **на серверной стороне** перед каждой отправкой. Если такая композиция на выбранном runtime не доказана, inference там unavailable; не включать общую сеть ради прохождения теста.

Установка зависимостей и internet-доступ могут стать отдельным последующим профилем после явной egress/SSRF политики. GPU, desktop input/screen/audio/camera и долговременный app hosting не входят в этот конечный workspace профиль. Уже существующий local-app процесс не убивать как «осиротевший ребёнок» без отдельного перехода в его hosting lifecycle.

## 5. Допуск, остановка и неизвестный исход

1. **Reader/runtime прежде writer.** Старый runtime игнорирует новые policy fields у знакомого `agent`, поэтому их добавление не даёт изоляции. Для bounded режима нужен явно различимый поддерживаемый executor kind + exact profile/version/digest, который старый resolver отвергнет. Сначала freeze wire/store/rollback compatibility, затем reader/runtime capability, последним admission. Имя kind и DDL не назначаются этим research-срезом.
2. **Один durable job.** P1 Invocation/dispatch intent сохраняет свой постоянный internal requestId и existing connector admission. Snapshot/profile/model/effect bounds входят в immutable request fingerprint. Ошибка между job COMMIT и binding jobId восстанавливается по нему; новый job не создаётся. Локальный supervisor хранит только bounded запуск/receipt, привязанный к этому jobId, а не вторую очередь.
3. **Свежая chain.** Admission, начало и каждое renew сверяют original credential/expiry, текущие device/creator/parent grants и неизменённый resource/profile. Новый read token не продлевает original execution. Глобальное изменение epoch из-за sibling grant не отменяет незатронутую цепочку; отзыв собственного предка запрещает renew. Проверка authority и durable выдача lease должны быть fenced в согласованном текущем доменном порядке, без DB lock через network await.
4. **Локальный deadline.** Wire передаёт ограниченный authorization lease и generation; runtime запускается только после валидного допуска, а не после проглоченного `started` failure. Полученная с задержкой lease не начинается заново от момента доставки. Monotonic deadline ограничивается original absolute expiry и wall limit; смена часов не продлевает его. Reboot/suspend/resume и очередной network response не дают новое право автоматически. Точный clock/supervisor contract и допустимая задержка реакции — отдельный executable gate.
5. **Watchdog живёт вне payload и переживает connector exit.** Использовать OS supervisor/runtime lifecycle, не единственный `setTimeout` в том же Node процессе. Payload не может изменить deadline, продлить unit через notify, покинуть scope или перезапустить себя. `Restart=always`/container restart policy не должны повторять неизвестный эффект. Даже при смерти watcher/supervisor его собственный OS lifetime должен приводить к остановке payload либо заранее установленному конечному deadline; просто отдельного JS watchdog недостаточно.
6. **Подтверждение остановки.** Cancel сначала durable, затем запрещает новые lease/model requests, затем stop actual container/process subtree. `kill()`/`taskkill` success, signal flag, CLI exit и истёкшие 10 s не означают пустое дерево: Node также разделяет error и exit. [Node child_process](https://nodejs.org/download/release/v24.21.0/docs/api/child_process.html) Не подтверждённый stop оставляет `executionUncertain`, удерживает slot/резерв и исключает новую работу поверх возможного живого payload.
7. **Reconcile.** После reconnect старые events/results проверяются по assignment/generation, не возобновляют execution. После смерти connector/host сверяется конкретный container/job identity и durable receipt, не выполняется prompt заново. Уже отправленная внешняя операция могла завершиться; её неизвестный outcome не превращается в `effects: none` или refund. Истечение lease и свежий GET не являются доказательством отсутствия эффекта.

На Windows minimum proof для bounded unavailable — сервер не выдаёт этот kind, old/native runtime не получает его как agent и UI не предлагает ограничения, которых нет. Для доступного Linux-on-Windows профиля дополнительно нужен реальный Windows host/VM kill-disconnect test; Linux-only тест этого пункта не закрывает.

## 6. Approval, расход, receipt и release

**Owner approval.** Использовать существующий подписанный допуск Connect. Один понятный выбор до запуска: конкретный workspace snapshot, режим, получатель данных/model, срок и общий лимит. Действия внутри него не требуют бесконечных вопросов. Дополнительный host путь/сеть/публикация/бюджет/аудитория требуют нового решения владельца; текст модели и runtime permission dialog не изменяют grant. Account switch/ABA не применяет старое подтверждение к новому владельцу. Неподдерживаемое действие объясняется отказом, без автоматической установки или повышения прав.

**P1 dependency.** Текущий unit `invocations` оставляем неизменным для Notes. Для paid compute нужен отдельный согласованный versioned extension **того же** reservation/settlement механизма: integer monetary units, зафиксированные tariff/model и bounded input/output/compute, atomic reservation каждой paid attempt до network send. Одновременные запросы, SDK retries, provider races/fallbacks и дети используют один остаток. Provider identity/data destination не меняется молча. Usage/error/lost ACK дают spent/released/held по фактам; abort не обещает отсутствие списания. Пока верхняя граница не вычисляется и не исполняется самим provider/adapter, paid hard-cap профиль недоступен. D1 test budget guard не подменяет эту production гарантию.

**Receipt.** Различать execution terminal/uncertain, подтверждённую остановку и бизнес-эффекты. Минимальный proposed projection: существующие Invocation/job IDs, executor/profile/image версия, фактические timestamps, причина остановки, confirmed/unknown termination, безопасные artifact ID/hash/размеры, verificationMethod/результат проверки и reserved/spent/held cost. Текст модели — заявление, exit 0 — технический факт. Принимаемый результат подтверждает независимый bounded validator после выхода payload; validator не исполняет произвольный проверяемый артефакт с правами host. Запуск тестов сгенерированного кода тоже остаётся в sandbox. Очистка scratch не удаляет permanent idempotency/proof и не выдаётся за откат ранее опубликованных данных.

**Обновление.** Закрепить точный runtime/image/toolchain digest и доверенный release origin. HTTPS + проверенный digest подтверждают выбранную цепочку доставки; защита от компрометации самого origin потребует отдельно утверждённого signing trust root. Не приписывать подпись connector соседнему SpreadEx verifier. Staged self-test проверяет effective runtime limits, а не один `--version`. Перед новым wire/version — реальный compatible serving baseline; rollback не теряет unknown jobs/receipts и не превращает bounded kind в native agent. Отключение bounded admission не закрывает owner history/cancel/reconcile.

## 7. Порядок работ и владение

| Срез | Зависимость и конечный результат | Предлагаемая область изменения после отдельного GO |
| --- | --- | --- |
| P5-A: contract/compatibility | Freeze двух классов, exact bounds/wire, fresh lease/stop/effects semantics, durable migration/rollback; текущий Notes и owner режим сохраняют смысл. | `server/connector-store.js`, `server/connector-persistence.js`, `server/connector-api.js`, `scripts/agent-modules/executor-policy.mjs`; domain reviewer отдельно. |
| P5-B: один Linux backend | Реальный effective resource/files/env/egress/self-test и supervisor lifetime; bounded profile unavailable при любой недоказанной prerequisite. Сначала deterministic payload, без модели. | Узкий новый runtime adapter в `scripts/agent-modules/`, композиция `scripts/soty-connector.mjs`; OS acceptance отдельно от unit tests. |
| P5-C: chain/partition/receipt | Existing Invocation→job binding, fresh start/renew, local deadline, no reoffer, crash/reconcile, bounded output, подтверждённый tree stop. | Те же connector зоны + минимальный existing Capabilities dispatch/access seam; тесты source/runtime и двух процессов. |
| P5-D: inference/cost | Job-scoped broker без наследования credential; фиксированный provider, reservation каждого attempt, held unknown. Платное исполнение остаётся закрыто до результата. | `server/gonka-proxy.js`, connector model-auth route, существующий P1 budget module. Отдельный review тарифного/DDL контракта до edits. |
| P5-E: Windows/release/UX | Проверенная матрица supported/unavailable для настоящего Windows device и Linux server; update/rollback, owner confirmation, receipt/cost/unknown UI. | `scripts/build-agent-release.mjs`, connector update/self-test, `src/platform/assistant.ts`; Windows и Linux acceptance раздельно. |

Это порядок зависимостей, а не разрешение одновременно менять все зоны. Начинать с P5-A + одного P5-B spike после согласования runtime installation; не строить Windows AppContainer, GPU режим, общий scheduler и arbitrary egress параллельно. P5-C использует backend lifetime, P5-D зависит также от утверждённого P1 денежного расширения. Общий P5 gate не закрывать по одной контейнерной демонстрации.

## 8. Meaningful acceptance — будущие проверки, не результаты

| Набор | Реальный отрицательный/пограничный опыт | Необходимое наблюдение |

Предел реакции измерен на каждой заявленной ОС. |
| Authority | Отзыв своего parent/device/creator/credential до start и между renew; paired sibling revoke; fresh read credential при expired original. | Своя цепочка останавливается/не продлевается; sibling не ломает чужую; чтение не продлевает execution. | Durable seams | Actual kill после job COMMIT до binding, до/после runtime start, после artifact/effect до receipt, receipt до ACK; reconnect и same-key retry. | Один existing job/эффект либо честный unknown, не повторный prompt; старый generation не снимает fence; delayed receipt reconciles без новой работы. |
