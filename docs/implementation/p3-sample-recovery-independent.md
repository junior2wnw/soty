Дата: 2026-09-30. Область: реально выдаваемый `/app.js` отдельного примера «Покупки», сохранность ввода и поведение при неизвестном результате записи. [Сетевая живость R3](p3-runtime-liveness-independent.md) принята отдельно; этот отчёт не переносит её выводы на форму или сохранность произвольного iframe.

## Подтверждённый дефект

Прежний `requiredSnapshot = snapshotRevision + 1` считал достаточным любое сообщение WS после начала POST. Это не связывало отображаемый список с результатом данной записи.

Независимый стенд получает HTML и скрипт от настоящего `createSampleApp`, выполняет выданный скрипт в небольшой DOM/VM оболочке, использует реальный HTTP origin и настоящий WebSocket. Он удерживает допуск первого POST и доставку отдельных уже полученных WS callbacks. Авторские fixtures не импортируются; рабочие QA порты и пользовательские данные не используются.

Воспроизведение:

1. Первый toggle удерживается перед отправкой серверу.
2. Другой настоящий writer добавляет строку через прежний `/api/items`. Приходит broadcast со старым состоянием переключаемого пункта.
3. Первый toggle допускается: сервер действительно меняет `done` на `true`, конкретный HTTP ACK доставляется. Соответствующий WS snapshot пока удержан.
4. Интерфейс всё ещё показывает `done=false`, но снимает запрет записи. Следующий click способен инвертировать уже выполненное изменение.

На исходном коде проверка была RED: ожидаемая недоступность checkbox отсутствовала (`false !== true`). Затем тест усилен до наблюдаемого эффекта: попытка активации не должна создавать второй POST, а запрет должен быть доступно обозначен. Проверяются два порядка: посторонний snapshot доставлен до ACK либо задержан до момента после ACK. Второй порядок исключает недостаточное исправление «подождать любое сообщение после ACK».

## Принятая узкая коррекция

Автор добавил версию только в opt-in представление sample API: `/api/items?snapshot=1` и `/live?snapshot=1` возвращают `{instance, revision, items}`. Прежние array/echo endpoints остаются для существующих клиентов и transport tests. Один счётчик повышается от всех применённых изменений, включая legacy POST.

Конкретный успешный ответ POST задаёт барьер `instance + revision`. Новая запись разрешена только после соответствующего или более нового snapshot того же запуска. HTTP ACK не перерисовывает список; запоздавшая меньшая WS revision не откатывает его. Числовые revision разных запусков не сравниваются. При смене запуска требуются явное подключение и проверка списка, без повторения POST.

Это причинная согласованность конкретного примера, а не idempotency protocol или обещание exactly-once. Потерянный ответ по-прежнему означает unknown. Исходный текст попытки и новый ввод раздельны; A → B → A защищается revision ввода. Reconnect выполняет только чтение, а снятие предупреждения остаётся явным действием.

## Клавиатура и доказательства

Интегратор независимо воспроизвёл в настоящем браузере потерю фокуса в BODY при native `disabled=true` для reconnect и checkbox после Space. Сохранение того же DOM элемента само по себе этого не предотвращает; исходный VM fixture не моделировал native blur от disabled.

Исправление использует `aria-disabled` и синхронные guards обработчиков, без позднего принудительного focus. Независимый тест допускает native или ARIA обозначение, но обязательно проверяет отсутствие лишнего POST. Native validation у временно недоступного add подавляется отдельным click guard; submit guard сохраняется.

На конечном `8a81acb…` интегратор сообщил фактический browser повтор: Enter на reconnect сохраняет фокус этой кнопки; Space на checkbox и последующий ACK сохраняют фокус checkbox. Настоящий commit с потерянным HTTP response оставляет unknown, исходный A отдельно от draft B; recovery GET/WS не добавляет POST. Счётчик origin: 2 записи — один нормальный toggle и одно добавление с потерянным ответом; dropped=1. Это сообщение интегратора, не собственное управление браузером рецензента. Его automation отказывается нажимать aria-disabled control, поэтому этот опыт не назван ручной проверкой двойного Enter; прямой отказ повторного handler проверен controller tests. Размеры 320/667, selection и окончательная геометрия остаются отдельной браузерной квитанцией.

## Границы

Тестовая VM не является браузером. Удержание доставленного сетевого callback проверяет причинный порядок, а не физическое заполнение TCP buffer. Sample хранит список и черновик в памяти; это не доказательство сохранности после перезапуска сервера, reload либо новой iframe navigation. Более новая запись другого человека после подтверждённого snapshot остаётся обычной конкурентной записью, а не нарушением этой проверки. Unknown не превращается в подтверждённый отказ или автоматический повтор.
