# Existing applications: current Root composition

Source-only candidate from `2af0fd10ea2892db1a8cc67da0f5417b9472082d`. No production call-site or private configuration is changed.

`createExistingAppHostComposition()` returns empty `externalApplications` and references. A private CODE registry can explicitly supply the existing `{appId,target,catalog,adapter,guidance}` records. The constructor uses `captureExternalApplications` unchanged, retains the original Native binding rather than combining it twice, and returns `httpOptions` for `createHttpApp` plus exact `sourceReferences` for the existing personal-agent composition. References/catalogue existence are not capability grants.

At execution, unchanged Root code applies Connect/current credential, owner-of-Root-credential, current Apps participant/target-revision/digest, and installed adapter checks. Root publication ownership does not become ownership of Native data. Root app/source/grant/device/credential changes still deny. The Native adapter must enforce its own current rights and fixed resource. The host does not issue an actor, read a private configuration, discover a destination, or create a storage/schema/dispatcher.

The Tavysh status adapter verifies a Native-owned explicit consent certificate, fixed Root account/client/principal, app/target/resource/project/incarnation/release and device signature. A query accepts only empty input, makes two bounded nonce-bound Native readonly attestations around Root checks, compares exact Native revision/lifecycle/status, and returns a <=2048-byte status projection. It does not play/upload audio, expose title/media/key/profile, write, publish or invoke a model. Unknown Native failures become safe unconfirmed results; current Native denial and current Root denial remain denied. An exact ledger retry uses existing metadata semantics and does not repeat a Native query.

The Native device port is in a separate branch from `af5745cadd77e9fe29c8bd4ec0fd14011d2cc3c9`. It reads actual existing `projectStore`, nonexportable current device key, local profile context, and the retained cloud lifecycle row. Native UI alone holds its opaque pending consent handle; an RPC/body Boolean is not approval. Grant max300s, consent request120s, signed read10s, max64 pending/grants and fixed `project.status` are closed. Profile/device/cloud A-B-A/incarnation/revoke/stop/expiry checks surround async signing/read. No Native account, cloud registration, SQL table or new IAM issuer is created. Native UI presents explicit read-only consent in the original profile and does not import a Root profile. Lost delivery after known Native approval does not regress to "not granted" or replay approval.

The actual Source BFF `rememberLogin`/`commitIdentity` still requires a synchronous final Native carrier frame. Async browser IndexedDB cannot substitute for that frame; the old candidate and its DENY paths remain unchanged. This new path is an explicit per-operation readonly bridge through the existing Root external broker, not a claim that the entire Tavysh OAuth/carrier/UI integration is ready. The physical owned browser-context signer/broker still needs Root review and actual installation before enabling the CODE registry. Current Native owner consent is independent of common Root login.

HIVE's already demonstrated human Source2/Native-profile3 route, per-project feedback, reply/Ready/reporter acceptance, restart and app revoke are preserved. Generic Root registration already supplies required EcoLab feedback; Source per-project ACL/receipts stay in the existing native adapters. This module adds no feedback dispatcher. Reviews keep the existing approved app/project/person subject bindings and public-read/managed ports; no association or review authority is inferred from a manifest. Peremetrika `4042027` keeps its actual default-OFF Native SourceHost, same installed SDK namespace/current PageAuth/NativeStore. Soty commit `181e5` contains managed-review fixture startup, not the Native Poveday implementation. Neither app is advertised as mounted by this candidate.

The cross-fixture test uses real current Root `createHttpApp`, signed Connect, Apps registration/participant ACL, SQLite capability ledger, and the actual new Native signing/read code on its maintained synthetic IDB fixture. It proves functioning query wiring, real Root revocation and publisher!=Native-owner. It does not claim browser/concurrent-IDB conformance, real personal data, full Native SSO, 24h recovery, effects, provider/model readiness or whole SourceReady.

Run this separate integration suite with `npm run existing-apps:integration:test` and an explicit `SOTY_TAVYSH_DEVICE_SOURCE_ROOT` pointing to an owned copy of Native commit `39b3e21ed74f1acb7043d077008a66332935bfe2`. It lives in `server/integration-test/` because the ordinary server suite and Docker build must not require a developer's Native checkout. No implicit local path or skipped Native pass is used.

Proposed single mount after Root/Platform review (not applied): obtain CODE registry from already approved installed Native ports, call `createExistingAppHostComposition({enabled:true,registry})`, and spread `host.httpOptions` into the existing `createHttpApp` options. Pass `host.sourceReferences` to the existing personal-agent source-reference/credential seam only with its current authorized credential. With no approved Native broker/ports, call the configless constructor; it stays OFF. No change to `server/index.js`, personal-agent configuration or default storage is included.
