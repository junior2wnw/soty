## MutationObserver: отрицательный контроль

Журнал IAB показывал `Failed to execute 'observe' on 'MutationObserver': parameter 1 is not of type 'Node'`. Собственный ранний page-realm collector fixture видел0, а15/15 DOM tests проходили. Нулевой collector не объявлялся чистой консолью.

Root создал отдельный raw Node HTTP server на loopback56325, без Vite и без импортов приложения. Его первый ответ — обычный статический HTML с heading/paragraph/button, **без script**. Ошибок в журнале нет. Второй ответ отличается только этим статическим элементом:

```html
<iframe title="Статический frame"
  srcdoc="<p>Статический вложенный документ без скриптов.</p>"></iframe>
```

На втором ответе появляется та же ошибка в11:28:40.538Z. Проверка DOM показывает0script в верхнем документе и0script в child через frame locator. Исходник контрольного server также не отдаёт никакого JavaScript. Следовательно, код Сот/его импортов не является необходимым условием этого воспроизведения; ошибка относится к среде браузерного наблюдения. Какой конкретно механизм браузера или инструмента её вызывает, по этим данным не установлено.

Доказательства: `output/implementation-20260930/p3-d4-script-free-iframe.json`, `p3-d4-script-free-child.json`, `p3-d4-script-free-iframe.png`; изолированный control script — `var/p3-entry-browser/browser-control.mjs`. Контрольный сервер не получает пользовательских данных. MutationObserver, исключения, обработчики и assertions приложения не заменялись и не подавлялись.

Независимый критик принял ограниченный вывод: ошибка всё ещё наблюдается в среде, но не считается найденным дефектом production на основании её наличия в этом журнале. Ошибки со ссылкой на код приложения, некорректные состояния, потери данных и проваленные сценарии остаются самостоятельными блокерами.
