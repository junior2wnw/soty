## Обнаруженные и исправленные дефекты

1. Preview по alias терял owner settings, reload показывал общий заголовок. Optional account metadata теперь восстанавливает title/settings, не меняя launch authority и не задерживая запуск до каталога. Сопутствующий риск offline смены account, смешения A → B → A и очереди запросов исправлен; независимые реальные client/service пробы прошли, см. `p3-owner-settings-ui-review.md`. Это не заявление о фактической смене аккаунта в браузере.
2. На320px частная ширина окна конфликтовала с общей bottom-sheet геометрией и оставляла справа16px. Исправлено scoped `width:100%` на том же breakpoint760px.
3. Последовательный native Escape мог закрыть окно после первого отменённого close, потеряв обычный draft. Исправлено локальной обработкой Escape на keydown до default close; два последовательных Escape фактически пройдены.
4. Общий dialog trap пропускал summary, а скрытое содержимое details сохраняло layout boxes. Исправлен общий семантический отбор focus candidates, включая все закрытые ancestor details. Фактические прямой и обратный обходы пройдены.
5. Скрытый checkbox tombstone мог активироваться кликом по label. Он теперь disabled и повторно проверяет bound/canPublish в change handler. Это source/API проверка; permanent retire в браузере ради этого опыта не выполнялся.

Все опыты используют настоящий API/connector, не подменяют UI ответами. Во время редактирования TypeScript Vite перезагружал страницы; опыты, затронутые HMR, не считаются проверкой сохранности при обычном reconnect. Browser state прочитан только через DOM; cookie, boot tickets и storage contents не выводились.

## Исходная последовательность

1. Открыть существующее приложение с главной и его новые настройки. Проверить настоящий owner read-model, адрес и readonly источник; без элементов classic UI.
2. Изменить название; закрыть/открыть окно и страницу. Открытый HTTP/WS-сеанс приложения и назначенные доступы должны сохраниться.
3. Получить новый свободный адрес. Проверить, что резервирование само не публикует проект; активировать отдельно. Неудача публикации не скрывает уже сохранённое имя.
4. Переключить аудиторию локального приложения, подтвердить точный источник для доступа по ссылке; проверить постоянную ссылку и настоящий запуск через B3.
5. Проверить копирование по фактическому Clipboard result, а не по нажатию кнопки; в ссылке отсутствует одноразовый ticket.
6. Два открытых окна: сохранить имя в одном, попытаться сохранить прежнюю revision в другом. Пользовательский ввод остаётся, конфликт объяснён; принятие текущего состояния явно.
7. Отсоединить только тестовый connector, обновить состояние; адрес остаётся. После reconnect старое наблюдение не считается новым ответом; затем настоящий preview.
8. Desktop/320/667×375, длинные названия/адреса, клавиатура/возврат фокуса/закрытие, внутренний scroll без горизонтального overflow. Снимки с измеренными размерами.
9. Отдельно зафиксировать непроигранные в браузере ошибки: потеря ACK/прореженная история/сбой storage/account switch. Их модульные и API-проверки не называются браузерными.

## Итоговый повтор на freeze

После окончательных изменений client/adapter/controller выполнено явное обновление приложения: настоящий список загрузился, WebSocket показал «подключено», название и owner settings сохранены. Окно настроек показало оба активных адреса и «Источник отвечает». Снимок `output/implementation-20260930/p3-settings-desktop.png` — фактический viewport1280×800. Существовавшая до повтора ошибка входа не объявляется успешным входом: успех зафиксирован после явного обновления. Полный автоматический gate указан в `p3-owner-settings-integration.md`.

## Границы

Это C1 существующего неизменяемого источника. Смена устройства/порта, публичный DNS/TLS, настоящие внешние проекты, Safari/Firefox, физический телефон и screen reader не принимаются наличием этого экрана. Незавершённые проверки не помечаются PASS.
