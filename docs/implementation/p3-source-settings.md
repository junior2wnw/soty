# P3-C2-C — управление источником в настройках

Основание: C2-A `efe0d9f`, C2-B `5a4cb1d`. Оба checkpoint отправлены в origin. Это подплан интерфейса, не подтверждение его реализации или production-выпуска.

## Последовательность и владение

1. **Контракт.** Один блок «Источник» внутри существующего окна: текущий источник → выбор устройства/порта/пути → проверка ответа → явное переключение. «Предыдущие источники» показывает неизменяемые конфигурации, не журнал событий и не резервные копии данных. Возврат требует новой проверки. Серверная модель C2-A/B не заменяется.
2. **Состояние — publishing_architecture.** `app-settings-state.mjs/.d.mts`, `app-settings.types.ts`, новый `app-source-state.mjs/.d.mts` и авторские tests. Та же account/app-scoped durable pending запись, Web Lock и requestId. Source-only `expectedSource` хранит ограниченную проекцию проверенного назначения для показа и сопоставления receipt, но не readiness, proof или срок. В запрос уходит только прежний args. Эфемерная подготовка привязана к выбранной цели, текущим CAS и аккаунту; срок отсчитывается монотонно с вычетом времени запроса. Потерянный ACK повторяет ту же операцию после reload/истечения proof без новой подготовки.
3. **Интерфейс — agent_ecosystem.** `app-settings.ts/.css`, авторский отчёт. Стабильный DOM, нативные select/number/details, краткие объяснения при отказе. Новая проверка/переключение недоступны при несохранённых изменениях аудитории или активных адресов; отдельный resetPublication сохраняет черновики имени, grants и slug. Повтор pending этим условием не блокируется. Public-source switch требует свежего подтверждения whole-port для конкретного нового tuple. История загружается ограниченными страницами, поздние ответы не меняют новый выбор.
4. **Интеграция — root.** Owner-only inventory сообщает negotiated bindingVersion выбранного текущего соединения. Inspection показывает floor и точное состояние привязки текущего target, не выдаёт старый ACK за новый. App toolbar обновляет устройство/имя без пересоздания iframe. Ошибки получают понятные сообщения. Root владеет `index.mjs`, `inspection.mjs`, точным getState в `runtime-bindings.mjs`, их авторскими tests, `app.ts`, `dialogs.ts`.
5. **Независимый аудит — whole_product_critic.** Отдельные tests/component fixture/отчёт, без исправления production-файлов автора. Проверить lost ACK/reload, несовпадающий receipt, две вкладки/CAS, время в background, публикацию и tombstone, preserved unrelated drafts, смену аккаунта, history cursor, Back/Escape/focus/320px/landscape. Сценарные находки возвращаются владельцу файлов.
6. **Приёмка root.** Полный локальный test/typecheck/build; настоящий браузер с перезапущенными Apps4 API и connector 1.4.0: A→B→A, explicit public ACK, недоступный источник, сохранность адресов/данных/черновиков, pending и responsive. Отдельно помечаются synthetic, реальные HTTP/WS, настоящий браузер и внешние непроверенные условия. После исправлений повторить затронутые сценарии, зафиксировать checkpoint.

## Границы утверждений

- «Источник отвечает» означает только свежий ограниченный HTTP ответ. Это не проверка кода, безопасности или работоспособности всех страниц.
- Switching меняет маршрут приложения, а не переносит базу данных проекта. История конфигураций не обещает откат данных.
- Онлайн-устройство не обязательно поддерживает проверяемое переключение. Версия показывается из текущего negotiated channel, не из общей версии сервера.
- Новая source promotion не применяет попутно несохранённые audience/name/grants. Точный эффект показывается после проверенного receipt; неизвестный исход остаётся доступным для проверки.
- Все данные тестового стенда изолированы. Production, новая публичная зона, физический телефон и совместимый Linux fallback остаются отдельными gates.

## Уточнение доступности после независимого разбора

[W3C Timing Adjustable](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html) отдельно рассматривает авторские ограничения времени, включая ограничения ради безопасности. Инженерный вывод для Сот: proof остаётся действительным 30 секунд, но чтение и решение человека не должны зависеть от этого окна. Это проектное решение, не заявление полного соответствия WCAG.

После истечения карточка кандидата остаётся читаемой. Обычная «Проверить ещё раз» никогда не переключает источник. Альтернативное явное действие «Перепроверить и переключить» получает новую проверку и создаёт intent только при совпадении полного ранее показанного target, его pins, исходного policy epoch/target, аудитории и согласия. Любая смена аккаунта, скрытие/редактирование/смена контекста во время операции или расхождение свежего результата возвращает к просмотру без переключения. Решение не продлевает proof, не сохраняет consent на диске и не заменяет повтор неизвестного pending новым запросом.

Порядок клавиатуры: поля → проверка → результат и согласие → переключение. Состояние объявляется через status, ежесекундный счётчик не озвучивается постоянно ([W3C Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)). Controls сохраняют общий размер 44px и отдельно проверяются на узком экране; это выше минимального 24px критерия с его оговорками ([W3C Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)).
