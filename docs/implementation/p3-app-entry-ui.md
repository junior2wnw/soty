# P3-B3 — точный вход в приложение из оболочки

2026-09-30. Авторская реализация UI; независимая браузерная приёмка выполняется отдельно. Изменены только `src/world/app.ts`, `types.ts`, `application.css`, добавлены `app-launch.mjs`, его declaration и тесты. Серверные cookies, ticket exchange, reset и runtime pages принадлежат другим подпунктам B3.

## Поведение

- `#launch/<appId>/<domainId>?path=…` открывает точный app/domain/path через `apps.launch`, без вызова `apps.list`. До и после запуска оболочка использует нейтральное имя, если проверенных метаданных нет. Название содержимого показывает само приложение; клиент не угадывает владельца или приватные данные.
- Старый `#app/<appId>[/<communityId>]` сохраняется. Запуск больше не зависит от ответа каталога. При необходимости название и разговор сообщества подгружаются отдельно под проверкой текущего аккаунта/экрана. Chat wrapper создаётся до iframe; поздний контекст не переносит уже открытый iframe и не расходует одноразовый ticket повторно.
- Одна неизменная цель используется при первоначальном запуске, повторе, обновлении, открытии отдельно и возвращении после выбора аккаунта. Ошибка не отправляет на главную. Новый маршрут не пишется в старое хранилище recent actions, которое не умеет сохранять domain/path; старые записи продолжают работать. Текущий точный hash сохраняет ссылку, без ticket.
- Всякий запрос получает `expectedAccountId`, захваченный из `deskAccount`. После await успеха/ошибки проверяются аккаунт, поколение экрана, уничтожение компонента и текущий маршрут. Смена аккаунта уже уничтожает старый World через существующий adapter; дополнительно launcher не пропускает его поздние ответы.
- Toolbar и текстовая кнопка «Открыть отдельно» появляются до первого await. Внешний запуск синхронно создаёт пустую вкладку по клику, запрашивает новый ticket и переводит только ещё актуальную вкладку. Повторный клик во время ожидания не создаёт очереди. Отказ popup blocker не расходует ticket. При уходе с экрана pending blank закрывается сразу; успешно открытые вкладки остаются у пользователя.
- При синхронном пересоздании app screen после Retry/Refresh фокус из старого app screen переносится на новый заголовок. Асинхронный успех/ошибка не перемещают фокус: выбранная за время ожидания кнопка остаётся активной. Это точечная правка по независимому review; реальная клавиатурная проверка входит в browser gate.
- «Другой аккаунт» открывает существующую панель аккаунта и сохраняет цель. Обновление оболочки повторно открывает app/launch intent. При холодном offline запуске ссылка сохраняется и показываются действия подключения, а не посторонний экран записок.
- Iframe сохраняет `sandbox="allow-scripts allow-forms allow-same-origin"`, `referrerPolicy="no-referrer"`. Нет postMessage, автоматического обхода cookie, навигации iframe в shell или обещания «готово» по событию load. Boot сообщает результат cookie-проверки внутри окна; external action постоянно остаётся в оболочке.

## Границы данных

`app-launch.mjs` проверяет формат app/domain ID, единственный path-параметр и отсутствие неизвестных query-параметров. Path — локальный путь до 8192 символов; external/protocol-relative URL, backslash, controls, malformed percent encoding пути, `/_soty` и его нормализованные обходы запрещены. Проверяется также нормализация `/.//host`.

Legacy hash-router пути `/#/dashboard` и `/board?tag=a%2Bb#item` разрешены: внутренний `#` кодируется как `%23` внутри внешнего shell route. Второй незакодированный `#` в самом shell route считается повреждённой ссылкой. HTTP direct navigation не позволяет серверу видеть fragment браузера; это не обещание восстановления неизвестного fragment.

Server launch URL остаётся непрозрачным: клиент проверяет absolute isolated HTTP(S), отсутствие user/password, exact `/_soty/boot`, 43-символьный base64url ticket в fragment, запрет HTTPS→HTTP. Query не переписывается и не используется клиентом как return URL. Backend остаётся источником exact origin и прав; frontend проверка отличается от проверки registrable-site isolation на сервере.

`WorldAppOptions.openApp` сохраняет первый аргумент и получает необязательный второй с полным pinned launch request. Production использует API. Старый однопараметровый hook компилируется, но hook обязан возвращать настоящий изолированный boot URL; внешняя произвольная страница больше не считается запуском приложения.

## Независимая приёмка ещё требуется

1. Реальный named unlisted direct launch без `apps.list`, включая отказ и выбор другого аккаунта.
2. Mobile toolbar 320/390px, клавиатура/focus, iframe с denied/blocked-cookie сообщением, external action без popup loop.
3. Old-cookie A + blocked Set-Cookie B, sessionCheck echo, expired/replayed ticket и explicit public reset — совместно с server/runtime pages.
4. Смена аккаунта и уход назад при задержанном launch/popup, холодный offline путь и сохранённый hash после reconnect.
5. Старый community app route: разговор и приложение независимо авторизованы; поздняя загрузка контекста не перезагружает iframe.

Здесь не заявляются browser cookie compatibility, действующие DNS/TLS, Linux deployment, backup/restore или публичный выпуск.
