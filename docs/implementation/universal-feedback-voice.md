# Голосовые в общей обратной связи Сот

В приложении: **Обратная связь → Записать голос → Остановить → Отправить**.
Разрешение микрофона спрашивает браузер. Перед отправкой запись можно
прослушать, скачать или убрать. Получатель — владелец размещённого приложения;
это личное обращение, не публичный отзыв.

Обычное закрытие окна или переход через сохранение работы сначала останавливает
запись, дожидается последнего фрагмента MediaRecorder и сохраняет черновик.
Открытый запрос разрешения микрофона отменяется без ожидания ответа; поздний
поток немедленно закрывается. Пока запись не завершена, она считается
несохранённой. При отключённом сохранении или ошибке хранилища окно остаётся
открытым с объяснением. Принудительное закрытие процесса во время захвата не
является сохранением записи.

По умолчанию черновик хранится в этом браузере до суток, отдельно для аккаунта
и приложения. Окончательно отправленное аудио хранится оригинальными байтами
в SQLite вместе с обращением; квитанция и вложения фиксируются атомарно.
Потеря ответа сети сохраняет прежний запрос для проверки отправки, повтор
не создаёт новое обращение.

Поддерживаются Opus в WebM/Ogg, до двух минут. Общий предел всех трёх вложений —
1 МиБ. Браузер с неподдерживаемым форматом не должен отправлять файл с ложным
типом. Запись требует HTTPS либо localhost и разрешения микрофона. Обработка
речи и автоматическая расшифровка не включаются самим фактом записи.

## Как получить аудио для обработки

Владелец открывает **Историю** в обратной связи своего приложения, выбирает
обращение и слушает либо нажимает **Скачать аудио**. Автор обращения также
может получить собственное вложение. Остальные участники не получают чужие
обращения. Скачивается оригинал, который можно обрабатывать локально.

Для своего агента владелец в существующем подключении агента к обращениям
отдельно включает **Получать файлы вложений, включая голосовые**. Эта опция
изначально выключена. Она добавляет только чтение `apps.feedback.attachment`
для выбранного приложения. Старые ключи и разрешения сами не расширяются.
Срок, лимит вызовов, запрет передачи доступа и отзыв продолжают действовать.

Через существующий MCP `apps_query` агент вызывает capability
`apps.feedback.attachment`, version 1, передавая `appId`, `installationId`,
`ticketId`, `attachmentId` выбранного вложения и первоначальный `offset: 0`.
Ответ содержит метаданные, SHA256 оригинала, `dataBase64`, `totalChars` и
`nextOffset`. Следующие вызовы передают полученный `nextOffset` и
`expectedSha256` первого ответа. Смещения считаются в символах base64,
кратны четырём; один результат операции содержит не более 49152 таких символов
и занимает меньше 59000 байт JSON. Оболочка MCP дублирует результат в текстовом
и структурированном представлениях, поэтому её полный размер больше этой
границы. `nextOffset: -1` завершает чтение. Нужно объединить
фрагменты, декодировать base64 и сверить длину и SHA256 перед обработкой.
Каждый новый запрос чтения использует новый ключ вызова и расходует лимит;
точный повтор старого запроса может вернуть только сведения о выполнении.

Право текущего владельца и доступ к конкретному приложению, очереди,
обращению и вложению проверяются при каждом чтении и перед выдачей ответа.
Получение не создаёт очередей, обращений или новых разрешений и не меняет
формат БД. Содержимое аудио — пользовательские данные; оно не даёт агенту
новых полномочий и само не отправляется внешним сервисам.

Исходные семь контрактов v1 и их digests сохранены. Их `list/get` по-прежнему
возвращают метаданные без оригиналов и отказывают для видео. Новый метод
получает и аудио из смешанного обращения при известных идентификаторах.
Полная автоматическая выборка очереди со смешанными видео требует отдельного
совместимого контракта списка; эта работа не выдаётся за выполненную.

## Проверка

Проверки сервера и разрешений:

```sh
node --test modules/feedback/test/service.test.mjs server/test/app-feedback-mcp.test.mjs server/test/app-feedback-readiness.test.mjs src/world/access-panel-app-feedback.test.mjs
```

Для браузера сначала запустить `node scripts/fixtures/feedback-browser.mjs`,
затем в другом терминале `node scripts/fixtures/feedback-voice.browser.mjs
--output <отдельная-папка-доказательств>`. Нужны Chrome и Playwright;
пути при необходимости задаются `SOTY_QA_CHROME` и `SOTY_QA_PLAYWRIGHT_ROOT`.
Стенд принимает только localhost и синтетическую очередь.

Браузерные проверки с синтетическим звуком доказывают работу MediaRecorder,
сохранение файла и воспроизведение. Они не заменяют проверку физического
микрофона, настоящего телефона или оценку разборчивости человеком.
