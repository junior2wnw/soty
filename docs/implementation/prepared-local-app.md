# Подключение готового локального приложения

Человек подключает своё устройство к Сотам, запускает на нём проект, затем выбирает
«Создать → Приложение», устройство и папку проекта. Кнопка «Добавить и открыть»
создаёт личную карточку и открывает обычный экран приложения. Карточка доступна в
«Моём». Выбор адреса вручную остаётся доступен для других проектов.

На выбранном устройстве в разрешённой рабочей папке проекта находится
`.soty/app.json`. Пример:

```json
{"schema":"soty.local-app.v1","name":"Моё приложение","port":3000,"entryPath":"/"}
```

Порт должен отвечать на HTTP-запрос `HEAD` на `127.0.0.1` этого устройства.
Файл ограничен 4 КиБ, не должен содержать повторяющиеся или лишние поля; порт
должен быть в диапазоне 1024–65535 и не занимать порт коннектора. Агент может
подготовить файл и запустить проект, если человек поручил ему это. Подключение
не запускает и не перезапускает процесс, не изменяет DNS и не открывает проект
публично. Если устройство выключено или приложение остановлено, оно недоступно.

Проверка обнаруживает ответ адреса из манифеста, но не доказывает, что этот порт
принадлежит именно выбранной папке. Приложение, которому нужны личные данные и
единый вход, должно самостоятельно поддерживать проверенный вход Сот и хранить
данные раздельно для пользователей. Один манифест или подключение к коннектору
не делает произвольное приложение совместимым с этим входом.

Выбор папки идёт через текущее авторизованное соединение владельца и ограничен
разрешёнными корнями коннектора. Коннектор повторно проверяет путь и манифест до
регистрации; сервер повторно проверяет устройство и аккаунт. В журнале исходная
квитанция связывает владельца, исходное устройство, коннектор, относительный путь
и отпечаток манифеста с постоянным идентификатором карточки. После потери ответа
оболочка сначала читает эту квитанцию и карточку; повтор не создаёт вторую
карточку и не восстанавливает отозванную. Прежние коннекторы не выполняют этот
путь: их нужно обновить либо выбрать ручное подключение.

Если вкладка закрылась до завершения, карточка уже подтверждённого подключения
остаётся в «Моём». При незавершённом запросе его можно проверить в диалоге
подключения; это не фоновый запуск проекта. Локальный маркер защищает повтор на
исходном устройстве и не является общим межустройственным журналом интерфейса.

Другое действующее устройство того же владельца может через `apps.prepared.read`
проверить **точный исходный запрос**, если известны его requestId, устройство,
папка и отпечаток. Сервер сверяет их с неизменяемой записью и заново проверяет
владение выбранным компьютером. Исходное подписавшее устройство не подменяется;
чтение с другого устройства не продолжает feedback и не подтверждает его
готовность. Повторить создание под старым requestId с другого устройства нельзя:
новое явное подключение получает своё намерение. Общего списка таких запросов
для другого устройства пока нет; если исходные реквизиты неизвестны, выберите
проект заново и проверьте «Моё».

Если порт уже занят и точный результат нового запроса не подтверждён, интерфейс
предлагает проверить «Моё». При неподтверждённом результате, в том числе если
проверка недоступна, человек также может явно убрать ожидание **только из текущего
браузера**; номер показан для технической проверки исходного запроса, поиск по
одному номеру в интерфейсе пока не реализован. Это не удаляет
серверную квитанцию, не останавливает уже переданную попытку и не доказывает
существование карточки: ранее начатая попытка ещё может завершиться.
Автоматически связывать карточку с выбранной папкой по одному порту нельзя.

Если установка обратной связи временно недоступна, карточка всё равно открывается;
статус сообщает `feedback: waiting`. Повторное `apps.prepared.read` пробует
завершить её установку. Этот путь пока не обещает устойчивого фонового повтора
после закрытия браузера: подтверждённый интерфейс может очистить локальный маркер
раньше готовности обратной связи. Не считать эту часть завершённой без отдельной
проверки и механизма восстановления.
