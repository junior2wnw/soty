# P2-I: дополнительная проверка короткого экрана

30.09.2026. Root проверил обычную авторизованную оболочку из текущего primary worktree на существующем изолированном стенде `127.0.0.1:5420`. Настоящий IAB, viewport **667×375**; не physical phone, не mobile OS keyboard и не установленная PWA. Frontend source в этой проверке не менялся. Это дополнение к [независимой матрице](p2-independent-gate.md), не закрытие всей P2-I.

| Сценарий | Наблюдение |
|---|---|
| Записки: создать → ввести → уйти к списку → открыть → полная reload | Synthetic `QA · альбомный экран` и все три строки с точными newline сохранились; виден статус «Сохранено». Фактический `documentElement.scrollWidth=667`, `innerWidth=667` |
| Клавиатура в редакторе | Tab после body попадает на «Пункт списка»; scroll доводит действие до видимой области, footer остаётся доступным |
| Действия записки | Modal целиком помещается: rect x0/y53/w667/h322, последняя кнопка y310/h44. Все цвета/архив/корзина/export видны; ни одно действие удаления/отправки не выполнялось |
| Escape из действий | Dialog закрыт, focus возвращён на «Действия с запиской» |
| Доступы и действия | Панель загружается, новый OAuth client честно disabled. ArrowRight от «Клиенты» переводит selected tab и focus в «Действия», пустая история отображается. Горизонтального переполнения нет |
| Добавить → Приложение | Настоящая форма загружает подключённое QA устройство. Последовательные Tab проходят название/device/port/path/audience, последний submit прокручивается в rect y304.5/h44 внутри viewport375 |
| Modal focus cycle | Tab после submit возвращает focus на «Закрыть». Escape закрывает форму и возвращает focus на глобальное «Добавить». App не создавался, форма не отправлялась |

Визуальные captures просмотрены в tool output для редактора, Notes actions, Access и App form. Ранний capture непосредственно после input иногда отражал предыдущий кадр; вывод о сохранности взят из последующего DOM/value и повторной reload, не из такого кадра. Уменьшенный viewport после проверки сброшен. Synthetic note оставлена в QA аккаунте; имеющиеся application chat drafts не открывались и не отправлялись.

Отдельная попытка реального browser zoom: `Control+=` при 1280×800 оставила `innerWidth=1280`, DPR1 и visualViewport.scale1. Этот backend не применил увеличение. Уменьшение viewport не выдано за 200% browser zoom. Физическая клавиатура/телефон, screen reader, настоящий 200% zoom и полная негативная UI-матрица остаются открытыми условиями.
