## Изолированный стенд

Рабочая копия `soty-platform`, shell `127.0.0.1:5420`, Apps API `5421`, connector `58350`; данные прежнего браузерного стенда C1 в `var/p3-entry-browser/data`. После перезапуска база прочитана read-only: Apps schema4, один активный источник и одна сохранённая конфигурация. Два независимых loopback sample проекта: A `56322`, B `56323`.

Для connector фактические переменные — `SOTY_CONNECTOR_DATA_DIR`, `SOTY_CONNECTOR_SERVER_URL`, `SOTY_CONNECTOR_MANAGED`, `SOTY_CONNECTOR_AUTO_UPDATE`, `SOTY_AGENT_AUTO_UPDATE`. Короткие `DATA_DIR`/`SERVER_URL` этот процесс не читает. При первом перезапуске стенда эта ошибка обнаружена до приёмки: процесс остановлен, только созданный им конфиг удалён после проверки точного пути и времени создания. Новый запуск использует прежний отдельный QA connector-каталог и локальный сервер. Этот ошибочный запуск не считается доказательством подключения тестового устройства.

Браузерные действия выполняются через CUA, сведения берутся из видимого DOM. Cookies/токены/внутреннее состояние страницы не извлекаются. Сохранённые images показывают реальные экраны; dev-only fixture отдельно помечен синтетическим.

## Реальные результаты и исправленные находки

A56322 получил через собственный UI запись «Возврат к источнику A · C2». Обычное переключение на B56323 потребовало отдельного согласия с точным портом. После receipt inspection показал B и подтверждённый binding; оба alias остались включены, несохранённое название осталось в поле и не стало названием приложения. Старый iframe не пересоздавался автоматически, его прежний stream закрыт. Явное обновление открыло B с подключённым WebSocket и без контрольной записи A.

Возврат через историю выбрал версию1/A. После30секунд карточка осталась видима; новое согласие и отдельная кнопка «Перепроверить и переключить» привели к fresh prepare и принятому возврату. Явное обновление открыло A с подключённым WebSocket и прежней контрольной записью. Это проверка возврата конфигурации, не резервного копирования данных. Снимки `p3-source-expired-320.png` и `p3-source-return-320.png` просмотрены интегратором.

Несохранённая аудитория блокирует новую source-проверку. «Отменить правки доступа» с явным подтверждением вернула исходную аудиторию, сохранив отдельный черновик названия и порт56324. Проверка недоступного56324 показала понятную ошибку; активный источник56323 не изменился. Выход из собственного тестового черновика вернул фокус к кнопке настроек.

Browser выявил дефект, которого не было в первоначальных раздельных helper tests: render вызывал unchanged observe, отменявший in-flight history. Реальная история выглядела пустой и после повторного чтения. Независимые RED probes подтвердили причину; разделение автоматического обновления draft и явного reset восстановило загрузку при сохранении cancellation fence. После исправления actual browser сразу показал версии2 и1; manual refresh также сохранил строки.

Ещё две находки: после принятого source ACK оставался процессный текст о чтении текущего источника; после собственного возврата старая history page предлагала обновить только inspection. Обе исправлены. После принятого переключения и inspection виден конечный статус; открытая история перечитывается. Прямое обновление истории читает inspection и history без стирания черновика. Отказ чтения после ACK и его последующее восстановление отдельно проверены компонентным сценарием.

## Финальный проход

В двух настоящих окнах один аккаунт имел разное несохранённое состояние. Второе окно изменило аудиторию public→private. После обновления первого его порт56323 и название «Мой несохранённый ввод» остались; UI показал конфликт и запретил проверку устаревшего намерения. Явное принятие текущего источника заменило только source-ввод. Новая private A→B promotion прошла, сохранив название, а открытая история автоматически показала три конфигурации и текущую revision3 без ложного предупреждения. Данные стенда остались private; ни одно production-приложение не изменялось.

`app-source.test.html?run=1`: свежий запуск **10/10 PASS** в настоящем браузере. Внутри — настоящий mounted UI с synthetic API, а не сеть. Сценарии покрывают ввод/фокус, пропавшее устройство, истечение проверки, lost ACK/remount, обе retry-кнопки при подмене pending, auto/latest history, собственное переключение с открытой history, ACK+failed readback+refresh, поздний ответ после dispose. Прежний автоматический прогон, прерванный HMR, не принят как независимое доказательство; окончательный полный запуск выполнен после freeze.
