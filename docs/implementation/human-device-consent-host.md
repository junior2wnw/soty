# Общий вход: подключение сохранённого согласия к серверу Сот

Это Source-проверка, ещё не публичный выпуск. Реальная привязка прежнего HIVE
к прежнему профилю Сот выполнена отдельно; прежнее 24-часовое подтверждение
не превращается задним числом в согласие на запоминание.

`loadUniversalConfiguration` читает необязательные `deviceConsent` и
`renewalLimits` из существующего частного файла Human. Численные ограничения
передаются конструктору сервиса отдельно от профиля и проверяются до открытия
хранилищ. По умолчанию согласие и миграция выключены, прежние пределы сохранены.
Миграция Human2 → Human3 разрешается только явным host-флагом
`SOTY_HUMAN_DEVICE_CONSENT_MIGRATION=1`. Входящие HTTP/RPC его не принимают.

Измерение готовности публикует только включение и digest/число допустимых
клиентов. Ключи, токены, сохранённые согласия и частные данные туда не попадают.
Probe независимо проверяет 38 объектов Human3 и точный layout
`b3fa2360e7db5e44af0fb7f0716ecbb9c6e43793a9771574a73db30c01a3afb9`.
План миграции, даже без блока `deviceConsent`, требует reader3 у кандидата
и запасного образа. Прежние reader1/2 не допускаются к Human3.

Приёмка Linux Node24.15: 89/89, без пропусков; типизация проходит.
Настоящий host factory остаётся на Human2 с прежней конфигурацией, отказывает
во включении без миграции, затем мигрирует и холодно открывает Human3 с прежней
конфигурацией без согласия. Непрозрачные cipher bytes, consumed flag и прежние
абсолютные сроки токенов сохраняются. Отдельный literal SQL-вектор и старый
reader2 проверяют несовместимость независимо от нового writer.

Для выпуска нужны свежая зашифрованная копия после реальной привязки HIVE,
проверенное восстановление и совместимый reader3 с выключенным согласием.
Штатный policy `features` требует compiled legacy baseline. После миграции
прежний образ ae с reader1/2 больше не является вариантом отката.
Автоматический вход и явный выход из двух RP HIVE проверяются отдельно
на естественном HTTPS-пути; локальные тесты этого результата не заменяют.
