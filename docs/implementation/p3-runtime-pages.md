# P3-B3 — страницы входа и восстановления

2026-09-30. Авторская область: только `modules/apps/server/runtime-pages.mjs`, `modules/apps/test/runtime-pages.test.mjs` и этот документ. HTTP/CSP/session nonce, прямые ссылки и браузерная приёмка интегрируются root; панель приложения — отдельная область.

## Интерфейс

```js
renderBootPage({ shellUrl, publicResetPath?, nonce? }) // полноценный HTML string
renderStatusPage({ error, shellUrl?, publicResetPath?, nonce? }) // HTML string
```

Root передаёт URL уже проверенной оболочки с нужным app/domain/path. Renderer дополнительно допускает только абсолютный HTTP(S) URL без userinfo, обратных слешей, пробелов и управляющих символов. Он не знает список доверенных origins и не заменяет серверную проверку принадлежности shell URL.

`publicResetPath` допускается только после свежего серверного разрешения anonymous входа. Renderer принимает локальный navigation target и сохраняет прежние hash-SPA пути, например `/#/dashboard`: fragment передаётся только браузерной навигации. Проверяются origin, encoded slash/control/backslash и две нормализованные проекции — декодированный URL pathname и декодированный исходный префикс до `?`. Обе должны исключать `//` и зарезервированный `/_soty` namespace. Поэтому `/x/..//double`, `/%2F_soty/session`, `/x%2f..%2f_soty/session` и несовпадающие encoded-dot/fragment интерпретации отказывают. Допустимый исходный path/query/fragment сохраняется без пересборки; encoded `%23` в query разрешён. Renderer не строит переход из текста ошибки. Успешный boot использует исключительно `entryPath` из серверного ответа, а не recovery query в исходном URL.

Root всегда генерирует новый `nonce = randomBytes(16).toString('base64')` и передаёт его renderer. Валидируется canonical base64 16 байт; единственный script получает escaped nonce attribute. Для страницы требуются соответствующий `script-src 'nonce-…'`, `connect-src 'self'`, inline styles и прежний sandbox без top-navigation/popups. Без параметра nonce renderer удобен для изолированных тестов; production CSP остаётся обязанностью caller.

## Состояния и действия

Boot синхронно читает ticket и удаляет fragment через `history.replaceState` до DOM работы и любого fetch. При сбое очистки или неверном формате ticket запросов нет. Затем один POST `/_soty/session` с `{ticket}`. Ответ обязан содержать `{ok:true,entryPath,sessionCheck}`; nonce проверки — base64url 43 символа. После него GET того же URL с `X-Soty-Boot-Check:sessionCheck`; только `{ok:true,sessionCheck:тот_же}` подтверждает точную новую cookie и позволяет `location.replace(entryPath)`.

POST не повторяется автоматически. Успешный POST, bare GET и `iframe.load` не считаются подтверждением входа. Текст после подтверждения — «Открываем приложение», а не обещание, что приложение автора уже загрузилось.

Все fetch используют `credentials:'same-origin'`, `cache:'no-store'`, `redirect:'error'`, AbortController и timeout 10 секунд на запрос, включая чтение JSON. Технические response codes не выводятся: известные ошибки превращаются в короткие состояния доступа, отсутствующего устройства, нагрузки или недоступного адреса; неизвестные HTTP ошибки отличаются от сетевого сбоя без раскрытия деталей.

В отдельной странице действие «Открыть через Соты» получает новый допуск через проверенный shell URL. Во встроенной странице anchor не получает href, top-navigation и popups не используются; видна инструкция «Откройте отдельно кнопкой над приложением». Ложной кнопки reload/«Повторить» для использованного ticket нет.

Если сервер разрешил публичное восстановление, `app_access_changed` означает «Доступ изменился» / «Откройте приложение заново.», а не окончательно закрытый доступ. Одинаковая формулировка используется при исходной странице статуса и при ошибке проверки нового входа. Она сама не сбрасывает cookie и не выполняет новый вход.

Публичное восстановление — только явная кнопка «Продолжить без входа», один DELETE `/_soty/session`, затем одна замена URL на проверенный локальный путь после `{ok:true}`. Двойное нажатие не создаёт второй запрос. Ошибка оставляет ручное восстановление; автоматического удаления cookie либо fallback в anonymous нет. Browser Origin для DELETE формирует браузер, проверяет сервер.

При `pagehide` запросы прерываются; поколение состояния блокирует поздние callbacks и переходы. После BFCache restore использованный boot не повторяется. Старый callback не может снять блокировку нового ручного действия.

## Внешний вид

Общие `modules/ui/palette.mjs` и `modules/ui/hex.mjs` дают палитру нейтрального графита и геометрию регулярных закруглённых сот. Цвета и формула не скопированы. Страница автономна: внешние изображения, fonts, scripts и CDNs не загружаются. Шрифт использует Manrope, если он доступен, затем системный fallback.

Один смысловой заголовок, короткое пояснение, не более двух применимых действий. SVG сохраняет viewBox/aspect ratio. Кнопки имеют минимум 46px (44px в компактном iframe), видимый keyboard focus; живой статус сообщает результат. Есть узкая компоновка для 320px, отдельная короткая landscape-компоновка и отключение анимации при reduced motion. Проверка `window.top === window.self` задаёт локальный признак встроенной страницы: повторный бренд внутри iframe скрыт. При высоте iframe до 280px и ширине от 480px карточка убирает декоративную подпись и сокращает геометрию/отступы; смысловой статус, действие восстановления и инструкция над приложением остаются видимыми. Прокрутка не блокируется. Фактическое измерение overflow, браузерный CSP и внешний вид проверяет root на общем стенде.
