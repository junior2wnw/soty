# Упрощение Сот: подключать существующее, завершать пользовательские сценарии

Решение после совместного разбора с GPT-6 Astra, 10 октября 2026 года. Все R01–R22 из общей матрицы требований сохраняются. Первый пилот использует наши приложения; контракт сразу пригоден для внешнего автора.

## Основа

Соты дают поле, каталог, общий человеческий вход, запуск и обнаружение инструментов. Каждое приложение сохраняет собственные данные, права, API и рабочие процессы. Подключение проходит через существующий Source SDK и адаптер к родным операциям. Для нового проекта не создаём заново авторизацию, очередь, агентский рантайм и распознавание.

Частная обратная связь и публичные отзывы — разные сценарии. Обращение видят автор и разрешённая поддержка проекта. Публичные отзывы используют действующий backend Поведай с привязкой к приложению, проекту или человеку. Отправка обращения не разрешает публикацию отзыва.

Агент получает существующие MCP/HTTP-инструменты только в текущем контексте пользователя и проекта. Наличие карточки приложения или описания инструмента не даёт право действия. Ответ агента сначала становится черновиком; отправку или изменение подтверждает человек по правилам приложения.

## Что завершено в текущем коде

В универсальном ordinary Source появилась вкладка «Обращения» на существующем `createSourceFeedbackClient`: список, полный диалог, изображение и аудио, ответ, передача на проверку, подтверждение исправления автором. Серверные `canReply/canManage/canAccept`, revision и квитанции переиспользованы. Новых таблиц, прав или процессоров для этого нет.

Длинная очередь выдаёт короткие карточки с курсором и лимитом ответа; полный текст и вложения открываются отдельно. Потерянное подтверждение сохраняет прежнее намерение и request ID. Смена binding и отказ доступа очищают видимые частные данные. После подтверждённой записи загрузка вложений остаётся чтением: её сбой не повторяет запись.

Локальная проверка: 17 тестов, проверка деклараций типов, сборка Source пакета и браузерный цикл на учебной Native SQL базе. В браузере проверены две учебные роли и ширины 1280/390/320. Это не приёмка настоящего общего входа, рабочего агента или публичного выпуска.

## Следующий законченный сценарий

1. Подключить одно действующее приложение штатным Source SDK: открыть из Сот, войти своим профилем, выполнить родное действие, вернуться с сохранением поля и поиска. Другой пользователь должен получить свои реальные права.
2. Пройти обращение с текстом, записью и снимком до ответа и подтверждения автора. Общий компонент интерфейса используется повторно; очередь остаётся у владельца проекта. Для ЭкоЛаб и HIVE используем существующие очереди и API.
3. Подключить существующего агента к этой очереди: прочитать разрешённое обращение, сохранить черновик, дать владельцу проверить и отправить. Распознавание подключается через существующий локальный процессор или согласованный сервис ЭкоЛаб. При его сбое исходное обращение и материалы сохраняются.
4. Повторить тот же контракт для всех приложений и внешнего автора. Затем проверить звонки, устройства, локальный исполнитель, GLM/Гонку, Transit, расчёты, производительность и восстановление согласно R01–R22.

## Что убираем из критического пути

Повторное изготовление экспериментальных cold-run контроллеров, собственный syscall observer для ASR и новые версии диагностической обвязки не являются условиями для списка обращений, ответа, просмотра или общего Source подключения. Их прошлые журналы сохраняются как история, прежние отказы не превращаются в успешные проверки.

Сохраняем действующие проверки доступа, согласия, ограничения, квитанции, отмену, данные и резервные копии. Истёкшие локальные QA права не продлеваются автоматически. Публикация следует после общей пользовательской приёмки и проверки восстановления, а не после одного теста или Source review.
