# P3-C2-C — интерфейс переключения источника

Авторская область: `src/world/app-settings.ts` и `src/world/app-settings.css`. Состояние и durable dispatcher принадлежат отдельному автору; серверная модель, источник данных, права и транспорт не заменены логикой интерфейса. Основание — `p3-source-settings.md` и C2-B `5a4cb1d`.

## Что видит владелец

Раздел «Источник» показывает текущие устройство, порт, страницу и отдельно состояние привязки маршрута. Раскрытие «Изменить источник» содержит нативные поля устройства, порта, страницы и доступа после переключения. Список устройств читается через настоящий `apps.devices`; исчезнувшее выбранное устройство остаётся явно недоступным и не заменяется соседним.

Обычный путь: изменить поля → «Проверить» → прочитать конкретный отвечающий источник → «Переключить». Для публичного источника перед переключением необходимо отдельное согласие открыть весь проект на показанном устройстве и порту, включая страницы и API. Ввод в форме и Enter запускают только проверку. HTTP-ответ не объявляется доказательством исправности всего приложения.

После истечения проверки карточка остаётся читаемой. Согласие можно дать без ограничения времени на чтение. Кнопка явно меняется на «Перепроверить и переключить»: helper получает новый ответ и возвращает intent только при точном совпадении просмотренных настроек. Сам интерфейс отправляет этот intent через прежний dispatcher. Изменившийся результат требует нового просмотра; обычная повторная проверка никогда не переключает источник. Если срок истёк между показом обычной кнопки и нажатием, действие ограничивается обновлением кнопки, а не скрытым переходом к совмещённой операции.

«Предыдущие источники» загружаются отдельными страницами до 20 конфигураций. Выбор возвращает конфигурацию в ту же форму и требует новой проверки. Текущая версия не предлагается как новое переключение. После принятого переключения и успешного inspection открытая история перечитывается отдельным запросом; ошибка этого чтения остаётся ошибкой истории и не отменяет receipt. Устаревшая история предлагает прямое «Обновить историю»: inspection → history без сброса черновика или переноса его CAS. Закрытая устаревшая история обновляется при следующем раскрытии. Этот список не обещает перенос или откат данных проекта.

## Сохранность ввода и точность действий

- Формы, раскрытия, согласие и кнопки создаются один раз. Обновление наблюдения, счётчик и inspection меняют свойства узлов на месте. Строки истории и варианты устройств имеют устойчивые ключи; пара устройства и коннектора использует существующий `deviceKey`.
- Source draft участвует в существующих Back/Escape/beforeunload guards. Он остаётся в памяти; интерфейс не называет неотправленный ввод сохранённым на сервере.
- Несохранённые аудитория и активные адреса блокируют новую проверку/переключение. Отдельная отмена этих правок сохраняет название, группы и новый slug. Обычные черновики не подмешиваются в source intent и не очищаются его ACK.
- Pending source intent хранится в прежнем account/app-scoped слоте. Повтор не требует нового proof и не зависит от несохранённого C1 draft. Оба обработчика повтора захватывают именно последний показанный pending до нового render; helper проверяет его точное совпадение под Web Lock. Заменённый другой вкладкой intent нельзя отправить под прежней подписью кнопки.
- Проверка, история и inventory имеют fences для поздних ответов. Скрытие страницы, закрытие раскрытия, редактирование и dispose инвалидируют эфемерную подготовку. В новом аккаунте не отображаются поздние результаты предыдущего окна.
- Серверный receipt подтверждает конкретный исторический запрос. После ACK интерфейс отдельно читает актуальный inspection. Успешная смена источника не пересоздаёт работающий iframe; новый запуск остаётся явным действием пользователя.
- После успешного чтения оба сообщения завершаются коротким «Переключение подтверждено»; replay остаётся явно историческим. Если receipt принят, но inspection не загрузился, сообщение отдельно подтверждает переключение и сообщает, что текущий источник не удалось проверить. Первый последующий успешный inspection, в том числе ручное обновление, завершает это состояние. До него хранится только сообщение в памяти, без записи процессного состояния на диск. Это не возвращает уже подтверждённый запрос в pending.

## Вид и доступность

Сохранены нейтральные общие токены, стандартный диалог и размеры активных областей от 44 px. На узком экране порт/путь складываются вертикально, длинные адреса переносятся; после проверки клавиатура проходит через согласие к переключению. Кнопки с `aria-disabled` сохраняют место в клавиатурной последовательности, capture guard блокирует действие. Изменение состояния объявляется через status, ежесекундный счётчик — нет. Таймер не создаётся для уже истёкшей проверки.

Это реализация конкретных механизмов доступности, а не заявление полного соответствия WCAG или проверки всех вспомогательных технологий.

## Проверки и оставшиеся границы

На срезе после обязательного exact-pending fence выполнены `npm run typecheck` — PASS и `node --test src/world/app-source-state.test.mjs src/world/app-settings-state.test.mjs` — **39/39 PASS**. Это повтор чужих авторских тестов состояния и проверка типов интерфейса, а не самостоятельная проверка DOM в браузере. `git diff --check` для двух файлов интерфейса — PASS. Полный build и настоящий браузер ведёт root отдельно, чтобы общий стенд и viewport не менялись параллельно.

Root сообщил настоящий предварительный опыт на desktop 1280×800 и 320×760: источник B прошёл проверку без изменения активного A; публичное переключение было недоступно без согласия; поля и кнопки помещались по ширине, Tab после проверки переходил к согласию. Скриншот: `output/implementation-20260930/p3-source-settings-320-preflight.png`. Это предварительная проверка до финального совмещённого действия и exact-pending исправления; её нельзя считать финальной приёмкой этих веток.

Позже root подтвердил реальное переключение A→B: текущий порт 56323, binding `bound`, черновик названия сохранён, aliases активны. Обнаруженное при этом незавершающееся «Читаем текущий источник» исправлено в авторском обработчике завершения; повторная проверка текста в браузере остаётся отдельной от исходного опыта.

При повторном открытии root обнаружил пустую историю. Read-only воспроизведение на настоящем `createAppSourceState` установило причину: промежуточный render вызывал обычный clean `observe`, а тот использовал explicit reset и инвалидировал начатое чтение истории. Автор состояния разделил автоматическое обновление черновика и явный сброс. Повтор того же probe после исправления: чтение без обновления — `accepted`, 1 строка; чтение с неизменившимся `observe` — `accepted`, 1 строка; чтение с явным `reset` — `stale`, 0 строк. Проверка типов после этого — PASS. UI wiring не обходил state и не подставлял фиктивные строки; actual component/browser повтор истории остаётся независимым gate.

Последующий root browser опыт подтвердил возврат B→A через истёкшую проверку и явное «Перепроверить и переключить». Он выявил устаревшую открытую историю и нерабочую рекомендацию обновить только inspection. Прямое чтение истории исправлено в согласованной UI области. Финальный source freeze: `app-settings.ts` SHA256 `4c5e89349568a5ec417b1e3428f16c56eaa62eaeb151272d7da5b6e5d82c9893`; typecheck и diff-check — PASS. Независимый повтор новой action/readback ветки не приписывается этой проверке типов.

Независимый synthetic component fixture, реальный A→B→A с HTTP/WS и финальная геометрия принадлежат отдельным приёмкам. Production, физический телефон и полноценное исследование со скринридером здесь не проверялись.
