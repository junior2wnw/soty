# Адреса приложений в Сотах

Актуальная схема с 5 октября 2026: **https://<имя>.4-2.рф**
(ASCII: https://<имя>.4-2.xn--p1ai). Прежняя зона соты.online сохранена явно;
NFC продолжает работать на https://nfc.xn--n1afe0b.online.
Отдельный зарегистрированный домен на каждое приложение не нужен.

Повторяемый процесс, команды, режим с собственной авторизацией и проверки:
[app-release.md](app-release.md). Карта действующей площадки:
[platform-current.md](platform-current.md).

NFC опубликовано в общем списке через обычный процесс Сот; [проверки выпуска](nfc-studio-release.md). В контрольных управляемых браузерах отдельная страница этого кириллического домена вызывает защитное предупреждение об адресе; встроенная страница работает. Проверка обычного Android остаётся необходимой. DNS и действительный TLS-сертификат сами по себе не исключают браузерную проверку похожих адресов; нельзя отключать защиту или считать HTTP 200 доказательством полного пользовательского сценария.

## Как разместить проект

1. Запустить HTTP-приложение на loopback-порту устройства с коннектором. Для NFC на SSH dev это 127.0.0.1:5318.
2. В Сотах выбрать «Подключить устройство». Для удалённого сервера выбрать «Подключить сервер по SSH», создать локальный SSH-туннель к его коннектору и указать порт туннеля. Это одноразовое подключение владельца; работа приложения затем идёт через исходящее соединение серверного коннектора и не зависит от SSH-туннеля.
3. «Добавить проект»: выбрать устройство, название, порт и начальную страницу. В начале проект доступен владельцу.
4. В настройках приложения открыть «Добавить адрес», проверить и закрепить имя, например nfc.
5. Отметить адрес, выбрать «Все по ссылке», при необходимости включить «Показывать всем в разделе приложений Сот», подтвердить раскрытие содержимого порта и сохранить доступ. Настройки применяются явной командой с проверкой актуальной версии источника.

Если браузер не разрешает обращение к локальному туннелю, в форме сервера есть «Подключить по файлу». Файл выдаёт действующий серверный коннектор; срок — 5 минут. Он содержит одноразовый код, поэтому его нельзя публиковать, коммитить или отправлять посторонним. В Сотах файл принимается только для точного текущего origin; подпись владельца и обычный серверный apps.claim остаются обязательны.

На сервере с Node 24:

```sh
node scripts/export-device-link.mjs --origin https://4-2.xn--p1ai --connector http://127.0.0.1:49427 --output /private/soty-device-link.json
```

Передать файл на компьютер по SSH и выбрать его в Сотах. После подключения удалить обе временные копии. Коннектор и приложение продолжают работать через исходящее соединение независимо от туннеля.

## DNS, TLS и маршрутизация

Для действующей зоны нужна wildcard A-запись **\* → TLS edge**. Адрес edge
определить из свежей конфигурации (на этой площадке 95.105.28.201).
Явные root/id/www/native записи и wildcard прежней зоны сохраняются.
DNS сам по себе не публикует приложение: неизвестные и вложенные имена не
попадают в основной сайт, API аккаунтов или коннектор.

Caddy обслуживает wildcard текущей зоны и прежний https://*.xn--n1afe0b.online,
передавая Host без замены в Soty gateway на loopback 18182. Точный native host
имеет отдельный проверенный route. On-demand TLS разрешается только для
зарегистрированных имён через /api/apps/tls-allow. Каждый адрес закреплён в
реестре; публичный runtime открывается после публикации.

Профиль **shell-subdomains-v1** задаётся оператором в /run/connect-releases/soty-app-hosting.json:

```json
{
  "schema": "soty.app-hosting.v1",
  "domainProfile": "shell-subdomains-v1",
  "namedAppZone": "https://4-2.xn--p1ai",
  "discoveryOrigin": "https://soty.pochinit.online",
  "retainedNamedAppZones": ["https://xn--n1afe0b.online"]
}
```

Это файл несекретных настроек. Отсутствие файла сохраняет прежнюю конфигурацию; переменные SOTY_NAMED_APP_ZONE и SOTY_DISCOVERY_ORIGIN при явном задании имеют приоритет. Ошибочный файл останавливает запуск до открытия хранилищ.

Основной origin допускается ровно как корень именованной зоны. Его дочерние имена обслуживает только реестр приложений. Дополнительный доверенный сайт внутри этой зоны запрещён. Профиль по умолчанию separate-site сохраняет прежнее требование отдельного registrable site; выбранная схема поддоменов является отдельным явным профилем.

Поддомены являются разными origins, но одним site. Защита аккаунтов не должна опираться на SameSite: HTTPS cookies имеют префикс __Host-, Path=/ и не имеют Domain; Connect проверяет подписи и точный Origin. На приложениях сохраняются CSP, sandbox, запрет обращения к другим origins, Origin-Agent-Cluster, фильтрация заголовков runtime и проверка актуального доступа. Недоверенные приложения не получают секреты основного сайта. Повышение возможностей sandbox требует отдельного изменения, NFC получает доступ только в верхнем окне.

## Развёртывание и возврат

При первом введении нового профиля/зоны сначала выпускается совместимый код,
затем меняется hosting-файл с явным сохранением прежних зон. Эта площадка уже
прошла переход: для новой карточки не нужно повторять два rollout.
Возврат использует совместимый выпуск, умеющий читать текущий реестр и обе зоны.
Каждый выпуск платформы проходит storage guard и не допускает двух писателей.

Публичный каталог /api/apps/catalog содержит только приложения с listed=true, доступом anyone и действующим включённым именным адресом. Приватные устройства, порты и connector IDs в нём не раскрываются. Снятие публикации или закрытие адреса убирает карточку и блокирует новые открытия.
