## Исправление после проверки на Android

Пользователь сообщил об успешном чтении на своём телефоне и предоставил снимок отказа записи `NotAllowedError`. Через USB подтверждены Samsung SM-G991B, Android 15, включённый NFC и разблокированный экран. Содержимое меток не выгружалось в серверные журналы. По [спецификации Web NFC](https://w3c-cg.github.io/web-nfc/) занятая метка при `overwrite: false` вызывает тот же тип ошибки, что и отказ в разрешении. Прежняя реализация защищала занятые метки, но скрывала разрешение замены в настройках и показывала эту ситуацию как общую ошибку телефона.

Теперь на Android рядом с главным действием видна «Перезаписать метку». Подтверждение показывает новые данные и предупреждает об исчезновении прежнего содержимого. Только «Заменить и записать» запускает `write(..., {overwrite: true})` непосредственно из клика; этот выбор не переносится на следующую обычную запись. При отказе обычной записи текущий статус Permissions API отличает уже разрешённый NFC от запрета доступа. Неизвестное разрешение сохраняет неопределённость причины. Занятая метка предлагает подтверждённую замену; отказ подтверждённой перезаписи не запускает повторные записи автоматически. Запись и её проверка чтением остаются разными результатами.

Полосы на мобильном экране устраняются сбросом встроенного ограничения `dialog` по ширине и высоте, фиксацией к краям окна и использованием `100dvh`. На 320×568 и 390×844 диалог измерен как `[0, 0, ширина окна, высота окна]`; горизонтальной и вертикальной прокрутки содержимого нет, обе кнопки видны. На 640×360 предусмотрена компоновка в две колонки: обе кнопки также видны без прокрутки. Подтверждение замены проверено через настоящий браузер. Визуальная локальная fixture использует функции рендера из приложения, без NFC Reader; снимки `output/nfc/overwrite-dialog-390.jpg` и `output/nfc/overwrite-confirm-390.jpg` подтверждают интерфейс, а не физическую запись.
