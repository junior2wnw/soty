# Изолированный Native Vault в dev

Обычный `node scripts/dev.mjs` сохраняет прежние форматы новых хранилищ:
Notes 1, Materials 1, Vault 1. Наследованная переменная
`SOTY_NATIVE_VAULT_ENABLED=1` не включает миграцию.

Явное включение:

```powershell
node scripts/dev.mjs --native-vault --named-apps --port 5194 --api-port 5195 --connector-port 49437 --data-dir D:\synthetic-native-data
```

Для программного запуска передайте `startDevelopment({nativeVault: true, ...})`.
Разрешены только boolean и отсутствие значения. Строки, числа и `null`
отклоняются до чтения пути данных и создания процессов. По умолчанию значение
`false`; CLI не читает для него переменные окружения.

Флаг передаёт в дочерний Root `SOTY_NATIVE_VAULT_ENABLED=1`; обычный запуск
явно передаёт `0`. Root использует один boolean для Notes `allowVaultMigration`,
Materials `allowVaultMigration` и Vault `allowFormat2Migration`. При явном
включении физические SQLite форматы — соответственно 3, 2, 2. Это разрешает
Native conversion; само включение не шифрует все существующие объекты.

Используйте отдельный синтетический DATA. Миграция хранилищ не означает
готовность production-релиза; перед миграцией существующих данных необходимо
остановить старые binaries и клиентов и отдельно проверить всех читателей.
Возврат флага в `false` не откатывает уже созданный формат. Текущий читатель
принимает известные форматы 3/2/2, но прежний binary может их отвергнуть.
При повторном запуске того же DATA сохраняйте прежние API origin/порт и
настройку `--named-apps`: Apps хранит точный origin template.

Dev передаёт Root только платформенные переменные и явно построенные локальные
настройки. Производственные credentials, `NODE_OPTIONS` и унаследованный
`DATA_DIR` не передаются. Уже существующий отдельный opt-in провайдера через
`SOTY_DEV_GONKA_*` остаётся без изменений; для проверочного запуска эти
переменные также следует исключить. Connector port — подсказка для отдельного
коннектора, сам коннектор dev не запускает.

Проверка на Node 24.22.1:

```powershell
node --test --test-concurrency=1 scripts/dev-native-vault.test.mjs scripts/dev.test.mjs scripts/dev-lifecycle.test.mjs
```

Новые проверки читают физические версии, lineage и схему SQLite реального
дочернего Root, повторно открывают DATA, проверяют неизменность неподдерживаемого
хранилища при отказе и освобождение обоих слушающих портов. Неизвестные версии
и дополнительные таблицы отвергаются. Browser encryption/reload и физический
Android требуют собственной проверки; ответ `/health` их не подтверждает.
