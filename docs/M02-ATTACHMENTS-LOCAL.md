## F3: атомарная отмена относительно отправки из другой вкладки

При победе cancel claim видит non-ready row и отказывает `attachment_queue_changed` до сетевой отправки. Локальный объект меняется только после commit; обычный update по-прежнему не может вернуть cancel-pending в ready или восстановить удалённую row. ## Исправление принятой отправки с неизвестным результатом

F1: редактируемый draft отделён от immutable pending attachment intent. До RPC его точные clientId/text/replyTo/ordered refs фиксируются одной IDB-транзакцией. При неизвестном результате повторяетcя только этот intent; изменения текста, ответа и новые файлы остаются следующим черновиком. UI прямо сообщает об этом и предлагает «Уточнить прежнюю отправку». Принятые refs снимаются из draft независимо от новых изменений; сами изменения не стираются. До уточнения результата исходные refs нельзя отправить на cancel, поскольку сервер уже мог их опубликовать. Серверные запреты published-ref reuse/cancel не ослаблены.

F2: durable accepted receipt и удаление только его refs объединены одной IDB-транзакцией. Закрытый экземпляр может завершить очистку своего scope; узкая queue invalidation обновляет живые экземпляры этого scope и другие вкладки через BroadcastChannel. В IDB snapshot rows+message читаются атомарно, повторное чтение после commit не может удовлетвориться старым in-flight snapshot. CAS update не создаёт заново уже удалённую строку. Перед любой публикацией claimMessage независимо перечитывает marker и ready refs внутри одной readwrite-транзакции: broadcast служит уведомлением, не заменяет guard. Marker использует отдельный `$message:` key существующего browser store; новая версия IDB/World wire не вводится. Никакого общего event framework нет.

## Что реализовано

`modules/world/server/attachments.mjs` даёт отдельные actor-bound операции capabilities / begin / chunk / complete / status / read / cancel. У каждой проверки текущий Connect actor, expectedAccountId, активное участие и точное сообщество. Опубликованный файл доступен текущим участникам; чужой незавершённый файл, угаданный ID, чужой чат и отозванное участие не дают байты. Права проверяются заново для каждого чанка. Вложение нельзя перепривязать к другой записи или воскресить после удаления.

Данные хранятся SQLite BLOB-чанками по 256000 байт. Начальная транзакция резервирует квоту до передачи байтов. Каждый чанк имеет размер, индекс и SHA-256; повтор принимает только те же байты. Complete проверяет полную упорядоченную последовательность и manifest digest, вычисляет потоковый file digest. Только затем явная отправка сообщения атомарно публикует до 10 готовых refs. Caption/reply/ordered refs входят в идемпотентный intent. Оборванный ACK не создаёт второе сообщение. Cancel требует отдельного подтверждения; опубликованные refs не очищаются по TTL. Удаление сообщения удаляет его чанки и оставляет tombstone.

`src/world/attachment-outbox.mjs` сохраняет Blob и метаданные в одной IndexedDB-транзакции перед сетью. AddBatch распределяет уникальные последовательные порядковые номера внутри этой же транзакции по текущему max, а не по времени или случайному ID. Reload сортирует по сохранённому порядку; старые строки только этого ещё не выпущенного локального пилота восстанавливают порядок по сохранённому draft. Есть одна передача чанка за раз; source читается slice-частями, без whole-file ArrayBuffer. Ошибка остаётся до явного retry. Переключение аккаунта/чата отсекает поздний ACK. Очистка принятой очереди атомарна.

Composer поддерживает выбор нескольких файлов, карточки очереди, прогресс, retry/cancel, необязательную подпись, вложения без текста и drag/drop. Вкладка не публикует очередь автоматически. File refs/clientId находятся в отдельном v2 draft; старый v1 tab не может стереть новый intent. На desktop Enter отправляет, Shift+Enter переносит строку; в coarse-pointer режиме Enter переносит, явная кнопка отправляет, Ctrl/Cmd+Enter тоже доступен. IME keydown защищён. Composer/remove targets измерены как 44 × 44 CSS px. Drag/drop реализован, но отдельный настоящий OS drag gesture в этом прогоне не выполнялся.

Получатель скачивает файл через подписанные RPC status/read, проверяет каждый чанк и ordered manifest, затем получает локальный octet-stream Blob с безопасным именем. Blob URL отзывается. HTML/SVG не встраиваются как активное содержимое. Отдельный публичный file URL, bearer URL или binary HTTP endpoint не добавлен: проверка filename/Content-Disposition foundation не означает, что здесь внедрён такой endpoint. Legacy roomAuth/E2E transport не переиспользован и не изменён; этот World actor slice не заявляет E2E-шифрование серверных SQLite BLOB.

Рабочий путь при проблеме — сохранить reader4, выключить writer; возврат к предмиграционному encrypted snapshot требует отдельной квалификации и решения о принятых после snapshot данных. Down-migration или автоматическая замена данных не реализованы.
