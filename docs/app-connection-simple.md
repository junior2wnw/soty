# Приложение в Сотах: единый вход и работа агента

Целевой сценарий ниже ещё не полностью доступен: в исходниках встроенный relay
привязывает общий вход к окну, но требует совместимых Root, оболочки, коннектора
и SDK. Их наличие и фактический запуск нужно проверять в конкретном развёртывании;
старый SDK и отдельная вкладка пока не поддерживают этот вход. Прежний прототип Root с общим cookie мог подменять аккаунт между окнами;
старую реализацию нельзя считать безопасной альтернативой.

Уточнение пользователя от 13 октября 2026 года. Соты — личное пространство и общие
сервисы. Существующие приложения предоставляют свои готовые функции. OTsov создаёт
новые приложения по задаче человека. Работающий совместимый интерфейс можно подключить
без полной переделки; общий вход и личные данные требуют поддержки приложением.

## Сценарий человека

Человек открывает Соты и сразу получает личный аккаунт. Добавляет нужные приложения,
включает их виджеты по желанию и разрешает своему агенту пользоваться нужными
приложениями. Агент узнаёт назначение приложения и доступные инструменты, выполняет
предметные задачи в аккаунте этого человека. Положение поля, агента и виджетов
восстанавливается при следующем входе. С другого устройства человек переносит этот
же аккаунт существующим QR/device-механизмом.

Запрос «сделай мне приложение» направляется в OTsov. OTsov принимает обычный код,
сохраняет отдельный проект и показывает результат. Затем готовое приложение
подключается к Сотам тем же путём, что приложение внешнего автора. Планировщик,
Периметрика, Отзывы и другие сервисы используются своими готовыми инструментами.

## Что предоставляет автор приложения

1. Название, назначение и действующий URL на выбранном автором сервере.
2. Подключение к существующему входу Сот. Сервер получает проверенную идентичность
   человека и ограничивает его данные; общий вход не означает общий аккаунт на всех.
   Для существующих аккаунтов сохраняются данные и штатная привязка профилей.
3. Имеющийся MCP и его справку. При наличии API вместо MCP достаточно опубликованной
   схемы и короткого skill. При работе через интерфейс используется подключённый
   браузерный исполнитель. Текст инструкции сам по себе не подключает исполнитель.
4. Частную обратную связь проекта и её очередь владельца. Текст, аудио и снимки
   остаются привязаны к нужному проекту; агент разбирает обращения доступными
   инструментами. Публичные отзывы подключаются отдельным сервисом Отзывы.
5. Необязательный компактный виджет. Человек сам включает его, перемещает и скрывает.

Соты должны показывать эти возможности при подключении приложения и передавать
агенту их описание после включения приложения человеком. Переиспользуются
существующие `.soty/app.json`, Source SDK и механизм размещения; эта инструкция
не вводит ещё один исполняемый manifest или протокол.

## MCP, skill и браузер

MCP/API предоставляют функции и проверяют доступ на сервере. Skill объясняет,
как выбрать функции для задачи. Браузер позволяет использовать готовый интерфейс,
когда подходящего инструмента нет. Подключённое приложение может предоставлять
любую из этих возможностей; новый MCP-сервер не является обязательным условием.

Сначала используйте discovery существующего сервиса. Не угадывайте ID проекта,
не выбирайте первый результат при неоднозначном имени и не используйте общий
технический ключ вместо личного доступа человека. Для нескольких приложений
агент использует их собственные подключения в пределах одного аккаунта Сот.

## Приложение для Сот и Telegram

Можно сохранять один web-интерфейс и предметный API, подключая адаптер нужной
оболочки. Вход и данные запуска проверяются адаптером оболочки: Telegram использует
свой механизм запуска, Соты — свой. Это схема интеграции, а не заявление о готовой
совместимости любого существующего проекта с обеими платформами.
Основа для Telegram: [официальная документация Mini Apps](https://core.telegram.org/bots/webapps).
Для инструментов: [официальная архитектура MCP](https://modelcontextprotocol.io/docs/learn/architecture).

## Проверенные точки повторного использования

| Проект | Что найдено | Статус этой проверки |
| --- | --- | --- |
| OTsov / Scope | `D:\otsov`; `/api/schema`, `/api/catalog`, `/api/runtimes`; приём обычного кода, проектное хранилище, CLI | Dev `scope-studio-dev` отвечает 200 на публичных discovery-маршрутах; связь создания с помощником Сот ещё нужна |
| Планировщик | `D:\планировщик\MCP.md`; `planner_help`, `planner_read`, `planner_apply` | Прочитан существующий контракт; подключение этого MCP к помощнику Сот не заявлено |
| Периметрика | `D:\peremetrika`; `/agent.md`, MCP HTTP/stdio и опубликованные инструкции | Найдены существующие инструменты; подключение к общему аккаунту/агенту ещё нужно |
| HIVE | Канонический репозиторий `D:\etap`; discovery, `/mcp`, OpenAPI | Общий вход и восстановление main/widget проверены; узкая проверка переименования остановлена после уточнения пользователя |
| Тавыш, Отзывы, Транзит, обратная связь | Существующие проекты и подготовленные интеграции | Требуется соединить готовые сервисы и проверить реальные сценарии; наличие исходников не выдаётся за подключение |

Скилл создания через OTsov находится в `integrations/agent-skills/otsov-app-builder/`.
Локальная копия установлена для Codex. В коде Сот помощник теперь получает
прикреплённые инструкции через существующий `source_catalog`: текст, тип,
версию и ссылку на соответствующий инструмент. Проверены выдача настоящего
OTsov skill своему аккаунту, отсутствие выдачи другому аккаунту, отзыв доступа
и ограничение размера. Этот код ещё не выпущен на действующий сервер;
подключение самого OTsov к общему входу и создание проекта проверяются отдельно.

## Как приложить инструкцию к готовому инструменту

В существующем серверном подключении `externalApplications` или в аргументе
`createSelectedNativeSourceApplication` добавьте `guidance`. Это поле уже
поддерживается Сотами; отдельный исполняемый manifest не нужен.

```js
guidance: [{
  kind: 'skill', language: 'ru',
  title: 'Создание приложения через OTsov',
  summary: 'Создать и сохранить отдельный проект в аккаунте человека.',
  content: verifiedSkillText,
}]
```

Текст читается сервером из установленной версии skill при запуске подключения.
После разрешения инструмента человеку каталог передаёт агенту и инструкцию.
Она объясняет готовые операции, но не выдаёт права, не подключает произвольный
код и не заменяет разрешение пользователя. Текущий MCP приложения и его схема
сохраняются. Для большого руководства используйте существующие
`apps_guidance_list` / `apps_guidance_get`; краткий skill до 16 КиБ попадает
в каталог помощника непосредственно.
