# Записки и глубина продукта — решения N1–N8, 28.09.2026

## Что было в проекте

Отдельной сущности личной записки не было. `src/main.ts` хранит тексты сот в `texts`, локально — `soty:text-snapshots:v1`: до 40 снимков по 200000 символов. `src/sync.ts`, `TunnelSync` использует `Y.Doc.getText('body')`; сервер хранит зашифрованные updates/snapshot общих комнат в `server/room-store.js`. Человек мог пользоваться этим как записками, но владельцем текста является модель доступа комнаты, а не новый аккаунт World.

Решение: старый editor/room/Yjs не меняется, в новых записках есть явный переход к прежним сотам. Автоматический импорт потенциально общего текста в личный серверный документ не выполняется. Новая сущность — личная аккаунтная записка, доступная с действующих подключённых устройств.

## N1. Сначала зафиксировать мысль

[Исследование local-first, Ink & Switch](https://www.inkandswitch.com/essay/local-first/) связывает отзывчивость и владение данными с доступностью локальной копии. Наш вывод для текущей архитектуры: сразу открывать поле ввода; не заставлять выбирать тип, папку и сервер до первого слова. Главная команда — «Новая записка», чеклист появляется одним нажатием. Сервер остаётся источником подтверждённой версии; продукт не объявляется полноценным local-first/CRDT-редактором.

Реализовано: новый редактор без обязательного заголовка, autosave после ввода, локальный account-scoped draft перед сетевой mutation. Проверка: offline draft test, quick-create из оболочки в браузере.

## N2. «Сохранено» — проверяемый факт

[IndexedDB transaction complete](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/complete_event) означает завершение транзакции; успешный отдельный request ещё недостаточен. [Yjs offline editing](https://docs.yjs.dev/getting-started/allowing-offline-editing) разделяет локальную persistence и сетевого провайдера. Из этого следует два честных состояния: «На устройстве» после локальной транзакции и «Сохранено» после серверного ACK. Browser storage остаётся best effort и может быть очищен по [документации quota/eviction MDN](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

Реализовано: ни сеть без ACK, ни local quota error не превращаются в «Сохранено». `flush` разрешает обновление оболочки при durable draft и отклоняется при локальной ошибке. Экспорт текста остаётся доступным. Проверка: quota failure и ввод во время сетевой задержки; реальный IDB — отдельная браузерная приёмка.

## N3. Конфликт сохраняет обе мысли

[RFC 9110, If-Match](https://httpwg.org/specs/rfc9110.html#field.if-match) описывает условную запись для предотвращения lost update. В подписанном RPC этот принцип выражен `expectedRevision`, а не HTTP-заголовком. Автоматический last-write-wins здесь может уничтожить абзац с другого устройства; внедрение CRDT поверх новой модели личного аккаунта потребовало бы отдельного протокола и проверки ключей.

Реализовано: атомарный CAS, сохранение локальной конфликтной ветки, «Сохранить копию» / «Открыть актуальную». При потере ACK повторяется тот же mutationId, включая reload. Временный receipt ограничен, но старая revision всё равно не позволяет затереть текст после его вытеснения. Проверка: два подписанных устройства, lost ACK после реального commit, повторное открытие базы, конфликт двух активных веток.

## N4. Личное определяется аккаунтом, а не маршрутом

[OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) рекомендует отказ по умолчанию и проверку доступа в каждом запросе. Наше применение: владелец — только verified actor в Connect. `expectedAccountId` — проверка устаревшего UI; ни noteId, ни присланный accountId не расширяют права. IndexedDB сам по себе origin-scoped, поэтому ключ дополнительно содержит project и account, ветки разных вкладок различаются.

Реализовано: get/list/search/put/purge одинаково ограничены владельцем, unknown fields отклоняются; отозванное устройство не проходит Connect. Новый текст сервер читается сервером; E2EE не обещается. Проверка: второй аккаунт, совпавшие noteId, подмена expected account, подпись изменённого тела, device revoke.

## N5. Каталог не растёт в объём загрузки

[SQLite FTS5](https://www.sqlite.org/fts5.html) предоставляет индексируемые слова, prefix queries и column filters. Мы индексируем токен владельца вместе с содержимым, затем дополнительно проверяем owner SQL; пользовательский ввод превращается в ограниченный набор quoted terms. Списку нужны метаданные и короткий preview, а полный body — только открытому документу.

Реализовано: лимит 40, keyset cursor, индекс owner/state/pin/time/id, один счётчик usage на аккаунт; нет чтения всех текстов ради списка или COUNT всего сервиса. Квоты сдерживают запись, tombstone и receipt. Проверка: 53 записки / 8 страниц без повторов, полный текст отсутствует в DTO списка, body/checklist search, cursor другого owner/query отклонён, query plan использует owner index.

## N6. Ошибку удаления можно исправить

Наша продуктовая гипотеза: архив и корзина решают разные задачи — убрать завершённое и отменить удаление. Автоматическая очистка незаметно превращала бы временное действие в окончательное. Поэтому архив/корзина обратимы, purge доступен только из корзины с явным подтверждением. Состояние, содержимое, FTS и quota меняются в одной транзакции по принципу [атомарного commit SQLite](https://sqlite.org/atomiccommit.html).

Реализовано: пустая корзина ничего не скрывает, восстановление возвращает текст/чеклист, purge оставляет только идентификатор и revision против позднего старого create. Проверка: transitions/counters, повтор purge, отсутствие текста в search после удаления, rollback всей записи при quota failure. Это не обещание физического уничтожения всех файлов/резервных копий.

## N7. Глубина открывается по намерению

[Nielsen Norman Group: Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/) предлагает отложить редкие настройки, оставив частые действия заметными, но предупреждает о цене лишних шагов. В нашей композиции ввод, поиск, новая записка, pin и checklist находятся на первом уровне; цвет, архив и экспорт — в меню. Старые соты не спрятаны внутрь настроек аккаунта. Десктоп имеет список+редактор, телефон — те же сущности на двух последовательных экранах.

Реализовано: короткие русские названия, подписи/aria-label у иконок, keyboard Ctrl/Cmd+S, видимая отдельная вкладка оболочки и её библиотечная точка входа. Проверка: полный путь create→edit→find→pin→archive→restore→trash в desktop/mobile browser; библиотечная маршрутизация принадлежит оболочке, не модулю.

## N8. Список работает обычным способом

[WAI-ARIA Checkbox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/) описывает чекбокс и переключение Space. Используем нативный input checkbox с label, а не нарисованную галочку: клавиатура и assistive technology получают обычную семантику. Enter создаёт следующий пункт; длинный текст не выходит за границы. Цвет — дополнительный ориентир, сохранение/ошибка различаются текстом; animation отключается при reduced motion.

Реализовано: native inputs, textarea/textContent вместо HTML, theme tokens для surfaces/ink/focus/danger, ограниченные размеры. Шестигранный акцент использует общие `--hex-aspect-ratio` / `--hex-polygon`, независимой формулы нет. Проверка: чеклист сохраняется при delayed request, typecheck, ручная клавиатурная и responsive приёмка.

## Текущие доказательства

`node --test modules/notes/test/*.test.mjs`: **18 PASS, 0 SKIP**. `npm run typecheck`: PASS. Unit browser-state использует memory draft adapter, реальный SQLite и контролируемый транспорт. Дополнительные regression: разрешённая конфликтная ветка после `discardBranch` + `dispose` не появляется повторно; восстановление backend до завершения старого timeout повторяет тот же outbox ровно один раз; одновременные сигналы дедуплицируются; повторная ошибка не создаёт цикл; disposal во время network/local write не оживляет отправку.

## Физическая остановка сервера: весь World

Дополнительная приёмка через документированный CUA Chrome, временная QA-вкладка, `http://localhost:5200`, production build `notes-C8IO7YHF.js` / `world-adapter-C2MApbao.js`. Новая PWA-версия сначала активирована штатной кнопкой «Обновить» с сохранением существующего черновика. Затем сервер 5200 действительно остановлен: независимый `/health` вернул connection refused. Browser offline-эмуляция не использовалась.

Открытая записка приняла текст и показала «На устройстве». Прямая перезагрузка `#notes/<id>` восстановила оболочку, локальную личность и полный IndexedDB-черновик; после неё добавлена ещё одна строка. После запуска того же сервера существующий PWA health-сигнал автоматически вызвал `NotesHandle.reconnect()`: без кнопок «Повторить»/«Проверить» появился ACK «Сохранено», восстановился профиль в шапке, полный текст и фокус в том же поле сохранились. «Мои соты» показали эту записку; повторное открытие из виджета загрузило весь серверный текст. **PASS**.

Первичная проверка обнаружила отсутствие реакции записок на возврат backend без browser `online`. Исправлено подключением к единому сигналу оболочки, без второго polling. Последующий независимый аудит нашёл гонку с поздним timeout уже отправленного запроса; её устраняет один объединённый `retryFlight`, доказанный тремя детерминированными regression выше. Этот узкий state-fix сделан после физических снимков; CSS не менялся.

Системная тема и яркость 50 подтверждены через UI, временный viewport сброшен. Дополнительно Library → Шахматы на 390×844: document client/scroll 390/390, клетка 30.75 px, шрифт 22.14 px; доска целиком видна. Артефакты открыты и проверены:

Осознанная граница v1: нет совместного редактирования, истории всех revision, вложений, Markdown HTML, сквозного шифрования новой сущности, полной offline-загрузки всего аккаунта или фоновой отправки из закрытого приложения. Старые возможности общих комнат остаются доступны. Конкурентная запись не теряет текст благодаря проверке revision и отдельному draft, а не обещанию несуществующей синхронизации.
