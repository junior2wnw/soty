# Соты: одно рабочее пространство

27 октября 2026. Целевая концепция по обсуждениям и выбранной модели «Рабочее пространство». Здесь описано желаемое устройство продукта; фактический выпуск и проверки фиксируются отдельно.

**Моё место, где люди, приложения и помощник доводят дела до результата.**

Человек открывает ссылку и сразу попадает в её цель. Из своего пространства он одним нажатием открывает приложение или разговор. Аккаунт, доступ, история и введённый текст сохраняются при переходах.

## Пять обычных сценариев

| Намерение человека | Простой путь |
|---|---|
| Открыть присланное | Ссылка → нужное приложение, сообщение или человек. Вход запрашивается при необходимости личных данных или закрытого доступа. |
| Продолжить своё | «Моё» → нужная карточка → работа с прежним состоянием. |
| Написать | Человек → разговор; приложение → соседнее обсуждение → обратно без перезагрузки приложения. |
| Подключить приложение | Выбрать подготовленный проект либо описать задачу → одно итоговое действие → работающая карточка. Первый допуск устройства остаётся отдельным понятным действием. |
| Поручить помощнику | Открыть помощника в текущем контексте → получить проверяемый результат → открыть созданное. Полномочия на действия понятны человеку. |

Оболочка имеет три основные области: **Моё, Сообщения, Поиск**. Помощник доступен в текущем контексте. Настройка находится рядом с тем, к чему относится: профиль, разговор, приложение или устройство. Технические параметры появляются только при необходимости.

## Как выглядит рабочее пространство

«Моё» объединяет нужных людей, приложения и совместную работу. Соты сохраняют узнаваемую форму и помогают ориентироваться; свободное расположение не должно мешать обычному открытию и поиску. На небольшом экране содержимое перестраивается в ясную последовательность. Общий интерфейс не закрывает действия приложения.

Приложение занимает рабочую область. Рядом доступны его обсуждение и помощник; они понимают текущий объект. Возврат сохраняет положение, выбор и незавершённый ввод. Пустое состояние предлагает один полезный следующий шаг, а ошибка сообщает конкретную причину.

## Что платформа делает один раз для всех приложений

| Общая способность | Результат |
|---|---|
| Вход и доступ | Подтверждённый профиль, участники ресурса, отзыв устройства и приложения. |
| Запуск и адрес | Один реестр, постоянная ссылка, подключённая среда, понятное состояние запуска. |
| Личные данные | Область приложения и подтверждённого человека; совместные данные открываются явно. |
| Устойчивое действие | Один идентификатор намерения, запись результата вместе с эффектом, проверка прежнего исхода после потери ответа. |
| Общение | Разговор, обсуждение, приглашение, прямые ссылки и уведомления. |
| Инструменты помощника | Разрешённые предметные операции и проверка результата через тот же контракт. |
| Помощь | Инструкция и приватное обращение о проблеме. Публичные отзывы пока могут оставаться отдельным приложением. |

Автор поддерживаемого приложения занимается предметной функцией. Платформа предоставляет общий вход и стандартные возможности. Существующему стороннему сайту нужен совместимый адаптер; передача страницы через транспорт сама по себе не разделяет его базу.

Устройство должно быть доступно, разрешено владельцем и поддерживать выбранный runtime. Перенос на другой хост сохраняет адрес только после проверенного переноса данных и прав. Произвольный код приложения не получает секреты коннектора и соседних приложений.

## Что следует объединить и убрать

- Одно намерение объединяет подготовку, запуск, регистрацию, проверку готовности и открытие. Человек не подтверждает одну работу несколько раз.
- Общий вход заменяет отдельные настройки авторизации каждого нового совместимого приложения.
- Один журнал действия и одна область данных заменяют независимые повторяющиеся механизмы восстановления.
- Названия конкретных приложений исчезают из общего ядра; адаптеры имеют явные границы и собственный жизненный цикл.
- Дополнительные режимы, настройки и панели вводятся только ради подтверждённого сценария. Отказ системы не изображается успешным запуском.

Защита данных, границы доступа, сохранение черновика и понятный отказ остаются частью простого пути. При неизвестном исходе нельзя выдавать новый запрос под видом повтора: сначала проверяется исходное намерение. Первая ещё не начатая отправка и восстановление уже начатой операции имеют разные права.

## От полезного продукта к большой платформе

Первый проверяемый цикл — небольшая команда: обсудить задачу, открыть приложение, получить результат с помощником и пригласить коллегу по ссылке. Затем сторонний автор подключает другое приложение через те же общие возможности. Проверка универсальности требует разных продуктов: документа, планировщика и совместной доски.

Рост даёт повторяемая польза: больше полезных приложений → больше решённых задач → больше людей и авторов. Доверие, переносимые данные, устойчивые интерфейсы и экономия времени должны накапливаться вместе с этим ростом. Плата за вычисления, хранение и командные возможности — гипотеза для проверки; оценка компании в триллионы из неё не следует.

Пять решающих проверок: новый человек понимает следующий шаг; вернувшийся продолжает без поиска; автор подключает второе отличающееся приложение без копирования входа; два человека и два устройства сохраняют свои данные; команда добровольно возвращается и приглашает других. Целевые показатели задаются до испытания, результаты измеряются на людях, а не выдумываются по автотестам.

## Ориентиры и пределы

Общий вход и запуск в знакомой оболочке полезно сравнивать с [Telegram Mini Apps](https://core.telegram.org/bots/webapps). Конкретные права и данные Сот проверяются собственными контрактами.

Клавиатурный фокус должен оставаться видимым: это отдельный критерий [WCAG 2.2](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html). Транзакционная работа локального хранилища опирается на [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB); наличие API не гарантирует сохранность при закрытии браузера и не заменяет серверное подтверждение.

Свод использует доступную историю Сот и текущие уточнения. Полное новое ручное чтение каждого сообщения всех аккаунтов не заявляется. Концепция, тестовый стенд, отправленные исходники и установленный выпуск — разные результаты.
