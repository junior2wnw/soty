## Проверенный сквозной сценарий

1. «Маша · тест» завела скрытый профиль. Другой пользователь видит только разрешённые данные.
2. В каталоге найдена «Мастерская», доступна её публичная витрина. До вступления чат закрыт.
3. Владелец «Алексей · тест» принял заявку. На ожидающем экране без навигации появились членство и чат.
4. Два пользователя отправили и прочитали сообщения. Владелец подключил отдельный локальный коннектор на 49429 и добавил «Покупки» с порта 5308.
5. Маша открыла приложение на другом origin и добавила «Фрукты». Это HTTP/WS-данные отдельного приложения.
6. Владелец удалил Машу через интерфейс. Открытый канал закрылся, форма приложения стала неактивна; повторный запуск показал «Доступ к приложению закрыт». Сделаны отдельные снимки этих состояний.
7. Повторная заявка и принятие вернули доступ. Удаление и блокировка являются разными действиями.
8. Переход в прежние комнаты и Back вернули новый интерфейс с тем же профилем. Данные прежних комнат и Connect не мигрировались в новую несовместимую учётную запись.
9. Поиск «Алексей» из аккаунта Маши вернул один профиль. Алексей выключил видимость в настройках; свежий поиск «Алексей · тест» вернул пустую выдачу и нулевой счётчик. После проверки видимость восстановлена для демонстрации.

Отдельный браузерный стенд на 5310 проверил весь путь создания с ИИ без прямого вызова внутренних API из браузера: новый аккаунт, локальное подтверждение коннектора, описание приложения, пустой необязательный путь, настоящее исполнение OpenCode, проверенное предложение «Покупки · тест ИИ», добавление в личные соты и запуск. Форма в iframe приняла пункт «Хлеб · проверка ИИ». Затем через интерфейс создана группа и ей предоставлен доступ; приложение появилось в её вкладке. Ошибок консоли нет. Стенд и вкладка после проверки закрыты. Снимки: `agent-ui-proposal.png`, `agent-ui-open.png`, `agent-ui-group.png`.

## Производительность и устойчивость

Исходная сборка загружала основной JS 545,70 КБ / gzip 178,32 КБ и CSS 49,46 КБ / gzip 10,62 КБ. Новый World и прежние инструменты разделены; QR и управление аккаунтом загружаются по действию. Начальные JS и CSS World: 187 276 байт, **54 454 байта gzip** против 188,94 КБ исходной загрузки — снижение примерно на **71%**. Это сумма пяти обязательных ресурсов, а не размер одного выбранного JS-файла. Все 13 URL итогового Service Worker существуют. Машиночитаемый результат: `output/world-validation-20260928/build-report.json`; воспроизведение после `npm run build`: `node output/world-validation-20260928/audit-build.mjs`.

Поле удерживает только близкие к viewport элементы, поиск отложен на короткую паузу ввода, чат ограничен страницами истории. Аватары подгружаются видимыми пакетами и не размножаются внутри каждого ответа каталога. Runtime ACK не пересылает историю заново; большие результаты читаются страницами. После закрытия экранов очищаются наблюдатели и таймеры. Service Worker проверяет наличие каждого precache-файла уже после окончательной обработки Vite.

Размер gzip и локальные геометрические измерения не являются полевыми Core Web Vitals: реальные INP/LCP для пользователей ещё не собирались.

Геометрия записана в `output/world-validation-20260928/interface-metrics.json`: ширина страницы совпала с viewport на 390/768/1440 px; на компьютере поле и панель составляют 1080/360 px, совместная работа — 260/850/330 px. Главная кнопка мобильной карточки целиком видна и заканчивается за 8 px до навигации. Tab/Shift+Tab остаются внутри модальной формы, Escape возвращает исходный фокус. Выключение плавных переходов через интерфейс даёт `0s`; переключение reduced motion в настройках ОС отдельно не проверялось.

## Условия рабочего запуска

- Для приложений нужны отдельный wildcard origin, DNS и HTTPS. Проверенный iframe-контракт использует Chromium и partitioned cookies. Сведения о настройке: [development-world.md](../development-world.md).
- На локальном сервере показа ключ inference не установлен. Интерфейс сообщает «ИИ пока недоступен», сервер не создаёт заведомо невыполнимое новое задание. Чтение и отмена ранее созданных заданий остаются доступными.
- Рабочую модель, её доступность и качество создаваемых проектов нужно проверить с настоящей серверной конфигурацией. Вызов платной внешней модели в ходе этой приёмки не выполнялся.
- Каналы и краткоживущие сессии привязаны к одному процессу шлюза; произвольная балансировка между несколькими независимыми узлами не поддерживается этой версией.
- Поддерживаются приложения с относительными HTTP/WS-адресами; произвольный внутренний URL и собственная cookie-авторизация upstream не входят в первый контракт.
- Проверки разрешённых каталогов не являются изоляцией операционной системы: OpenCode исполняет инструменты с правами пользователя коннектора. Новый код не обещает OS sandbox.
