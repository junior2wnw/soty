# Более короткие сценарии Сот

22 октября 2026. Подготовлено и проверено локально; на рабочем сайте этот срез ещё не опубликован.

## Решение

Сохранить принятый рисунок «Одного поля» и сократить промежуточные действия. Одно поле показывает приложения, людей и комнаты; «Личное / Мир» меняет область. Обычное нажатие выполняет главное действие, видимая кнопка действий, ПКМ и удержание оставляют дополнительные возможности. Поворот полотна и новая домашняя страница для общения не нужны для этих сценариев.

Одна кнопка QR открывает существующий typed hub. Один человек сохраняет профиль на нескольких устройствах, у каждого устройства остаются свои ключи и возможность отзыва. Приглашение друга и подключение своего устройства имеют разные назначения и подтверждения внутри общего входа. Бессрочный универсальный QR с доступом ко всему не требуется.

Постоянный голосовой помощник и существующий текстовый ввод сохраняют свои сценарии. Обложки, темы, права приложений и возможности локального агента остаются в существующих компонентах. Новые панели, сервисы и зависимости для этого изменения не добавлены.

## Сделанные изменения

| Сценарий | Результат |
|---|---|
| Подтверждённый контакт на личном поле | Нажатие или Enter сразу открывает существующий личный разговор: 2 действия → 1. |
| Комната действующего участника на личном поле | Сразу открывается существующий чат. |
| Поиск в Мире, непроверенный контакт, неактивное членство, расстановка | Сохраняется карточка и прежняя проверка доступа. |
| Дополнительные действия контакта | ПКМ/удержание/видимая кнопка открывают карточку; кнопка честно называется «Написать», когда DM доступен. |
| Свой QR уже показан | Повторная кнопка «Мой QR» скрыта; на узком экране инструменты занимают две колонки. |
| Нативная вставка поддерживаемой ссылки | Существующий локальный предпросмотр появляется без дополнительного submit; текст и фокус остаются в поле. |
| Ручной ввод либо инструмент без метаданных вставки | Сохраняются Enter и «Открыть ссылку». |
| Возврат к своему QR | Прежний предпросмотр закрывается. Фокус со скрываемой кнопки переносится на копирование ссылки. |

Вставка не подключает устройство и не принимает приглашение. Это делает прежний consumer только после «Продолжить». Смена аккаунта, поколение подтверждения, relationship/membership, сохранение заметок и серверные ACL сохраняют прежние границы.

## Более простой выпуск интерфейса

Обновлять UI отдельно от сервера и базы через уже существующий `SOTY_DIST_DIR` в [startup.js](../../server/startup.js). Предпочтительная целевая установка: родительский каталог версий подключён только на чтение как `/ui`, текущая версия выбирается внутри него. Внешний origin, API, авторизация и динамические защитные заголовки остаются у того же HTTP-приложения.

Это требует одного проверенного перехода профиля установки. Текущий контейнер ещё не имеет такого подключения; обычная смена каталога прямо сейчас не является внедрением этого решения.

До внедрения нужны:

1. Закреплять один неизменяемый каталог на весь HTTP-запрос: простой symlink между `stat` и `open` сам по себе не гарантирует целостность ответа.
2. Удерживать старые и новые hashed assets для открытых вкладок и отката; проверять конфликты одинаковых URL.
3. Проверить реальный read-only mount, PWA-обновление с несохранённой заметкой, старую вкладку и откат.
4. Отделить UI-выпуск от канала установщиков `/agent`; обновление их профиля проверяется отдельно.
5. Один раз применить новый профиль установки с сохранением единственного writer, данных и штатного восстановления.

Прямое редактирование слоя работающего контейнера отвергнуто: оно создаёт дрейф и теряется при его замене. Caddy умеет response interception, но здесь добавляет правила маршрутизации и перенос заголовков, которые существующему `SOTY_DIST_DIR` не нужны.

## Проверенные основания и ограничения

На работающем образе сравнен публичный Source `server/` и `modules/`: 770 файлов, 764 совпадения после нормализации CRLF, четыре рабочих различия и два изменённых теста. Различие `universal-mode.js` — комментарий, значение false одинаково. Три содержательных изменения относятся к scoped launch: fragment при запуске/renewal, query перед fragment и recovery текущего Source/domain. API renewal уже существует. Это не доказывает готовность всех live-сценариев и не устанавливает причину пустого HIVE.

В изолированном контейнере того же рабочего образа выполнен реальный Express static middleware: A → B → A без перезапуска процесса, доступны оба набора assets, тестовый API сохраняет 403. Продуктивная база, порт и конфигурация не использовались. Это проверка механизма, не весь профиль выпуска.

Для UI: 242 теста, без skip; TypeScript и production build прошли. В Chrome проверены прямой DM, ПКМ → карточка → Escape → фокус → Enter → DM; на viewport 390 CSS px проверены две колонки QR, ручной fallback, смена назначения и возврат фокуса. Браузерный инструмент генерирует input без inputType, isTrusted=false: он подтверждает fallback, но не нативный paste. Нативный insertFromPaste проверен в поддерживаемых тестах; физический телефон и настоящее событие вставки остаются отдельной проверкой.

Физические звонки/TURN, голосовой провайдер, реальные выдачи доступа, TRANSIT на телефоне и публикация нового UI этим срезом не принимаются.
