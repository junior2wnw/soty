# MCP планировщика

MCP управляет той же шкалой, которую видно в браузере. Это полноценный сервер с discovery инструментов, JSON schemas, structured results, ресурсами и prompt `plan-anything`. Используются стандартные **Streamable HTTP** и **stdio** транспорта официального TypeScript SDK. При создании, импорте, переносе и загрузке файла ответ означает сохранённое изменение в SQLite.

## Подключение

В планировщике откройте **… → Настройки и MCP → Агенты и MCP**, выберите пространство, права и срок доступа. Создайте ключ и нажмите **Скопировать подключение**. Секрет показывается один раз, хранится на сервере только в виде SHA-256 hash и отзывается сразу. Ключ видит выбранные пространства; фактические права аккаунта проверяются заново на каждом запросе. Изменение общих настроек аккаунта и создание новых пространств недоступны ключу одного пространства.

HTTP endpoint локального приложения: `http://127.0.0.1:4317/mcp`. Клиент передаёт `Authorization: Bearer <ключ>`. В конфигурации своего MCP клиента используйте скопированный `mcpServers.planner` либо поля URL/headers, которые принимает клиент. Внешнее размещение требует собственного HTTPS reverse proxy и ключа; готового OAuth login flow здесь нет.

Пример без секрета для локального owner режима — `mcp.example.json`. Этот режим работает только при loopback binding и соединении с того же компьютера. При запуске с `PLANNER_HOST=0.0.0.0` вход или ключ обязательны. Неверный Host/Origin и cross-site запросы отвергаются.

Для stdio используйте полученную в настройках команду Node.js или `mcp.cmd` из этой папки. Напрямую из папки проекта: `node --import tsx server/mcp-stdio.ts`. Переменные адаптера:

| Переменная                    | Назначение                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------------- |
| `PLANNER_URL`                 | Origin запущенного приложения, без path/query/секрета; по умолчанию localhost:4317     |
| `PLANNER_MCP_TOKEN`           | Ключ; задавайте через защищённые настройки клиента, не через аргумент командной строки |
| `PLANNER_PORT`                | Порт автоматически запускаемого локального сервера; по умолчанию 4317                  |
| `PLANNER_DB_PATH`             | Собственная база для локального автоматического запуска / изолированных проб           |
| `PLANNER_MCP_AUTOSTART=false` | Отключить автоматический запуск                                                        |

Если `PLANNER_URL` не задан и сервер отсутствует, stdio поднимает локальный сервер, обслуживает настоящую базу и закрывает только свой процесс при отключении клиента. Существующий сервер продолжает работать. В stdout stdio идут только сообщения MCP. Не запускайте MCP через обычный `npm run`, который добавляет служебный текст в stdout.

## Восемь инструментов

| Инструмент          | Возможности                                                                                                                                                       |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `planner_help`      | Краткая справка, примеры, словарь, точные координаты и доступные пространства                                                                                     |
| `planner_read`      | Обзор, объекты, типы/поля, ресурсы, правила, участники, настройки, сигналы, уведомления, комментарии, шаблоны, сценарии и occurrences; фильтр, версии, pagination |
| `planner_apply`     | Один атомарный пакет до 100 операций: CRUD объектов/пространств/типов/ресурсов/правил/связей, точные события, комментарии, персональные настройки                 |
| `planner_scenario`  | Просмотр последствий, создание варианта, отправка, утверждение/отклонение; календарный или точный сдвиг; baseline/факты сохраняются                               |
| `planner_template`  | Сохранение, применение, переименование и удаление шаблонов; календарная дата или точный anchorNs, неопределённость, поля/теги/связи и ресурсы                     |
| `planner_attention` | Подтвердить сигнал, отложить, разрешить после устранения причины, принять риск с причиной и правами                                                               |
| `planner_transfer`  | Export/import JSON v3, CSV v3, ICS с явными предупреждениями и новыми ID при импорте                                                                              |
| `planner_file`      | Настоящие вложения текстом или base64, чтение и удаление; 1 MB через MCP, большие файлы через сайт                                                                |

`planner://guide` и `planner://overview` дают справку и актуальный контекст. Типизированные schemas описывают `data`, select options, recurrence, ссылки на ресурсы и даты — агенту не нужно читать исходники.

## Минимальный пакет

После `planner_read` можно использовать ID пространства или его точное уникальное имя. Внутри пакета созданные элементы доступны как `$key`; ID, версии и `refs` вернутся в результате.

```json
{
  "requestId": "trip-2027-create-1",
  "operations": [
    {
      "op": "create",
      "collection": "objects",
      "workspace": "personal",
      "key": "trip",
      "data": { "title": "Поездка", "kind": "process", "start": "2027-06-01", "end": "2027-06-08" }
    },
    {
      "op": "create",
      "collection": "objects",
      "workspace": "personal",
      "key": "hotel",
      "data": { "title": "Отель", "parent": "$trip", "start": "2027-06-01", "end": "2027-06-08" }
    },
    {
      "op": "create",
      "collection": "objects",
      "workspace": "personal",
      "data": { "title": "Музей — идея", "parent": "$trip" }
    },
    { "op": "comment", "ref": "$hotel", "data": { "text": "Проверить условия отмены" } }
  ]
}
```

Дата `YYYY-MM-DD` означает местную дату в timezone объекта/пространства. Конец периода исключающий: 1–8 июня охватывает дни до начала 8 июня. Время требует ISO с `Z` или offset; для сохранения местных часов при DST задаётся IANA timezone. `until` и exceptions с точностью до дня сохраняют календарную семантику. Нет даты — `null`, никакой случайной «сегодня».

Для единой оси от наносекунды до миллиардов лет используйте `plan.precise`. Координаты — целые наносекунды от Unix epoch, только каноническими decimal strings: без exponent notation, дроби, leading zero и `-0`. Никогда не передавайте их JSON-числом: `Number` теряет точность. `precise.start/end` авторитетны; `start/end` остаются точными календарными зеркалами, если координата попадает в годы 0001–9999, и `null` за их пределами.

```json
{
  "requestId": "exact-event-1",
  "operations": [
    {
      "op": "create",
      "collection": "objects",
      "workspace": "personal",
      "data": {
        "title": "Импульс 1 нс",
        "plan": {
          "timezone": "UTC",
          "precision": "exact",
          "precise": {
            "scale": "unix-nanoseconds",
            "start": "1798761600000000000",
            "end": "1798761600000000001",
            "resolutionNs": "1"
          }
        }
      }
    }
  ]
}
```

`planner_read` возвращает эти строки без преобразования. Для occurrences далёкого или субмиллисекундного окна задайте `fromNs` и `toNs` строками; обычное календарное окно использует `from/to` и ограничено 366 днями. Точные календарные повторения отвергаются явно. В сценариях доступны `startNs/endNs/shiftNs`; `shiftMinutes` у точного объекта должен быть безопасным целым. В шаблоне точная опора называется `anchorNs`.

Чтение объекта сохраняет канонический `plan` и добавляет `localPlan` для удобной проверки в IANA timezone. Для конца целого дня в местную полночь возвращается `endInclusive` — последний включённый календарный день; иначе `end` содержит местный ISO с offset. Например, отпуск 5–10 июня показывается как `start: "2027-06-05", endInclusive: "2027-06-10"`, а его канонический конец — начало 11 июня. Это пояснение результата, а не новое поле для записи: `planner_apply` по-прежнему принимает исключающий `end`. `detail:true` возвращает в том же чтении исходный план, baseline и явный `actual:null`; для неизвестного времени `localPlan` отсутствует.

Required поля обязательны только у объектов выбранного типа. Заметка может пользоваться обычным `note`; ей не нужен бюджет бронирования. Для `select` задайте `options`. Новые ресурсы по умолчанию доступны в любые дни; рабочие дни задаются явно.

Редактирование/удаление объекта требует `expectedVersion`; изменение конфигурации — `expectedRevision`. Пакет с одной ошибкой полностью откатывается, включая настройки и receipt. Неоднозначность возвращает choices с ID. После `409` читайте актуальные данные и повторяйте оставшееся намерение с новым requestId. После потерянного ответа повторяйте прежний запрос дословно — duplicate не появится.

При переносе: `preview → create → submit → approve`. `approve` требует `confirm:true`; это параметр инструмента, а не отдельное окно подтверждения. Пространство выводится из уникального доступного ID объекта/сценария. Сценарий становится stale при изменении относящихся к плану данных; комментарий не делает его stale.

Шаблон создаёт новый план и повторения, сохраняет относительные местные часы через DST и оставляет недатированные идеи без даты. Назначения существующих ресурсов сохраняются, а применение возвращает конфликты новых бронирований. Исторические факты, прежние владельцы, файлы и правила не копируются автоматически. Попадание начальной даты в несуществующее местное время возвращает понятную ошибку.

JSON v3 сохраняет точные decimal strings без потерь. Полный CSV v3 дублирует их в `precise` и `entityData`; обычный CSV остаётся проекцией, а табличные вычисления над большими координатами могут потерять точность. ICS не умеет наносекундную или глубокую временную шкалу и явно отказывается экспортировать такие объекты. Эти форматы не являются резервной копией accounts, credentials, файловых bytes, истории или outbox. Для полного backup сохраняйте SQLite штатным способом из README.

## Проверка и расширение

`npm run test:mcp` проверяет реальные HTTP/stdio handshake, tools/resources/prompts, atomic rollback, scopes, отзыв ключа, версии, replays, шаблоны, DST, импорт и файлы. `scripts/mcp-client.mjs` — маленький SDK client; `scripts/mcp-call.mjs <tool> <input.json>` выполняет одну операцию. `npm run mcp:help` и `mcp:list` удобны в терминале.

Новая возможность добавляется transport-independent handler + schema, затем MCP integration test. Транспорт и ACL остаются общими. Опасных инструментов для произвольного SQL, shell или чтения путей сервера нет. Внешние календари/CRM и почтовые рассылки не подключаются автоматически: текущий продукт использует уже настроенные generic webhooks.

Модельные проверки и измерения — в `MCP-QA.md`. Это проверенная матрица сценариев, а не доказательство отсутствия ошибок во всех возможных состояниях.

Документация протокола: [MCP specification](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [официальный TypeScript SDK](https://ts.sdk.modelcontextprotocol.io/server).
