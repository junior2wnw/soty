# Создание приложения через OTsov

OTsov — существующий создатель приложений, в документации называется Scope.
Репозиторий на этом компьютере: `D:\otsov`. Используй готовый приём обычного кода,
проектное хранилище, историю и browser runtime. Соты предоставляют личное пространство,
общую идентичность и подключение приложений; остальные проекты предоставляют свои функции.

## Сначала определить соединение

- Прочитай опубликованные `/api/schema`, `/api/catalog`, `/api/runtimes` текущего OTsov.
  Локальный редактор обычно работает на `127.0.0.1:4317`; действующий Dev —
  `127.0.0.1:18570` на SSH `dev`, контейнер `scope-studio-dev`.
  Loopback сервера не является адресом браузера человека.
  На другом развёртывании бери адрес и руководство из подключённого приложения;
  приведённые пути и порты описывают только эту рабочую среду.
- Используй действующее соединение нужного человека и разрешённого проекта.
  Owner key и capability — разные уровни доступа. Не раздавай общий owner key пользователям
  и не подменяй их отдельные аккаунты одним техническим аккаунтом.
- Если MCP уже подключён, используй его discovery. Если доступен API, достаточно API
  и этой инструкции. Браузер подходит для работы через существующий интерфейс.

## Создать новое приложение

1. Подготовь обычные HTML/CSS/JS/TS, React или Vue файлы по задаче человека.
   Обязательный платформенный manifest и функция `render()` модели не нужны.
2. Передай код существующему composer «Код агента» → «Новый проект» либо проверенному
   API создания текущего развёртывания. Получи настоящий ID и квитанцию созданного проекта.
   Подробности: `D:\otsov\docs\ordinary-code-v7.md`.
3. Открой поддерживаемый runtime и проверь поведение результата, включая мобильный размер.
   Сохранённые backend/Python/Node исходники со статусом `needs-runner` ещё не исполняются.
4. Подключай готовое приложение к Сотам существующим процессом размещения
   (`soty-app-deploy`, если доступен). Сохрани размещение на выбранном владельцем сервере,
   его данные, URL и возможность использовать те же исходники с другой оболочкой.
   Временный browser preview OTsov не выдавай за опубликованный сайт.

Для последующих правок именно создаваемого проекта есть готовый CLI
`D:\otsov\scripts\code-response-cli.mjs`: `capture` до генерации → `prepare` →
`apply` подготовленного результата. Этот CLI работает с уже существующим project ID;
не используй его вместо создания нового проекта. При потерянном ответе сохрани прежние
идентификаторы и проверь квитанцию; конфликт требует свежего чтения и отдельного решения.

## Сделать приложение понятным агентам

Предоставь URL приложения, назначение, имеющиеся MCP/API и краткую инструкцию работы.
Переиспользуй собственные инструменты Планировщика, Периметрики, HIVE и других приложений
для их предметных задач. Skill объясняет выбор и порядок действий; доступ предоставляет
действующее соединение конкретного пользователя, а не текст skill.

При подключении предусмотрены общий вход Сот, частная обратная связь проекта,
отдельно публичные отзывы и необязательный виджет. Проверяй фактическое подключение каждого
модуля. Отсутствующий адаптер обозначай как незавершённое подключение, а не как работающую
возможность. Исходники уже открытых сторонних приложений не переписывай ради подключения.
