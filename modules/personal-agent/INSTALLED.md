# Подключение помощника

`server/index.js` подключает существующий личный runtime, приватные записки и очередь локального коннектора. По умолчанию помощник выключен. Этот пакет не активирует модель и не выполняет платные запросы.

Для установленного подключения нужны `SOTY_PERSONAL_AGENT_ENABLED=1` и абсолютный `SOTY_PERSONAL_AGENT_CONFIG_FILE`. Файл JSON — `soty.personal-agent-installed.v1`, до64KiB; на POSIX только владелец может читать/писать файл. Секреты не публикуются в статусе. Резервные копии такого файла должны быть зашифрованы.

Файл содержит `gateway` с `origin` (точный HTTPS origin), `billingTenant`, `inferenceBearer` и `managementSession`; `accountIds` — явно допущенные аккаунты Root. Модель остаётся фиксированной GLM. Инференс идёт через существующий accounted POST; квитанция читается через прежний management GET `/api/requests/:id`. Management cookie и inference key — разные права. Наличие файла не доказывает, что эти права действуют: gateway проверяет их при каждом запросе, Root проверяет настоящий signed Connect actor.

Необязательный `localTargets` содержит для каждого аккаунта один `{accountId,hostDeviceId,connectorId,cwd}`. Папка абсолютная и фиксированная; модель может передать только текст одной задачи. Действующая Apps ownership проверяется перед предложением инструмента и в очереди записи; отмена/отзыв до эффекта не создают задачу. Используется прежний `apps.assistant.send`, его sandbox, durable request/receipt и история. Ответ `queued` означает принятие в очередь, не выполнение. После фактического принятия остановка turn не отменяет уже начатую работу устройства; её управление остаётся в существующем режиме «На компьютере».

Подтверждённый разговор сохраняется одной помеченной запиской владельца. Пара «пользователь +ответ» имеет один Notes CAS/receipt; первый append сам ничего не записывает. После перезапуска текущий владелец может продолжить тот же context. Другой аккаунт, смена scope, архивирование/удаление/повреждение записки и конфликт revision не дают использовать старый диалог как новый. Записка — данные пользователя, не credential, Source grant или anti-rollback floor. Обычные backup/restore свойства Notes сохраняются; новая БД и миграция не нужны.

В записке максимум256 сообщений и96KiB JSON; текущий runtime использует последние8 сообщений. Старые сообщения не вытесняются автоматически: при заполнении нужен новый разговор, прежняя записка сохраняется. Действующие общие Notes квоты также остаются. Неизвестный исход не записывается как подтверждённый ответ и не запускает автоматическую повторную отправку. Commerce и локальная очередь сохраняют свои исходные idempotency правила; история не заменяет их ledger.

Source-read инструменты по-прежнему требуют установленный `sourceReferences` +private `sourceCredentialFor` и текущий Root/Source grant; catalog, JSON, publisher или память не выдают таких прав. Этот JSON loader не создаёт Source credentials. Шифрованные Connect roots/комнаты не становятся агентной памятью.

Проверки: Node24.19, `node --test server/test/personal-agent-http.test.mjs server/test/personal-agent-configuration.test.mjs`; отдельно explicit commerce/runtime integration test использует проверенные donor paths. CLI тесты запускают только собственные loopback процессы с синтетическими данными и завершают их через существующий IPC shutdown.

Настоящие production credentials не проверены/не активированы. `wholeReady=false`: браузерный operational gate, полный голос и остальные Source подключения — отдельные фактические проверки, не результат этих fixtures. Native SDK/runtime upstream остаётся неизменным.
