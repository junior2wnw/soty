# Подключение локального жизненного цикла звонка

Состояние 07.10.2026: **verified-component**, production integration pending. Runtime и три тестовых набора перенесены побайтно из independently reviewed v3. 62/62 проверки повторены после переноса; отдельные исходные peer-контрпримеры и дополнительные проверки прошли. Свидетельства: `D:/соты/output/soty-implementation-20261007/research/voice-call-lifecycle-source/root-installed-proof.json` и `peer-v3/receipt.json`. Исторические v1/v2 HOLD сохранены. Статус ожидания peer в замороженном README относится к моменту его создания; актуальный статус здесь.

Это библиотека управления **локальными** ресурсами. Импортировать её следует в один владеющий звонком host, переживающий переходы между приложениями. Обычная навигация не вызывает dispose. Смена аккаунта/устройства, revoke и logout проходят через её identity/termination boundary. Во фронтенд текущего выпуска импорт не добавлен; серверных call routes, SFU, TURN или voice-provider здесь нет.

1. Trusted Connect adapter подтверждает canonical account/device и текущую membership/role/audience revision; выдаёт актуальное admission для join и отдельное admission для публикации микрофона. Обычный JSON, descriptor, boolean или client-supplied ID этого не заменяет.
2. Trusted transport реализует receive-only join, подготовку публикации, реальный commit и tombstone/dispose, не сохраняет и не передаёт звук отдельным неконтролируемым путём. Проверки leases/revoke/expiry выполняются в самом adapter на фактическом IO. Нативный microphone adapter возвращает только собственный реальный аудиопоток после явного действия пользователя.
3. UI показывает компактные отдельные controls: подключиться/слушать, микрофон, завершить. Join оставляет микрофон выключенным. Agent invitation, recording и transcript имеют отдельные будущие admission/consent/lifecycle; этот компонент отвечает `feature_not_integrated`.
4. Provider operations обязаны иметь собственные deadlines и фактическую отмену/очистку. Предел16 относится к ownership groups одного экземпляра: отмена не освобождает slot до реального settlement и очистки; failed/unknown cleanup удерживается в quarantine. Это не глобальная quota всех вкладок/устройств/серверных workers. Host/controller должны обеспечить свои общие limits.
5. Stop evidence различает возврат stop(), наблюдаемое readyState=ended и ошибки. Сеть, удалённый участник, аппаратный LED, уже буферизованное аудио, E2EE или удаление записи этой квитанцией не подтверждаются. Поздний результат разрешения микрофона очищается, когда действительно получен.

Gate перед UI/live activation: actual signed admission, human1:1/group SFU/TURN, removed membership+старый JWT/rejoin, две настоящие сессии, delayed/denied permission, mute/end/revoke/account/device switch, background/sleep, karaoke/media focus, ignored cancellation/transport faults, bounded provider cost и наблюдаемое termination. Ни одна из этих integrations не объявляется выполненной unit-тестами.

Тесты компонента: `node --test modules/personal-agent/call/lifecycle.test.mjs modules/personal-agent/call/capacity.test.mjs modules/personal-agent/call/reentrancy.test.mjs`. Донорская бизнес-логика, prompts, keys и пользовательские записи не переносились. Микрофон, сеть и paid model calls в этих проверках не использовались.
