# Параллельные ответы Source

Cookie остаются приватными в коннекторе и принадлежат одному точному Root
reference и его неизменному контексту. Старый GET не может затереть cookie,
полученную параллельным `session-continue`, либо отменить её явное удаление.
После проверки текущего Root и binding ответ объединяется с текущим head,
а не со снимком cookie до сетевого ожидания.

`forget(reference)` удаляет этот приватный head. Незавершённый ответ проверяет
идентичность head и не восстанавливает его даже после нового запроса с тем же
reference. Дополнительного неограниченного списка tombstone нет: действует
существующий предел continuation и удаление истёкших head.

Контекст pin исключает только операционный `expiresAt`; account/device,
Human client generation, Source/profile/resource/target/reference остаются
точными. Для срока хранения используются только уже проверенные Root deadlines.
Это не продлевает cookie Source: её собственный expiry проверяется независимо
при каждом запросе. Проверки Root и binding до/после await, Source OIDC/ACL и
SQL fences сохранены; этот head не является доказательством входа или доступа.

Регрессии выполняют реальные loopback HTTP и MAC, удерживая старый ответ до
новой cookie/удаления/revoke/смены контекста. Это тест транспорта cookie,
не имитация Native login или разрешений проекта. Коннектор 1.4.8 содержит
тот же проверенный пакет в генерируемых `soty-connector` и compatibility asset.
