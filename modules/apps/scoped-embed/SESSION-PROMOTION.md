# Продолжение без преждевременной замены cookie

Диагностика на неизменных Root B02 и HIVE 4ab воспроизвела гонку: скрытая вкладка обновления получала новую основную cookie приложения раньше подтверждения Source. Действующий редактор уже отправлял новую cookie Root, но новый контекст ещё не имел cookie Source. Присутствие и чтение проекта получали `selected_authentication_required`, после чего HIVE приостанавливал редактирование.

При `apps.scoped.renew` выдача билета теперь создаёт временную серверную сессию. `POST /_soty/session` возвращает прежний `sessionCheck`, но не меняет основную cookie. Проверочный заголовок `x-soty-boot-check` выбирает эту сессию только на `GET /_soty/session` и точном `POST /api/embed/session-continue`. Его нельзя передать на чтение проекта, изменение данных, вход Source или повторную выдачу билета. Это короткий маршрутизатор к уже проверенному билету; заголовок не даёт прав и не подтверждает готовность.

Сервер принимает готовность только из проверенного ответа установленного коннектора на фиксированный маршрут Source. После `continued` с настоящим `ready:true` он повторно проверяет актуальность Root, контекста, временной сессии и семейства cookie. Только затем меняет голову семейства и отправляет основную cookie в ответе продолжения. Клиентский JSON и сообщение скрытой вкладки не участвуют в выдаче прав.

Семейство хранится в RAM и связано с исходной серверной сессией браузера. Временная сессия захватывает точную cookie браузера, голову и ревизию семейства. Поздний конкурентный ответ не может заменить победившую голову. Другой браузер, приложение, источник, текущий профиль либо закрытая вкладка не получают временную сессию. Проверки текущих прав и привязок продолжают работать отдельно от этого сравнения.

Срок проверочного маркера остаётся 30 секунд. Не больше 256 временных маркеров; общий прежний предел 4096 сессий сохраняется. Истёкшая неподтверждённая сессия удаляется; конкурирующая устаревшая сессия удаляется при отказе. Закрытие контекста убирает его временные маркеры. Отказ чужого браузера сам по себе не удаляет законный маркер. Перезапуск Root очищает RAM; возобновление затем требует обычного свежего запуска и подтверждения Source.

`ready:false`, ошибка, неизвестный ответ, отзыв прав или истёкший маркер сохраняют прежнюю основную cookie. Повтор после неизвестного результата использует тот же временный контекст и намерение Source, пока они действуют. Потеря ответа браузеру после переключения допускает возврат той же подтверждённой cookie. Это не обещание распределённой атомарности: Source мог уже записать свой результат до потери ответа. Текущее Source ACL и его собственная квитанция остаются обязательными.

Первый обычный запуск, Basic300, профиль Source, протокол ACK, MCP, SDK, схема данных и срок Native/RP-сессии не меняются. Basic300 не получает продление от временного маркера. Cookie Source не копируются между ссылками Root.

Проверка:

```powershell
$env:SOTY_PLANNER_GATEWAY_SOURCE_ROOT='C:/Users/Junio/.codex/worktrees/planner-source-rp'
& 'C:/Users/Junio/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe' --test modules/apps/test/scoped-session-promotion.test.mjs modules/apps/test/scoped-renewal-source.test.mjs modules/apps/test/runtime-pages.test.mjs
```

Пакет использует реальные signed Connect, HTTP, установленный коннектор, maintained RP и временную БД Source. Проверка истечения маркера ждёт настоящую 31 секунду; часы не подменяются. Это транспортный тест на отдельном Source Planner. Чистый естественный Chrome-проход HIVE на новой точной версии Root, включая голос 120 секунд, остаётся обязательным. Диагностика 394 его не заменяет. Причины исторического Human400, первоначального CSS retry и прежнего PNG-сбоя пока не закрыты.
