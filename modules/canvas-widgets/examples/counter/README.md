# Стеклянный счётчик — обычное самостоятельное приложение

Пример использует общий CSS модуль библиотеки и настоящее SQLite-состояние.
Полотно открывает обычный `/`; новый widget route, descriptor или Root rebuild
не требуется. Изменение подтверждается квитанцией и переживает перезапуск;
повтор одной неподтверждённой команды использует тот же requestId.

Зависимости передаются явно: stylesheet и widget-context нашей Glass UI, browser module/bundle
существующего Source SDK, origin родительских Сот и путь собственной базы.
Стиль библиотеки можно получить из `glassUi.styles` в ответе
`/.well-known/soty-app-platform`; приложение отдаёт его со своего origin вместе
со своим небольшим CSS. Состав SDK указан в `sourceSdk` того же discovery.

Запуск из корня репозитория для локального авторского проекта:

```powershell
node modules/canvas-widgets/examples/counter/app.mjs `
  --port 53124 `
  --database-path C:/my-counter/state.sqlite `
  --glass-css vendor/optical-glass/src/ui-kit.css `
  --source-sdk modules/source-app/browser/app-work.mjs `
  --widget-context vendor/optical-glass/src/widget-context.js `
  --parent-origin http://127.0.0.1:5194
```

Затем подключите приложение через обычный коннектор/порт Сот, выберите доступ
и разместите виджет. Это общий счётчик приложения; личную изоляцию пользователей
предоставляет Native workspace пример `../reading-list`, а допустимость запуска
обычного приложения проверяет существующее размещение Сот. Пример слушает только
loopback и не меняет права аккаунта.

Компактное окно показывает название и значение. Нажатие по карточке раскрывает
тот же iframe для работы; кнопка использует настоящий HTTP Source. На каждый
маленький iframe не создаётся отдельный WebGL-контекст: CSS material статический,
оптическое стекло полотна остаётся у Root. Native кнопки и события сохраняются.
Общий UI-контекст скрывает команду в пассивном обзоре и показывает её в рабочем
режиме, сохраняя тот же DOM. Старый host/отдельное окно остаётся интерактивным.
Этот контекст не даёт доступ к данным и не передаёт команд приложения.

В обзоре цифра занимает место, оставшееся после названия: её размер учитывает
высоту строки и число разрядов. При коротком окне уменьшается и название.
Рабочий режим растёт по содержимому; в коротком окне прокручивается сам документ,
поэтому команда остаётся доступной. Содержимое и полосы прокрутки не скрываются.

При первой ошибке чтения обзор показывает причину. В рабочем режиме та же
кнопка предлагает повтор подключения: она выполняет только GET, сохраняет
окно и после успеха снова становится «Прибавить». Неподтверждённая запись
повторяется с прежним requestId; повтор чтения её не подменяет.

`POST /api/increment` принимает только `Content-Type: application/json`
(необязательный charset допустим). Простой браузерный POST с другим типом
отклоняется415 до изменения состояния; CORS preflight не разрешается. Неверный
JSON или схема при правильном типе по-прежнему дают400.

Проверки: `node --test modules/canvas-widgets/examples/counter/test.mjs modules/canvas-widgets/examples/counter/ui-state.test.mjs`.
Визуальный контроль дополнительно должен проверить paint/clipping, 44×44 в
рабочем фокусе, реальное действие, обновление и сохранность после reload.
