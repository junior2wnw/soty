# Обновления без потери аккаунтов

В 0.1.1 добавлен отдельный `recoverRelease`: принимающее приложение может завершить локальное восстановление **до** обращения к сети. Для Сот используется host controller из `deploy/connect`, отдельный от обновляемого каталога. Он собирает полное приложение, связывает дерево модуля с неизменяемым Docker image ID, резервирует данные в зашифрованном виде и переключает единственного писателя. Канал Сот: `https://xn--n1afe0b.online/releases/connect/stable.json`; доверенный публичный ключ устанавливается отдельно, а не заимствуется из скачанного артефакта. Другой проект использует собственные проверки и активацию.

## Два независимых процесса

**Код модуля** находится в копируемом каталоге. **Данные** — в постоянной SQLite вне каталога модуля и в неизменяемом по имени браузерном хранилище. Номер релиза никогда не включается в account ID, project ID, имя базы или ключ записи.

Обновление серверной/браузерной логики не удаляет данные, не создаёт новый аккаунт вместо нечитаемого и не запускает «ремонт» через очистку хранилища. Ошибки диска и неподдерживаемые форматы приводят к остановке конкретной операции с сохранением старых данных.

## Что реализовано в updater

1. Канал загружает один ограниченный по размеру JSON-пакет по HTTPS. Перенаправления отключены.
2. Подпись Ed25519 проверяется закреплёнными ключами из локального файла доверия. Поддерживается порог нескольких различных подписей; сборщик создаёт одну подпись.
3. Подпись связывает имя пакета, версию, канал, монотонный номер релиза, срок действия, долю rollout, совместимость, размеры и SHA-256 всех файлов.
4. Истёкший релиз, понижение номера/версии, неизвестный ключ, несовпадение хеша, другой major и несовместимое поколение хранилища отвергаются. Для 0.x автоматически не меняется minor.
5. Поэтапная выдача определяется идентификатором развёртывания, не идентификаторами пользователей. Можно начать с одного тестового проекта.
6. Новая версия распаковывается в соседний staging-каталог. Проверяются пути, файловые типы, symlink и коллизии. Пользовательская база не копируется в staging.
7. Запускаются тесты подписанного кандидата и независимая проверка проекта из **местной конфигурации**, без shell и команд из метаданных релиза.
8. Замена выполняется переименованием каталогов с журналом. Прежний каталог остаётся рядом. Ошибка проверки возвращает прежний код; база не откатывается.
9. Повторная проверка уже установленного точно такого же релиза возвращает `current`. Подмена содержимого при прежнем номере не принимается.

Это небольшой собственный формат подписанного релиза, **не полная реализация TUF**. Автоматическая смена root-ключей, независимые timestamp/snapshot roles и защита от компрометации всей цепочки публикации здесь не заявляются. [Спецификация TUF](https://theupdateframework.github.io/specification/) использована как первичный ориентир для угроз rollback/freeze/mix-and-match.

## Включение в проекте

Скопируйте `examples/update-config.example.json` в корень проекта и укажите реальный HTTPS-источник, отдельный `stateDir`, файл доверенных публичных ключей и местную команду проверки. Пути разрешаются относительно конфигурации. `source` в примере намеренно не является действующим каналом.

```powershell
node modules/connect/update/cli.mjs sync connect-update.json
node modules/connect/update/cli.mjs watch connect-update.json
```

`sync` выполняет одну проверку; `watch` проверяет канал раз в шесть часов по умолчанию. В рабочих условиях watcher запускается вашим CI или менеджером процессов. В этой задаче постоянная служба и канал публикации не включались.

В Сотах предоставлена команда независимой проверки `node scripts/validate-connect-update.mjs`: типы, неизменность существующих Identity-контрактов, сборка в отдельный каталог. Она не заменяет работающий `dist`.

Для полностью автоматического выпуска задаётся местная `activate: ["executable", "arg1", ...]`. Она должна собрать/опубликовать целиком версию приложения, перезапустить сервер, проверить здоровье и возвращать ненулевой код при отказе. После неудачи updater возвращает старый модуль и вызывает ту же активацию для старого кода. Если повторная активация не удалась, нужен оператор. Без `activate` результат честно содержит `restartRequired: true`; модуль обновлён на диске, работающий процесс не объявляется обновлённым.

Не запускайте несколько updater с разными `stateDir` для одного каталога. Расположение stateDir и файла доверия — часть конфигурации развёртывания. При конкурентном запуске работает lock; после аварийного завершения он самовольно не захватывается. Проверьте, что записанный процесс завершён, снимите оставшийся lock и повторите запуск: журнал восстановит прежний каталог до следующей попытки. Проверки PID и ручное действие нужны лишь для аварии updater, не для обычных пользователей сайта.

## Выпуск новой версии

Сборщик принимает путь к **внешнему** приватному ключу, имя key ID, sequence, будущую дату истечения и output. Приватный ключ не должен находиться в копируемом модуле или репозитории.

```json
{
  "directory": "modules/connect",
  "signingKeyFile": "../private-release-keys/connect-ed25519.pem",
  "keyId": "connect-release-2026",
  "sequence": 2,
  "expiresAt": "2026-10-25T00:00:00Z",
  "channel": "stable",
  "rollout": 10,
  "output": "connect-release-2.json"
}
```

```powershell
node modules/connect/update/cli.mjs pack release-config.json
```

Срок здесь — пример, его нельзя копировать бесконечно. Повышайте sequence для каждого нового подписанного содержания. Дата истечения ограничивает принятие релиза, а не работу уже установленного сайта или срок жизни аккаунта. Публичный файл доверия: `{ "threshold": 1, "keys": { "connect-release-2026": "-----BEGIN PUBLIC KEY-----..." } }`.

## Совместимость и откат

У модуля четыре независимых номера: версия кода; версия HTTP-протокола; версия внутренней SQLite-схемы; минимальное поколение reader. В выпуске 0.1 внутренние миграции добавляют поля/таблицы, а reader epoch остаётся 1. Предыдущий совместимый reader проверяет объявленное происхождение схемы и необходимые таблицы и может работать с additive-изменением без downgrade базы.

Браузерная физическая IndexedDB-версия остаётся 1; запись имеет отдельный формат и `minReaderEpoch`. Необязательные расширения располагаются в `extensions` и сохраняются старым reader без интерпретации. Изменение обязательных полей, ключей шифрования или модели авторизации требует нового формата, переходного чтения и отдельного плана. Нельзя просто поднять номер и начать заново.

Для обязательного изменения следующая процедура: новая версия сначала читает старое и новое; затем записывает совместимое представление; миграция выполняется возобновляемыми частями с проверкой; старый reader выводится из обращения только после окна совместимости. В этом выпуске не реализован произвольный движок таких будущих преобразований: несовместимые обновления автоматически отклоняются.

Откат кода никогда не восстанавливает старую базу: иначе оживут отозванные устройства, использованные recovery-коды и старые права. Восстановление сервера из резервной копии — отдельная аварийная процедура со сверкой более свежих отзывов, не действие updater.

## Поведение страницы

Soty service worker загружает новую версию в ожидание, не прерывая ввод. При готовом обновлении появляется действие «Сохранить работу и обновить». Локальная контрольная копия должна завершить запись до reload. Черновик, сканирование и выполняемые действия задерживают перезапуск. Другие открытые вкладки не перезагружаются принудительно. Закрытие всех страниц позволяет стандартному lifecycle service worker активировать ожидающее обновление.

Каждая сборка получает worker с отпечатком фактического кода и CSS, поэтому изменение модуля обнаруживается без ручной смены номера кеша. Новые ресурсы загружаются до активации; предыдущий кеш сохраняется для старых вкладок. Открытая страница проверяет выпуск при возвращении пользователя и раз в час, если она видима; ошибки связи оставляют текущую версию работоспособной.

При изменении модуля выпуск должен пересобрать и опубликовать приложение целиком. Копирование одной папки на работающий сервер не заменяет уже загруженный JavaScript в чужих браузерах.
