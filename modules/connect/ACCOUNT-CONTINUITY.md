# Как люди сохраняют свои аккаунты

## Постоянные сущности

Account ID выдаётся случайно один раз и хранится в базе. Он не зависит от ника, телефона, версии приложения и ключа единственного устройства. Устройства добавляются отдельными строками, каждое со своими ключами подписи и обмена. Переименование меняет только название. Контакт относится к аккаунту, а не к одному телефону.

Установка браузера остаётся ограничением веба: очистка сайта, другой браузер или удаление профиля могут убрать единственный локальный ключ. Ни обновление интерфейса, ни «привязка к устройству» не позволяют гарантированно узнать физический телефон после такой потери.

## Основные меры и фактическое поведение

| Ситуация | Поведение |
|---|---|
| Обычный новый релиз | Account ID, имя базы и ключи остаются прежними |
| Две вкладки открыли сайт впервые | IndexedDB атомарно выбирает одну установку; проигравшая вкладка читает победившую |
| Ошибка чтения или повреждение ключа | Новая пустая идентичность не создаётся; прежние данные не удаляются |
| Прерванный bootstrap | Ключи и ключ данных сохранены до серверного создания; повтор возвращает прежний аккаунт |
| Переход на другой телефон | Новый телефон получает свой ключ и тот же account ID после явного подтверждения |
| На новом телефоне уже есть профиль | Он остаётся локально, есть переключение; комнаты Сот добавляются отдельно после подтверждения |
| Ответ о подключении/восстановлении потерялся | Получатель повторяет операцию тем же ключом; сервер возвращает прежнюю выдачу без второго аккаунта |
| Попытка использовать QR другим устройством | Получатель закреплён ключом и назначением; чужой ключ не завершает выдачу |
| Чужой аккаунт первым подтвердил QR нового устройства | Получатель видит имя и источник до входа; сверяет код, а завершение привязано к выбранному account ID |
| Потерян телефон | Другое устройство или проверенный recovery-файл открывает аккаунт; потерянное устройство можно отключить |
| Новый recovery-файл ещё не проверен | Старый проверенный способ продолжает действовать |
| Recovery-файл использован | Вход на новое устройство завершается; секрет не может выдать доступ третьему получателю; нужен новый запасной файл |
| Устройство отозвано | Tombstone остаётся; bootstrap тем же ключом не возвращает доступ |
| Удаление последнего устройства | Без проверенного восстановления сервер отказывает |
| Одновременное сохранение копии двумя устройствами | Проверка revision останавливает устаревшую запись |
| Другая вкладка переключила профиль | Поздний ответ не отображается как данные нового профиля; операция остаётся привязана исходному аккаунту |
| Новая обязательная схема | Старый reader останавливается, сохраняя данные; несовместимый релиз не применяется автоматически |

## Восстановление входа и данных

Сохранение recovery-файла и сохранение комнат — разные действия, это отражено в разделе «Сохранность». Восстановление входа вернёт контакты и доступ к аккаунту. Тексты и комнаты вернутся из последней успешно сохранённой зашифрованной копии. Несохранённые изменения и бинарные вложения не обещаются восстановимыми.

Внутренний ключ данных шифруется для получателя через ECDH P-256, HKDF и AES-GCM. Запрос, проект, получатель и аккаунт входят в криптографический контекст. При штатном подключении не передаётся приватный ключ установки. Содержимое резервной копии шифруется с привязкой к account ID и revision. Сервер хранит ciphertext; recovery-секрет хранится на сервере только как verifier.

Recovery-файл содержит 256 случайных бит, а не придуманную человеком короткую фразу. Он позволяет восстановить ключ данных, поэтому защищать нужно сам файл. Подтверждение проверяет реально выбранный файл и возможность открыть им текущий ключ; успешное нажатие Download само по себе не считается сохранённым способом.

## Переход существующих Сот

Старые `soty-online/kv/device`, room IDs, секреты комнат и текстовые записи сохраняются. Они не заменяются новыми account ID. Connect получает отдельную базу `soty-connect-v1`; привязка общих Identity-subject по нику, email или device ID не выполняется.

При добавлении нового устройства ключ старых Сот не клонируется. У нового браузера собственная локальная идентичность Сот. Сохранённые обычные комнаты можно добавить в него через зашифрованную копию. Существующие комнаты с тем же ID сохраняются без перезаписи; перед импортом записывается местная контрольная копия. Автоматического объединения конфликтующего текста нет.

Локальные старые комнаты Сот относятся к установке браузера и остаются видны при переключении Connect-профиля. Это не изолированные рабочие пространства разных людей. Для общего или чужого компьютера нужны отдельные браузерные профили; ограниченный гостевой доступ входит в следующий этап. Если текст в копии превышает текущий импортный предел Сот, импорт целиком останавливается с объяснением, без молчаливого обрезания.

Старые экспорт и импорт оставлены для совместимости с уже сохранёнными пользователями файлами. Они относятся к прежнему формату; основным новым способом служат Connect-подключение и проверенный recovery-файл. Старый файл, содержащий копию приватного ключа, нельзя называть отдельным отзывным устройством.

Скрытый жест сброса заменён открытием управления профилем. Ссылка с параметром старого reset больше не удаляет данные без явного подтверждения. Обычный сбой и обновление никогда не должны направлять пользователя на reset.

## Эксплуатация

Серверную SQLite необходимо регулярно резервировать согласованным SQLite backup API, а не копированием одного файла работающей WAL-базы. Нужны шифрование архивов, отдельное хранение ключа резервирования, копия вне сервера и периодическая проверка восстановления. [Node SQLite: backup API](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html#sqlitebackupsource-db-path-options).

Удаление рабочего тома или потеря всех его копий не исправляются модулем входа. Перенос на новый домен или изменение `projectId`, endpoint и имени IndexedDB — миграция, а не косметическое переименование. Перед ней нужен явный перенос с контролем старой и новой стороны; обычное обновление сохраняет эти параметры.

## Что должно пройти перед каждым релизом

- Старый профиль и реальные старые форматы читаются новой версией без изменения идентификаторов.
- Два параллельных клиента, повтор после обрыва и перезапуск сервера дают тот же результат.
- Отозванные устройства и использованные recovery-секреты остаются отозванными после обновления и отката кода.
- Чтение старым совместимым reader сохраняет неизвестные необязательные расширения.
- Новая версия не меняет границы профилей, шифрования и прав без отдельного миграционного решения.
- Браузерные тесты выполняются с настоящими IndexedDB/CryptoKey, а не только mock storage.

Совместимость защищает от обычных программных обновлений. Она не заменяет серверное резервирование, проверенный способ восстановления у пользователя и независимый security review перед массовым выпуском.
