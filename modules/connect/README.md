# Connect 0.1 — профиль, контакты и устройства

25 сентября 2026. Реализованный переносимый модуль и интеграция с Сотами. Для первого потребителя подготовлена отдельная серверная обвязка подписанных релизов; описание и квитанция развёртывания находятся в репозитории Сот, `deploy/connect`.

Модуль работает без React, Vite, исходников Сот и сторонних runtime-зависимостей. В браузере нужны WebCrypto и IndexedDB, на сервере — Node.js 24.13.1+ с `node:sqlite`. Для другого серверного языка можно реализовать тот же HTTP-контракт, но готовый сервер в этом выпуске — Node.js.

## Что работает

- Автоматическое создание локального профиля с устойчивым случайным account ID. Имя меняется независимо от идентичности.
- Постоянная сменяемая QR-визитка, входящий запрос, взаимное добавление в контакты, отмена, отказ, удаление, блокировка и разблокировка.
- Приглашение знакомого в обычную комнату Сот с отдельным согласием. Знакомство не открывает прежние комнаты.
- Добавление собственного устройства с отдельными неэкспортируемыми ключами. Старый профиль этого браузера сохраняется и доступен для переключения.
- Список устройств и серверный отзыв их доступа к профилю.
- Шифрованная копия данных продукта с проверкой версии: старое устройство не может затереть новую копию.
- Случайный файл восстановления, проверка сохранённого файла до активации, замена старого способа только после проверки. Восстановление одноразовое; повтор того же завершённого запроса тем же устройством безопасен.
- Подписанные релизы, проверка совместимости, автоматическая проверка канала, поэтапная выдача обновлений, обязательные тесты и откат кода при неудаче.

## Подключение к другому проекту

Скопируйте **весь каталог `modules/connect`**, оставив пользовательскую базу за его пределами. Сервер откажется создавать базу внутри заменяемого модуля, включая совпадения Windows-путей в другом регистре. Сначала запустите независимые тесты:

```powershell
node --test modules/connect/test/*.test.mjs
```

На сервере до обработчика страниц подключите модуль:

```js
import { createConnectService } from './modules/connect/server/index.mjs';
import { createConnectHandler } from './modules/connect/server/http.mjs';

const service = createConnectService({
  databasePath: '/persistent-data/connect/accounts.sqlite',
  projectId: 'my-project',
  allowedOrigins: ['https://my-project.example']
});
app.use(createConnectHandler(service)); // Express, Connect или адаптер Node HTTP
```

В браузере:

```js
import { createConnectClient } from './modules/connect/browser/index.mjs';
import { openConnectPanel } from './modules/connect/ui/index.mjs';
// Подключите modules/connect/ui/style.css обычным способом вашего проекта.

const client = createConnectClient({
  projectId: 'my-project', endpoint: '/api/connect/rpc'
});
await client.bootstrap('Мой профиль');
openConnectPanel({ client, productName: 'Мой проект' });
```

При использовании готового UI можно передать:

| Адаптер | Назначение |
|---|---|
| `qr(url)` | Возвращает data URL изображения QR; если не передан, остаётся рабочая ссылка |
| `snapshot()` | Возвращает данные проекта для шифрования; исключите ненужные права и машинные секреты |
| `restore(payload)` | Проверяет формат и явно добавляет/восстанавливает данные согласно правилам продукта |
| `onRename(label)` | Согласует имя профиля с уже существующим отображением имени внутри продукта |
| `invitation()` | Возвращает `{url,label}` для текущей комнаты; текущий серверный профиль принимает только URL своего origin с единственным параметром `j` |

Последний адаптер специфичен для профиля комнат этого выпуска. Другим проектам нужен собственный зарегистрированный тип ресурса/приглашения; произвольные внешние ссылки не разрешены. Вход, контакты и устройства работают без этого адаптера.

Самостоятельный пример без исходников Сот:

```powershell
node modules/connect/examples/server.mjs
```

Откройте `http://127.0.0.1:8099`. Данные примера находятся в `connect-example-data`, вне модуля. При копировании в другой репозиторий этот каталог не нужен. Пример слушает только loopback.

## Структура

| Каталог | Ответственность |
|---|---|
| `browser` | Ключи, IndexedDB, доказательства запросов, шифрование, восстановление, уведомления вкладок |
| `server` | SQLite, аккаунты и устройства, контакты, одноразовые запросы, проверка прав |
| `ui` | Независимый доступный диалог и разбор ссылок; без глобального управления страницей |
| `update` | Сборка подписанного релиза, проверка и безопасная замена модуля |
| `test` | Реальная криптография, SQLite, миграции, сбои и отрицательные сценарии |
| `examples` | Независимый проект и пример конфигурации обновлений |

## Граница возможностей версии 0.1

Это идентичность **внутри одного проекта**. Один и тот же модуль можно использовать на всех сайтах, но аккаунты разных доменов не склеиваются автоматически. Общий OIDC-вход и межпродуктовые контакты остаются отдельной интеграцией с нейтральным Identity/Control Plane. Существующий канонический STABLE wire Сот не изменён.

Новое устройство в этом выпуске — **собственное доверенное устройство с полным доступом к профилю**. Временные TV, ограниченные права пульта, passkeys/FIDO и семейные роли не заявляются реализованными. Нельзя переименовать такое подключение в «гостевой телевизор» без отдельной модели grants.

В Сотах сохранены старые ключи и комнаты. Их прежняя авторизация основана на общем секрете комнаты: отзыв устройства Connect не отнимает уже известный ему старый секрет комнаты и не удаляет скачанные данные. Для индивидуального отзыва участия потребуется следующий этап миграции realtime-протокола. Копия Сот переносит обычные комнаты и тексты, но не бинарные вложения, подключённых агентов и разрешение управлять компьютером.

Пользовательский recovery-файл — секретный способ входа, а не безопасное публичное вложение: он содержит случайный секрет и зашифрованный ключ данных. Секрет находится в том же файле, поэтому кража файла позволяет восстановить аккаунт. Храните его в защищённом месте; он никогда не помещается в QR, URL, telemetry или логи.

## Перед рабочим выпуском

Нужны зарегистрированные HTTPS-origin, постоянный том базы, проверенное резервирование сервера, выбранный источник релизов и доверенные ключи подписи. Для нагрузки в нескольких дата-центрах нужен адаптер к подходящему транзакционному хранилищу; SQLite WAL подходит процессам, работающим с одним локальным томом, не произвольной сетевой файловой системе. HTTP-инфраструктура должна ограничивать размер/скорость запросов и не журналировать тело RPC.

Этот код прошёл автоматические проверки и локальные браузерные сценарии. Это не независимый криптографический аудит и не проверка всех браузеров/телевизоров.
