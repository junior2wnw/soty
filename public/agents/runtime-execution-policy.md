# Разрешения выполнения мини-приложения

Обычное размещение сохраняет ограниченный CSP. Для WASM, своих workers и
публичных ресурсов оператор может утвердить конкретное приложение и текущую
цель. Это не доступ к данным и не изменение видимости. Параметр запроса,
заголовок приложения и копирование чужого Source profile не дают разрешение.

## Конфигурация оператора

Root при запуске читает необязательный
`/run/connect-releases/app-execution-policy.json` в существующем read-only
каталоге. Другой абсолютный путь: `SOTY_APP_EXECUTION_POLICY_FILE`.
Отсутствие стандартного файла сохраняет прежние ограничения; невалидный
существующий файл и отсутствие явно заданного файла останавливают запуск.
Предел64KiB/128 записей, закрытая схема, без повторяющихся ключей.

Форма записи, **не готовое разрешение** для реального приложения:

```json
{
  "schema": "soty.app-execution-policy.v1",
  "admissions": [{
    "appId": "app-11111111111111111111111111111111",
    "policyEpoch": 2,
    "target": {
      "revision": 1,
      "digest": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
      "profile": "soty.relay-restricted.v1"
    },
    "capabilities": {
      "wasm": true,
      "workers": "self",
      "connectSrc": ["https://tiles.openfreemap.org"],
      "imgSrc": []
    }
  }]
}
```

Все части app/epoch/target revision/digest/profile должны совпасть с действующей
проверенной целью; digest связывает её с владельцем. В коде нет списка
конкретных приложений или поставщиков. `workers`: только `none`/`self`.
Каждый список — до8 разных канонических HTTPS-источников длиной до2048 ASCII
символов: origin без завершающего слеша либо явный префикс пути со слешем.
Локальные/IP/специальные домены, wildcard, credentials, query, fragment,
неоднозначная нормализация и разделители CSP запрещены. DNS/серверных загрузок
при проверке нет. CSP path/redirect семантика не заменяет серверный ACL.

## Ограничения и совместимость

`wasm` добавляет только `wasm-unsafe-eval`. JavaScript eval/Function, blob
script/worker, чужие источники, камера, микрофон и навигационные разрешения
этим модулем не включаются. Собственный enforced CSP сохраняется второй
политикой и может дополнительно запретить WASM или сеть.
[CSP3](https://w3c.github.io/webappsec-csp/#can-compile-wasm-bytes).

Обычный relay требует коннектор1.4.24 с `relayResponseCsp:true`. Настоящий CSP
upstream HTTP передаётся отдельно как `sourceCsp` v1: absent/present/invalid;
present допускает пустую политику. Report-Only не становится разрешением.
Прежний allowlist и его16KiB не меняются. Без возможности сохранения CSP
утверждённое приложение получает503 **до** upstream-запроса; невалидные
metadata получают502 до расширения политики. Прочие приложения продолжают
работать со старым коннектором.

Реестр — неизменяемый снимок при запуске. Замена файла сама по себе не меняет
живой процесс. Удаление требует штатного запуска с новым снимком либо
существующего retarget/policyEpoch процесса; старое разрешение не совпадёт
с новой целью. Смена заголовка не отменяет уже скомпилированный код:
существующие проверки доступа и отзыв iframe продолжают защищать данные.

Проверенный порядок выпуска: точные байты файла и текущий tuple → новый
совместимый коннектор → Root с новым снимком → публикация загрузок/инструкции
→ настоящая managed-аппка и повторное открытие. Файл включается в актуальную
проверенную резервную копию конфигурации. Старый Root31 игнорирует новый
файл: откат остаётся ограничительнее и сохраняет актуальные данные.
