# Общий стеклянный UI для приложения и виджета

Модуль `soty.optical-glass` обнаруживается через `/api/app-agent-directory/modules`.
Точные URL исходников находятся в `glassUi` ответа `/.well-known/soty-app-platform`.
Эти общедоступные файлы дают UI-компоненты; доступ к данным и операциям приложения
определяет его действующий Source-контракт.

Скачайте stylesheet `glassUi.styles` в свой проект и подключите на своём origin.
Так приложение работает с собственной CSP и сохраняет интерфейс после обновления
платформы. Для статического стеклянного материала достаточно CSS и явных ролей.
Опциональный `glassUi.entry` экспортирует `createGlassUI` и
`GLASS_UI_WORKING_THEME`; его относительные imports доступны в `glassUi.files`.
Это локальная расширенная версия нашей библиотеки, а не обещание содержимого npm.

## Компактный интерфейс на прежнем entry

Внешний размер и форму окна определяет полотно. Содержимое, данные, обработчики и
семантические роли создаёт само приложение. Используйте общую bounded-композицию:

```html
<main class="glass-ui glass-ui__widget"
      data-glass-material="working" data-glass-tone="light"
      data-glass-role="card" data-glass-safe-area="off" data-glass-render-mode="static">
  <section class="glass-ui__widget-content" aria-label="Состояние приложения">
    <!-- Крупное полезное состояние, затем собственный редактор/содержимое. -->
  </section>
  <footer class="glass-ui__widget-actions">
    <button data-glass-role="accent" type="button">Действие</button>
  </footer>
</main>
```

Задайте своему document/container определённую высоту. Основное состояние должно
помещаться в небольшом viewport; содержимое прокручивается, действия сохраняют
доступную область. Настоящие `<button>`, `<input>`, `<output>`, labels и события
остаются нативными. Для полей назначайте `data-glass-role="field"`, для обычного
действия — `control`, для главного — `accent`.

На отдалённом полотне Root показывает glance и одним нажатием раскрывает тот же
iframe в читаемый рабочий размер. CSS/ResizeObserver внутри iframe видят его
logical viewport и не определяют внешний zoom. Размеры и форма не являются
разрешением Source. Один адаптивный entry подходит и для `/embed`; новый route
или widget manifest для этого не требуется. При изменении размеров сохраняйте
DOM полей и незавершённый ввод. Маленькая высота, включая экранную клавиатуру,
не должна безусловно скрывать редактор или единственный способ сохранения.

Для явного режима загрузите `glassUi.widgetContext` рядом с собственным UI-кодом:

```js
import {bindGlassWidgetContext} from './widget-context.js';
const context = bindGlassWidgetContext(document.querySelector('main'), {
  parentOrigin: 'https://your-soty-host.example', // точный заранее настроенный origin
});
// При удалении данного UI: context.dispose().
```

В режиме `glance` библиотека скрывает `.glass-ui__widget-actions` и
`.glass-ui__widget-editor`; полезное состояние остаётся в `.glass-ui__widget-glance`.
В `interactive` редактор и действия доступны, в том числе при экранной клавиатуре.
Они сохраняют DOM, состояние и собственные обработчики. Старый host и отдельное
открытие приложения используют `interactive`. Контекст передаёт только режим,
проверяет точные origin и Window отправителя; он не передаёт данные, команды,
URL или разрешения Source. Поддержку подтверждает только это работающее окно.
Root скрывает повторную микрошапку лишь после такого подтверждения; название
остаётся в доступном имени объекта, поиске и панели раскрытого окна.

Проверьте два разных приложения в hex/rectangle на телефоне и компьютере:
видимое состояние → раскрытие → настоящее действие → компактный результат →
reload. Проверяйте отдельные отказы при отзыве доступа. Объекты полотна, Source
pin, launch/renewal и синхронизация используют существующие контракты Сот.
